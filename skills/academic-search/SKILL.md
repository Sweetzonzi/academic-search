# academic-search

通过 CLI 取回论文元数据并缓存，再根据用户的研究问题筛选、核查和组织文献。单篇查询直接选命令；领域入门或经典与前沿调研使用 §3 的探索流程，论文精读使用 §4 的 Markdown 阅读流程。

CLI 的检索结果均来自本地库，联网负责刷新语料。每篇以 `work_key` 标识，`doi` / `arxiv_id` 和 `sources[]` 提供出处；列表可能同时包含本次取回与既有缓存条目。

## 1. 调用入口

    skills/academic-search/scripts/run.cmd  <命令> [参数...]     # Windows
    skills/academic-search/scripts/run.sh   <命令> [参数...]     # POSIX

- 上述路径用于仓库内调用；安装后的副本用该 skill 目录下的 `scripts/`，不要假定当前目录就是仓库根。参数与示例按需读 [CLI 参考](references/cli-reference.md) 对应命令小节。
- **首次使用、环境变化或启动失败时先读 [初始化与排障](references/setup.md)**，按启动器诊断 → 本地库 → 所需来源联网分层验证。`--diagnose` 只检查本地启动前提；正常调用已验证的环境时直接执行任务。
- 仓库根绑定、Python 和凭据注入见初始化参考；`--root` 是全局选项，放在子命令前：`--root <仓库路径> search ...`。根目录同时决定配置和缓存位置，切换时说明实际使用的库。
- 显式写全 `--refresh auto|true|false`：通常用 `auto` 复用新鲜缓存，要求强制更新时用 `true`，仅查本地用 `false`。`search` 的 `auto` 按检索式新鲜度判断；`lookup` 的 `auto` 按标识是否已命中判断。对 DOI / arXiv ID，`true` 均先刷新再查本地。
- 不直接修改 `data/`；采集、去重与落库交给 CLI。CLI 不调用 LLM，文献筛选与解释由当前 agent 完成。

## 2. 按任务选择入口

| 用户想要 | 命令 |
|---|---|
| 一次性主题检索、某方向的最新进展 | `search --all-of ...` / `--any-of ...`；不需要画像 |
| 领域入门、经典与前沿 | 按 §3 拆分查询，再用 `search` 与 `lookup` 筛选核查 |
| 本地已有文献 | `search --refresh false`；不给检索式时列本地全部，**空检索式只配 `false`** |
| 确定的单篇 | `lookup --doi ...` / `--arxiv ...`；标题已知且库内检索时可用 `--title` |
| 指定会议或期刊 | `search --venue ICRA` 等；名字须能解析，详见 CLI 参考 §1 |
| 执行已保存的具名查询并生成报告 | `sync` / `sync --query 名`；画像处理见 §5，调度由宿主负责 |
| 下载原件 | `download --work <work_key> --source auto\|pdf\|all`；仅支持 arXiv，只取件、不转换 |
| 精读方法、公式、图表，解释某篇论文 | `read --work <work_key> --refresh auto`；按 §4 读取转换后的 Markdown 与图件 |
| 配置与维护 | `profile show\|check\|scaffold`、`verify`、`version`；按需读 CLI 参考对应小节 |

`lookup --title` 只做本地短语匹配，任何刷新档都不联网，也不做模糊排序。只有主题描述或标题不确定时，先 `search`，再用结果中的标识取单篇。

## 3. 领域探索：经典与前沿

**先形成问题框架。** 从用户描述提取应用场景、研究层级、任务、约束和排除范围。信息足以启动时，说明合理假设并开始检索；只有会改变研究范围的缺失信息才需要询问。例如无人机决策研究可关注任务归属、观测位置、通信与重规划，并据用户要求排除以姿态稳定和轨迹跟踪为主要贡献的工作。

**按研究分支组织查询。** 根据问题分开找通用理论与方法、应用桥接工作、近期进展，按任务规模选择需要的分支。基础方法不必含应用名；不要把“多智能体”直接收缩成 MARL，或把某个热门模型当作全部方法。`--any-of` 放同义词或候选短语，`--all-of` 表示必要条件；CLI 只提供这两组组合，复杂概念组合拆成多条查询。短词与缩写搭配领域词，避免跨领域同名命中。

| 检索目标 | 取数与筛选策略 |
|---|---|
| 经典与基础 | 优先用 OpenAlex 的 `--sort citations` 召回，再复核问题奠基、方法代表性或基准贡献。被引是全局计数，不是主题相关性；`--min-citations` / `--min-fwci` 按需要使用，不预设通用门槛，也不把低被引当成排除理由 |
| 近期代表工作 | 按用户时间范围给 `--since-years`，结合细分问题检索近期已发表工作；不把单次日期排序的头部视为整个时间窗口的代表 |
| 最新预印本 | 用 arXiv 补查，通常不设被引或 FWCI 下限；OpenAlex 补充正式载体与被引信息。根据领域覆盖选择互补来源，报告实际查询范围 |

arXiv 采集接口不提供被引次数或 FWCI，也不提供用于载体白名单判定的载体信息，因此给载体白名单或任一被引阈值会跳过该源采集。本地阈值按 work 聚合指标判断，无相应指标的论文不通过；通过 OpenAlex 获得指标的预印本仍可能返回。仅 `--sort citations` 保留 arXiv，其采集仍按日期取数，本地无被引数据的结果排后。`--min-citations` 单独使用仍按日期取数，要按被引召回需加 `--sort citations`。载体判据可能漏掉只有预印本记录的经典；细则见 CLI 参考 §1。

**每批结果后决定下一步。** 先检查摘要与主题相关性、时间分布、版本重复和文献类型，再针对缺口追加查询，避免一次铺开所有分支。噪声多时收窄必要概念或拆分子问题；结果少时先看 §6 的本地漏斗和失败信息，再判断是否缺同义词、来源覆盖或缓存语料。代码发布、数据集、学位论文和综述可作为不同用途的资料，不能仅因有 DOI 就当成已发表研究论文。

**把召回边界纳入判断。** 每次远端取数仅一页、最多 100 条；本地可用 `--offset` 配合 `--limit` 分批展示，两者都不增加远端取数。`counts.local.truncated=false` 只表示本地候选预算未耗尽，不证明远端完整。宽查询集中于最近几周时，用细分主题或其他来源补查，并检查近期代表工作是否缺失；不能声称已穷尽指定年份。CLI 未提供任意起止日期、排除词或远端续页选项，不编造参数。

**核查候选与结束检索。** 对准备推荐且摘要信息不足的条目用 `lookup` 读完整摘要，按 §7 处理日期、发表状态和证据；需要确认方法、公式或实验细节时进入 §4 的精读流程。当主要分支已有与任务相符的代表文献、关键缺口已补查或说明、追加查询主要带来重复或低相关条目时收束；明确的预算或来源限制也应作为停止依据并报告。不要为凑数量持续扩张列表。

## 4. 论文精读

**默认读取转换后的 Markdown。** `read` 负责取得 arXiv LaTeX 源码或 HTML、转换并缓存正文与图件；agent 使用返回的定位器阅读 Markdown。正常精读无需先运行 `download`，也无需自行打开下载的原始 PDF、HTML 或源码，或另起转换流程。`download` 用于用户明确要原件的任务。

### 4.1 获取 Markdown 与定位器

通过 `lookup` 或检索结果取得目标论文的 `work_key`，调用：

```text
scripts/run.cmd read --work <work_key> --refresh auto
```

只对需要精读的候选调用，**不要对着候选列表逐篇 `read`**。`read` 自动复用正文缓存或转换已有原件，必要时才取件。返回的是 JSON 定位器，正文不在信封里：

- `doc.work_path`：人和 agent 默认读取的 `works/<proj>/paper.md`，同目录有 `figures/`，可直接使用正文中的相对图片引用；仅在投影可用时返回。
- `doc.path`：`bytes/` 中的正文实体，与 `doc.work_path` 逐字节相同；投影不可用时才回退到它。文件名可能只有哈希、没有 `.md` 后缀，仍按 UTF-8 文本读取。
- `anchors`：章节标签与行号，用于定位阅读范围。
- `figures`：正文图片引用名到本地图件的映射。

先检查 `warnings` 和来源版本，再用自己的文件工具读取正文。使用本次返回的路径，目录名可能随元数据变化；长期标识论文用 `work_key`。正文和图件均只读，笔记另存。参数、缓存和失败行为按需查 [CLI 参考 §11](references/cli-reference.md#11-read)。

### 4.2 按问题分段阅读 Markdown

先读正文开头的元信息、摘要与章节标题，再结合 `anchors` 找到用户问题涉及的章节。围绕“研究问题与假设 → 方法与公式 → 实验设置与结果 → 局限”组织阅读，按需要补读符号定义、引用段落或附录；单个公式问题只读相关上下文，不必先通读整篇。

用文件工具的行号或范围读取能力，从锚点附近开始，结合后续章节边界分段读。长文不要整篇无差别灌入上下文。方法细节、实验参数和性能比较必须落实到实际读到的正文，不能把 `search` 的摘要片段或 `lookup` 的完整摘要当作已精读的证据。

### 4.3 按映射查看图件

在 Markdown 中遇到图片引用（如 `figures/fig-01.png`）时，从 `doc.work_path` 的父目录按相对路径找到图件，用图像工具打开。结合图注与正文解释坐标、曲线、实验条件和作者结论；图注不能替代对图像的查看。

回退到 `doc.path` 时，按正文引用名匹配 `figures[].ref`，打开对应的 `figures[].path`；不能从 `bytes/` 的父目录拼接相对图片路径。复杂表格可能以 HTML 保留合并单元格，读取时核对表头与数值对应关系。图件缺失或未渲染时说明限制，不声称已经看过图。

### 4.4 形成有依据的回答

标明论文身份、来源版本及相关章节、公式或图号，区分论文原文、对图件的观察与自己的推断。源码生成的锚点表示章节位置，不等于 PDF 页码；行号只对应本次返回的 `doc.sha256`，正文变化后重新取定位器。证据与发表状态的通用要求见 §7。

无编号段落的锚点会用所属章节与标题定位，不能把该定位文字当成论文节号；定位器用法见 [CLI 参考 §11](references/cli-reference.md#11-read)。

### 4.5 版本与转换缺损

`stale=true` 表示有版本落后证据，需要更新时用 `read --refresh true`；版本未知时不能声称最新。仅查本地用 `--refresh false`，它仍可转换本地原件或重建投影；缺正文与原件时按返回错误恢复。

缺图、未解析引用和 HTML 公式限制须按 `warnings` 转述。只有转换缺损影响所问结论、或用户明确要求核验原文时，才回查 `front_matter.source_url` 指向的来源；无法核实的内容明确保留，不凭经验补写。正常阅读始终从转换后的 Markdown 与图件开始。

## 5. 长期查询与画像

只有需要保存常用检索式或执行具名查询时才使用 `config/profile.toml`。一次性检索不因缺画像而中断，也不据此改写用户的研究方向配置。

需要画像且 `profile show` 返回 `no_profile` 时，从用户目标和已验证的查询起草方向名、`all_of` / `any_of`、可选载体与回看窗口；优先给可用草稿，缺少关键范围时再询问。按用户已授权的配置范围新建或修改文件，**改完必跑 `profile check`**，回显实际解析结果。CLI 不写配置；字段与模板见 CLI 参考 §9。

`sync` 与 `search` 按相同检索式共用新鲜度账，不因换命令自动重新取数。`sync` 的清单在 `data/runs/<run_id>/run.json`，人读同目录 `report.md` 或 `data/latest-report.md`；信封只返回各 `runs[]` 的状态与成本，细节见 CLI 参考 §4。

## 6. 结果诊断与失败处理

stdout 是 JSON 信封 `{ok, command, schema, data|error}`，日志走 stderr。优先看 `ok` 和载荷；退出码 `0` / `1` 对应有产出 / 无产出。参数解析或启动器失败可能没有信封，先修参数或环境，不能套用源失败重试。

- **本地未命中**：只说明现有语料未命中。用户需要外部文献且允许联网时，用 `search --refresh auto` 取数；已经联网仍空时，说明本次来源与检索式未找到匹配，不能推断“无人研究”，也不凭记忆补成已查证结果。
- **列表少于预期**：读 `data.counts.local`；`truncated` 表示候选预算耗尽，`venue_filtered_out` 表示文本命中但载体不符，`matched` 与 `returned` 区分匹配数和展示数。`data.items` 查的是本地库，条数不等于本次新增数。
- **部分源失败**：`counts.failures[]` 非空时仍可能 `ok=true`，使用成功结果并说明缺失来源；`search` / `sync` 的 `counts.complete` 表示本次规定的采集是否完成，细则见 CLI 参考 §8，不能把失败或跳过的来源报告成已完成检索。
- **`warnings`**：`search` / `lookup` 可返回 `data.warnings` 字符串列表。阅读并向用户转述影响覆盖范围或结果判断的提示，与 `counts`、`degraded` 中的同一事实合并说明；没有该字段不代表检索完整。字段用法见 CLI 参考 §8。
- **`degraded`**：读 `reason` 并结合 `network`、`cost.requests`；`sync` 看各 `runs[].refreshed`、状态与成本。新鲜度命中是正常复用，只需说明本次未刷新；额度不足可能整次跳过，也可能已经完成部分来源。不要统一说“只查本地”，也不要因该标记重复请求或绕过额度限制。
- **`ok=false`**：仅 `busy`、`source_error`、`network_error`、`rate_limited` 在原因允许恢复时最多重试一次；缺依赖、错误参数、写权限或网络策略拒绝先按[初始化参考 §5](references/setup.md#5-按失败阶段恢复)修原因，重复执行无用。错误码细节见 CLI 参考 §10。

## 7. 交付与证据

- **每篇有出处和推荐理由**：给标题、`published_at`（有日期差异时注明口径）、可点击的 DOI / arXiv 链接与来源名；两种外部标识都缺时保留 `work_key`。依据 `sources[]` 说明记录来源，不把已有 arXiv 成员误报成本次已执行 arXiv 检索。完整 `sources[]` 可留在结构化清单，不必把 JSON 原样堆进正文。
- **领域导读回答为什么读、怎么读**：按问题或方法解释经典的基础作用、前沿的研究问题、与用户场景的关系及阅读顺序。应用迁移与选题建议明确标为推断，不能把检索未命中当成创新性证明。
- **证据深度与断言一致**：`search --abstract` 是摘要片段，`lookup` 带完整摘要但可能为空；缺摘要不等于源失败。摘要可能来自预印本或 OpenAlex 倒排索引还原，逐字引用或翻译前核对原始页面。依据摘要概括时如实标注；性能比较、方法细节或创新性判断需要相应原文证据，不能暗示已精读或复现。
- **核对身份、日期与发表状态**：DOI 与题名不一致时先核查；`published_at`、arXiv 上传日和会议年份可能不同。涉及“最新”“首次提出”或录用状态时回到出版商、会议或 arXiv 页面确认。带 arXiv DOI 不等于已接收，会议投稿不等于录用。
- **版本与排除**：`dup_suspect=true` 时说明疑似重复，避免把同篇不同版本当成独立贡献或合计被引；`is_retracted=true` 的论文不推荐。来源之外的网页发现可作为补充线索，用可用标识经 CLI 核查，尚未入库的线索单独注明。
- **交代实际范围与限制**：说明检索日期、来源、时间范围和重要缺口；按需要汇报 `cost` 并保留 `basis` 的估算 / 实测含义。简短查询直接回答，只有用户需要留档或结果较多时才另存报告。

## 8. 环境要求与未接线

- **运行前提**：Python `>=3.11`、可写存储；OpenAlex 凭据由执行进程的 `OPENALEX_API_KEY` 提供，arXiv 不需要 key。设置、自检与失败恢复统一见[初始化参考](references/setup.md)；不输出凭据值。
- **能力边界**：`search`、`lookup`、`download`、`read`、`sync`、`profile`、`verify`、`version` 已接线；`digest`、`export` / `bundle`、`promote`、`graph` 尚未接线，不能声称完成摘要缓存或导出。`read` 只转换 arXiv LaTeX 源码与 HTML，不解析本地 PDF 或出版社页面；初版不接 Zotero。
- **转换依赖**：检索与原件下载无需 pandoc。转换链按 `ACADEMIC_SEARCH_PANDOC`（可执行文件）→ 仓库 `vendor/pandoc/pandoc.exe`（POSIX 为 `pandoc`）→ `PATH` 查找；可从 [pandoc 官方发布页](https://github.com/jgm/pandoc/releases/latest) 下载对应平台压缩包，解出可执行文件放入上述位置。HTML 另需 `lxml`；缺 pandoc 时仍可读取已有的完整正文缓存。
