## 1. 设计目标与约束

**目标**：实现[项目定位](01-需求说明.md#0-项目定位)——面向本课题组的 LLM 文献检索与阅读辅助技能；满足 R1–R11 与 N1–N4，且满足[验收标准](01-需求说明.md#5-验收标准)。

**关键约束（来自 [02](调研/README.md)）**：

| 约束 | 影响 |
|---|---|
| Zotero 9.0.4 本地 API 只读，库未同步无 API key | 写入通道当前不可用；升级 10.x 是前置条件 |
| Zotero schema 为固定字段集 EAV | 派生数据必须另存（→ ADR-0001） |
| OpenAlex 按次计费、无 key 每日 $0.10 | 必须申请 key；filter 优先、批量刷新、结果缓存 |
| arXiv 每 3 秒 1 请求、新文章午夜后可见 | 一天一次足够；必须缓存 |
| SQLite FTS5 默认分词器对中文失效，`trigram` 也只在 ≥3 字有效 | v1 绕开它：检索一律用英文，中文翻译不进索引（[ADR-0042](决策/ADR-0042.md)） |
| 运行时缺 `requests`/`PyYAML`/`pyzotero`，无 uv | 核心链路只用标准库 |
| 本地库仅 5 条目 | 定位为"锚"，而非管理主体 |

## 4. 系统设计

### 4.1 数据源层

**逐源字段映射、源能力矩阵、规范枚举、源文本规范化、work 级聚合与硬排除规则见 [IFACE-SOURCE](接口/数据源适配.md)**（[ADR-0052](决策/ADR-0052.md)）；本节只讲检索策略与闸门。

**检索策略（省额度的硬规则）**：
1. **计费按「有没有做全文检索」分档**：不含全文检索的 `filter` 是 `$0.0001`/次；任何全文检索——`filter=field.search:` 与 `search.` 参数**同价**——是 `$0.001`/次（[EX-2026-10-16-source-contract §1](实验/EX-2026-10-16-检索口径与来源校验.md)）。所以省额度的做法是**结构化条件一律走 `filter`、主题条件走 `search.title_and_abstract=`**（[ADR-0063](决策/ADR-0063.md)），而不是「避开 `search=`」；结果落盘；
2. 一律 `per_page=100` + `select=` 限定字段（仅顶层）；
3. 存在性判定只走结构化 `filter`（DOI/ID/`title.search`），自由文本噪声极大；
4. 深分页用 `cursor=*`，但要设页数上限，不拉全库；
5. 每轮读 `x-ratelimit-remaining-usd`，低于阈值降级为"只跑增量、停探索式 search"；
6. 引用数刷新走批量：`filter=ids.openalex:W1|W2|…`（OR ≤100）。

**发现式查询的构造**：领域画像（关键词/venue 白名单/作者/机构）→ 展开为若干**具名查询**（[ADR-0027](决策/ADR-0027.md)、[ADR-0040](决策/ADR-0040.md)）；画像由 **agent 写、CLI 只读校验**（[ADR-0039](决策/ADR-0039.md)）；年份窗口按增量策略（见 §4.7）。

**检索式的两个来源各有一个入口**：`search` 只接受 agent 当场给的检索式（`--all-of`／`--any-of`），不要求先写进画像，结果照样落候选池（`record` + `candidate` 都写，[ADR-0043](决策/ADR-0043.md) 决策 1、[ADR-0056](决策/ADR-0056.md)）；画像里的具名查询由 `sync` 执行并产出报告（[ADR-0049](决策/ADR-0049.md)）。两者共用去重与缓存（[ADR-0041](决策/ADR-0041.md)）。

**质量闸门**：`is_retracted`、`type`（paratext / editorial / erratum 列入硬排除）、`primary_location.source.type`、OA 状态与许可、`fwci` 与 `citation_normalized_percentile`、`counts_by_year` 异常检测（单年暴涨 → 灌水嫌疑）、venue 白名单（领域顶刊顶会 + DOAJ）、venue 黑名单（掠夺性/已知灌水刊）、语言、年份窗口、机构与通讯作者匹配。**输出为分级（A/B/C）+ 理由**，不做二元淘汰；理由随候选落库。**过滤发生在读取端**：黑名单与撤稿无条件排除；**venue 白名单与黑名单都按「作品载体的 source id 集合 ∩ 名单 ≠ ∅」判定**——两端同一判据，载体集合为空的记录既进不了白名单、也不会被黑名单命中（[ADR-0060](决策/ADR-0060.md)）；按质量下限（默认 `B`）过滤的机制保留，但 **A/B/C 分级与 `--min-grade` 不在初版**（[ADR-0051](决策/ADR-0051.md)）。

**摘要处理**：OpenAlex 倒排索引按位置还原为文本；arXiv 直接取 `summary`；缺失是正常分支（回退 Crossref/arXiv 或标记"无摘要"）；两者原样缓存。

**一致性校验**：按 DOI 命中后，用标题相似度 + 年份 + 首作者交叉校验；严重冲突 → 标 `metadata_conflict` 进入待确认，不静默采用。

### 4.2 身份与去重层

#### 4.2.1 五层结构（依据 ADR-0003 / ADR-0011）

| 层 | 键 | 回答什么问题 | 可变性 |
|---|---|---|---|
| **记录 `record`** | `(source, source_id)`；对外 id = `record_uid` | "这条来源记录抓过没有" | 只增不改（重新抓取只更新） |
| **记录标识 `record_ident`** | `(ns, value)` | "这个 DOI / arXiv ID / W ID 命中过哪条记录" | 可增删 |
| **分组 `work` + `work_member`** | `work_key`（= 首领记录的 `record_uid`） | "这几条记录是不是同一篇" | **可随时重新分组** |
| **派生 `derived_content`** | `content_hash` | "这段原文我算过了没有" | 可丢弃重算 |
| **字节层 `bytes/`** | `sha256(字节)` | "这些字节存过没有" | 可丢弃重抓 |

**没有任何随机铸造的 id**（ADR-0003）：

```
record_uid = base32(sha256(source ‖ 0x1f ‖ 归一化后的 source_id))[:20]   # 定长、路径安全、可复现
work_key   = 组内最早见到的那条记录的 record_uid                          # 不另铸 id
```

`record_uid` 里哈希只做**格式归一化**（把两个字段压成单列定长），不做去重——`(source, source_id)` 本身已经是唯一键。需要给人看的 handle（比如导出的文件名、对话里的指称）时，**按需从 `record_ident` 派生**（优先 openalex > doi > arxiv），不落库。

#### 4.2.2 写入路径（不需要跨源仲裁）

```
ingest(一条网络结果):
  1) upsert record (source, source_id)          # 幂等；同一来源重跑只更新
     record_uid = base32(sha256(source ‖ source_id))[:20]   # 确定性，不铸随机 id
  2) 写入该记录的全部标识 record_ident          # DOI / arXiv / W / PMID / CorpusId
  3) group(record):                              # 见 4.2.3
       · 命中已有 work → work_member 挂进去（work_key 不变）
       · 未命中 → 该记录自己当首领：work_key = record_uid，写 work + work_member
  4) 记录不再单独出现在任何面向用户的界面里
```
**注意第 3 步的方向**：新记录加入已有组**永远不会**改变 `work_key`（首领 = 最早见到的那条）；只有"一篇全新的论文"才会让新记录成为首领。这就是"不需要铸造 id"的原因。

**这两步不对外暴露命令**：调用方只发 `search` / `lookup` / `sync`，落库（含入候选池）与分组在其中完成（[ADR-0047](决策/ADR-0047.md)、[ADR-0056](决策/ADR-0056.md)），三个入口行为一致；初版的 `group()` **只自动执行 L0 与 L1**；L2 命中登记为待确认、不归组（[ADR-0048](决策/ADR-0048.md)）。

**去重判据优先级**（`group()` 内部，逐级降级）：

| 级别 | 依据 | 动作 |
|---|---|---|
| L0 | 记录标识与已有 `record_ident` **共享强标识**（DOI / arXiv ID / OpenAlex W / PMID） | 直接归入同一 work |
| L1 | 一方记录的 `locations[]` / `externalIds` **显式指向**另一方（arXiv↔正式版桥） | 归入同一 work，并**把桥对面的标识补进 `record_ident`** |
| L2 | 弱判据：`title_key` 命中 **且** 一作姓氏相同 **且** 年份落在窗口内 **且** 强标识不冲突 | **不归组**：登记为待确认（`dup_suspect`），并在结果里标注"可能同一篇"（[ADR-0048](决策/ADR-0048.md)） |
| L3 | 人工确认（**初版不提供入口**） | 归组或**拆组**；拆组是一等操作，不是修数据。入口须是"可读清单 + 选择"（[ADR-0047](决策/ADR-0047.md)） |

`work_member.role` 里 `primary` = 首领（`work_key` 的来源），`preprint` / `published` / `duplicate` 标其余记录的角色。**首领是按"最早见到"定的，与"哪条是正式版"无关**——展示时用正式版记录的元数据，但 `work_key` 仍来自最早那条。

**年份窗口必须不对称**：实测预印本 → 正式版可以差 3 年（arXiv 2009 → 期刊 2012），也可能出现 **-1**（arXiv 2024-01 → 会议 2023-11），所以用 `[-1, +10]` 而不是 ±1。

**桥的三条实测通道**（从**只有正式版 DOI** 出发反查预印本）：
1. **OpenAlex 单实体 GET** `/works/doi:<doi>` → 同一 Work 的 `locations[]` 里通常同时有 `publishedVersion`（期刊）与 `submittedVersion`（arXiv，`landing_page_url` 含 arXiv ID）。**单实体 GET 免费**，所以分组任务可以跑得很勤，不烧额度。
2. **Semantic Scholar** `/graph/v1/paper/DOI:<doi>` → `externalIds` 含 `ArXiv` / `MAG` / `CorpusId`（免费，共享池易 429）。
3. **arXiv 的 DataCite DOI** `10.48550/arXiv.<id>`（可**直接构造**，不需查询）→ 反查 OpenAlex。注意：Crossref **不认识**这个 DOI（实测 404），且有已知错配案例 → 命中后必须用标题/年份校验。

#### 4.2.3 弱判据的字段与阈值（实测标定）

| 判据 | 单独使用的假阳性 | 说明 |
|---|---|---|
| `title_key`（小写 + 去标点 + 去首冠词） | **16%**，最大一组 **7 篇不同论文** | 只能当**召回键**，不能当判据 |
| `title_key` + 年份 | 4% | **年份是判别力最强的单字段** |
| `title_key` + 一作姓氏 | 12% | 单独加几乎无用，但组合时需要 |
| `title_key` + 一作姓氏 + 年份 | 4% | 建议判据（另加"强标识不冲突"否决） |

⚠️ 两个必须处理的脏数据：① Crossref 标题里会嵌 **MathML / JATS 标记**（实测 `<mml:math>`、`<sup>®</sup>`）→ 归一化前先剥标记，只剥 LaTeX 不够；② 书章节/前言/索引的记录标题本身重复（实测 `Index` 撞 **3 本不同的书**）→ 按 `type` 过滤 + 黑名单。

#### 4.2.4 派生数据的共享规则（替代"指向最早记录"）

```
derived_content(content_hash PK, kind, lang, model_id, prompt_version, terms_version)   # 不装文本：文本落 bytes/（ADR-0045、ADR-0054）
content_hash = sha256(规范化后的源文本)          # 摘要原文 / 正文原文，二选一按 kind
```
- 原文**没变** → 哈希相同 → 自动命中，零成本复用；
- 原文**变了**（预印本 → 正式版是常态）→ 哈希不同 → 自动重算；
- **顺序无关**：谁先算出来都一样，不需要知道"谁是最早的记录"。

`content_hash` 与记录/作品解耦，所以同一段原文出现在多条记录、甚至多个 work 下也只算一次。

#### 4.2.5 重新分组（自动维护，可撤销）

触发条件：① 某条记录后来才拿到 arXiv ID / DOI；② OpenAlex 侧发生合并或拆分。**这两条都由分组任务自动处理**。③ 人工拆组**不在初版**：`work_key` 与 `works/` 目录都是哈希样标识，人工入口必须先做成"可读清单 + 选择"（[ADR-0047](决策/ADR-0047.md)）。

**合并两个组**（键永不改写，只做重定向）：

```
merge(A, B):                              # 保留哪个组当首领？
  keep = A 若 A 挂了 Zotero；否则较早 first_seen_at 的那个
  drop = 另一个
  UPDATE work_member SET work_key = keep WHERE work_key = drop
  UPDATE work      SET merged_into = keep WHERE work_key = drop   # ← 我们自己保留合并映射
  # drop 那一行不删：任何仍引用旧键的旧导出文件都能一跳解析回来
  # 不删任何 record，不覆盖任何原文
```

**拆组**（唯一可能产生"新键"的操作；**初版没有触发入口**，机制先保留）：拆出的记录集合里取**最早见到**的那条当首领；若那条恰好是原首领（即首领留在原组），则拆出部分临时回到"新论文"分支——此时它的 `record_uid` 本来就是一个可用且唯一的键，直接用即可，**仍然不需要铸造随机 id**。

**禁止硬删记录**：删除一律标 `record.status='tombstone'`（`record` 与 `work` 的行都保留）。这是 `work_key` 稳定性的唯一前提，必须写进实现约束。

#### 4.2.6 复用

`zotero-mcp/src/zotero_mcp/identifiers.py`（MIT，纯标准库，作者声明可外部 import）提供 `normalize_doi` / `doi_match_key` / `arxiv_identity` / `normalize_title_for_matching`。

**缺口**：其标题匹配只做精确折叠，**无编辑距离、无"作者 + 年份 + 副标题"模糊启发式**；其查重走 Zotero 客户端库（Zotero 未运行不可用）→ 离线模糊匹配层须自研（即本节 L2）。

### 4.3 存储层

#### 4.3.1 三分工：一个索引 + 一个字节仓库 + 一个投影

三者不是三个并列的库：**查询只有一个入口（sidecar SQLite），大块字节只有一份实体（`bytes/`，内容坐标），人读的路径是可重建的投影（`works/`，作品坐标）**。

```
   查询 ──►  sidecar SQLite（唯一索引：record / work / derived_content / candidate / artifact）
                     │
                     ├─► 摘要·翻译（短派生文本）：sidecar 只留缓存键与 sha256 指针
                     │
                     └─ sha256 指针 ─► bytes/<sha 前2位>/<sha256>（字节唯一实体：抽取纯文本、paper.md、译文、图件）
                                              │ 投影（硬链接，见 ADR-0034）
                                              └─► works/<proj>/paper.md + figures/ + captions.json
```

**两条取用路径**（回答"从 id 怎么走到派生内容"）：

| 取什么 | 路径 | 落点 |
|---|---|---|
| 摘要、翻译（短派生文本） | `record_uid` → `record` → 源文本 → `content_hash` → `derived_content`（缓存键）→ `sha256` → `bytes/` | 字节实体，与全文同一套规则（[ADR-0045](决策/ADR-0045.md)）；DB 只留缓存键与指针 |
| 全文类产物（字节） | `work_key` → `artifact` → `sha256` → `bytes/<sha 前2位>/<sha256>` | 字节实体：抽取纯文本、`paper.md`、图件（[ADR-0029](决策/ADR-0029.md)） |
| 全文类产物（人读） | `works/<proj>/paper.md` + `figures/` | 投影，可完整重建 |

第一行的键是 **`content_hash` 而不是 uid**：同一段原文出现在多条记录下只算一次（[ADR-0011](决策/ADR-0011.md)）。

**全文不进 SQLite**（[ADR-0029](决策/ADR-0029.md)）：sidecar 只存指针与元数据，因此 v1 的 FTS5 只覆盖英文原文（标题、摘要），不覆盖正文，也不覆盖中文翻译与中文摘要；正文检索走 `works/` 文件扫描（[ADR-0036](决策/ADR-0036.md)、[ADR-0042](决策/ADR-0042.md)）。

**什么进哪一层**：

| 判据 | 存储 | 装什么 | 类比 |
|---|---|---|---|
| 要 SQL 查询 / 联接 / 唯一索引 / 版本化的**指针与键** | sidecar（一个 `.db`） | 记录、标识、分组、源文本（标题与摘要原文）、**翻译与摘要的缓存键与指针**、引用边、候选池、运行账本 | 卡片柜与借阅台账 |
| 人要直接打开、要整体打包的**字节**（不分原始与派生） | `bytes/` + `works/` | 抽取纯文本、`paper.md`、译文与中文摘要、可选 `paper.html`、`source.tar.gz`、`figures/` | 字节的家 |
| 用户的正式资产 | Zotero（`D:\ZoteroLib`） | 条目、collection、tag、附件 PDF、笔记、标注、全文索引 | 书架与正式资产 |

**字节层的两级布局**（依据 [ADR-0011](决策/ADR-0011.md)、[ADR-0033](决策/ADR-0033.md)）：
- `bytes/<sha 前2位>/<sha256>` —— **唯一字节存储**，内容寻址，相同字节只存一份（预印本与正式版原文相同、或两个 work 引用了同一份源码时不会重复占空间）；
- `works/<proj>/` —— **给人看的投影**（`paper.md`、`figures/`），其中每个文件是 `bytes/` 里的**硬链接**（不占额外空间），**删掉可完整重建**（[ADR-0034](决策/ADR-0034.md)）；下一层目录名是 `<年>-<首作者>-<标题>-<work_key>`，**尾段才是身份**（[ADR-0068](决策/ADR-0068.md)）。
- **路径不落库**：库里只存 `sha256`，`bytes/` 与 `works/` 下的路径一律现场拼。`works/` 的名字可以被人抄走，但**可读段会随元数据变**、只有尾段 `work_key` 是身份，见 [IFACE-STORE §2](接口/存储与迁移.md) 与 [ADR-0068](决策/ADR-0068.md)。

产物来自哪条记录写进 `artifact(record_uid, …)` ——所以"这份 Markdown 是 arXiv 源码转的还是出版社 HTML 转的"永远可追溯。

#### 4.3.2 权威边界（依据 ADR-0008）

| 语料库 | 规模量级 | 权威 | 内容与访问方式 |
|---|---|---|---|
| **我的库**（人工策展） | 10²–10³ | **Zotero** | 条目、标签、collection、附件、笔记、标注、全文索引；**读** = 只读 sqlite 副本（`items`/`itemData`/`itemTags`/`fulltextItems`）+ `.zotero-ft-cache`；**写** = 官方 API（10+ 本地 / Web API） |
| **领域语料 + 候选池 + 图谱语料** | 10³–10⁵ | **sidecar** | 检索结果、评分与理由、引用边、翻译与摘要的缓存键与指针、运行账本；SQL + FTS5 |
| 作品身份 | — | **sidecar 自己持有**：`record_uid`（确定性派生）+ `work_key`（= 首领记录的 `record_uid`）+ `record_ident` 别名 | 第三方 ID 会 404（ADR-0003），所以身份必须自己拿；第三方 ID 只作可替换的锚点 |

**流动单向**：`领域语料 --promote--> 我的库`（带 provenance、可回滚）；反向只有"读"。**promote 以 work 为单位**（一个 work 只对应一个 Zotero 条目），而不是以 record 为单位。

**初版（M0–M3）不实现本节的任何后端**：不接 Zotero，`promote` 不会发生，「我的库」是空的。本节描述的是 M5 起的目标形态（[ADR-0032](决策/ADR-0032.md)）。

**冲突规则（元数据，四条）**：① **人工优先**——Zotero 侧编辑永远胜出；② **不合并、只失效**——发现条目变化（`dateModified`/`clientDateModified`，10+ 另有本地 `version`）即把相关缓存标 stale 重算；③ **写入显式**——改 Zotero 元数据必须显式命令，默认**只补空、不改非空**；④ **冲突暴露**——与 Zotero 不一致的外部元数据标 `metadata_conflict` 并进报告。

**没有任何字段同时存在两处**；唯一冗余是 `work_key ↔ itemKey` 指针。**「我的库」的权威由后端决定**（ADR-0009）：Zotero 后端下是 Zotero；FileBackend 下是 `library/` 目录中的 Markdown + YAML。

**发现正式版时的行为**（承接 ADR-0011，典型场景）：新记录进记录层 → 分组任务用 L0/L1 判据归入已有 work → 派生数据按 `content_hash` 决定复用还是重算 → **Zotero 条目不动**，只写一条待确认提示（"已发现正式版 DOI …，是否更新条目？"），由人决定是否补 DOI/venue/卷期。**预印本的原文与日期永不覆盖。**

#### 4.3.3 sidecar 三条原则

1. **「我的库」侧没有只此一份的数据**：sidecar 里不装任何用户资产，整个文件删掉，用户库毫发无损。id 是**确定性**的，重新抓取重建之后连 `record_uid` 与 `work_key` 都和原来一样；重建不回来的只有本地决定——候选的 `dismissed_at` 与人工拆组（[IFACE-DATA §4](接口/数据模型.md)）；
2. **不重复 Zotero 已有的东西**：元数据以 Zotero 为准，PDF 只存 Zotero 一份；
3. **只装可重建的派生数据**。

工程要求：外键用 `libraryID + itemKey`（不用自增 `itemID`）；**按 `Zotero-Server-ID` 分区**（10+ 版本号为本机局部版本）；`schema_version` + 迁移脚本；单写者 + WAL。

#### 4.3.4 单一检索入口（消除"分叉"）

```
lookup(DOI | arXiv ID | 标题 | 关键词 | 标签)
  ① 本地 Zotero（只读副本，离线、零成本、毫秒级）
       命中 → 返回条目 +「已在库」+ 附 sidecar 中文摘要（若有）
  ② sidecar 候选池（避免重复推荐、避免重复计费）
       命中 → 返回候选 + 评分与理由
  ③ 均未命中 → 联网 OpenAlex/arXiv，结果先与 ①② 去重，再落候选池
```
落点映射：**DOI/arXiv ID** → Zotero 的 DOI 字段 + sidecar 的 `record_ident`，两路合并去重；**标签** → 只查 Zotero（标签权威在该处，agent 自动打的标签也写进 Zotero）；**关键词** → Zotero 标题/作者 + `.zotero-ft-cache`，加 sidecar 的英文标题与摘要 FTS5（中文摘要不进索引，见 §4.3.5）。

**初版里第 ① 层为空**：本地去重只走 ②③ 两层，即 sidecar 自身——`record` 持久化上一次 run 的记录，`candidate` 持久化「看过但不要」（[ADR-0032](决策/ADR-0032.md)）。

**检索只有一条路径：刷新（可选）→ 查库 → 返回**（[ADR-0043](决策/ADR-0043.md)）。联网结果先落库，查询永远只面对数据库——所以没有「两个来源要合并」这回事。`--refresh auto|true|false` 决定刷不刷：默认 `auto` 按**检索式**新鲜度自行判断（不等价一律刷新）并**在输出里标注是否跳过**，`false` 绝不联网。来源标在每条结果上（`first_seen`），不做成开关。

**`--refresh` 三值在 `search` 与 `lookup` 上同义**（[ADR-0065](决策/ADR-0065.md)）：`true` 都是「先刷新，再查库」，`false` 都是绝不联网。`lookup` 即使本地已按标识命中也会刷一次——刷新不只为发现新论文，也为**更新引用数与安全信号**（`cited_by_count` / `counts_by_year` / `fwci` / `is_retracted` / `oa_status` / `pdf_url` / `type` / venue），而单实体 GET 免费（实测计费头 `x-ratelimit-cost-usd: 0`）。**两者的差别只在默认档**：`search` 的 `auto` 按检索式新鲜度判断，`lookup` 的 `auto` 按本地有没有命中判断（它的标识来源确定，不需要第二本新鲜度账）。`--title` 不是标识、用不了单实体 GET，在 `true` 下降级为只查本地并在 `degraded` 里标注。

**真正需警惕的三件事（属去重问题，非存储分叉）**：① 用户自己导入的重复条目（Zotero 自带检测只做 DOI/标题精确折叠，超 5000 条拒绝扫描）；② 预印本与正式版各存一条；③ Zotero 条目与 OpenAlex 记录是同一篇。

**这三件事现在统一由分组层处理**（§4.2）：前两件靠 L0/L1 判据归组，第三件靠 `record_ident` 里 `(ns='openalex')` 命中；L2 弱判据只登记待确认、不自动归组（[ADR-0048](决策/ADR-0048.md)）。**面向用户的三个入口——检索结果、候选池推荐、阅读列表——都返回 `work` 而不是 `record`**，所以同一篇论文不会因为来自两个源就出现两次；而"它来自哪几条记录"随时可查（这既是溯源，也让判据可以被人工复核）。

#### 4.3.5 中文摘要的可见性

**默认看不到**（sidecar 不出现在 Zotero UI）；写回需 Zotero 10+ 写入通道。四种位置：

| 位置 | 可见性 | 代价 | 结论 |
|---|---|---|---|
| **child note** | 条目面板 Notes 区，点开即读，可被搜索命中（建议 `Everything` 模式） | 条目树变长 | ✅ 默认（标题固定前缀，如「AI 中文摘要」） |
| Abstract 字段 | 最显眼（面板顶部，列表可加列） | 覆盖原文摘要、污染导出 | ❌ |
| Extra 字段 | 列表可加列扫读 | 行语法解析 + 导出泄漏 | ⚠️ 仅极短单行 |
| `.md`/`.html` 附件 | 附件区双击打开 | 通常不被全文索引、占附件位 | 备选（长报告） |

**检索一律用英文**（[ADR-0042](决策/ADR-0042.md)）：FTS5 用默认 `unicode61` 分词器，索引只覆盖英文原文（标题、摘要）。中文翻译与中文摘要照常生成，但**不进索引**——它们是给人读的，文本按 §4.3.1 的规则落 `bytes/`，sidecar 只留缓存键与指针。用户的中文表述由 agent 侧翻成英文关键词再检索。

#### 4.3.6 候选池：没有状态机

**候选池是「检索结果 → 决定要不要」之间的暂存区**：一张 `candidate` 表，**每篇作品一行**（键是 `work_key`）。**行存在本身就是事实**——"这个 work 入过池"。这里没有状态列（[ADR-0044](决策/ADR-0044.md)）。

三件常被当成"状态"的事，各有一个别处：

| 问题 | 答案在哪 |
|---|---|
| 这条抓过没有 / 会不会重复计费 | `record` + `record_ident` 的唯一约束 |
| 这篇推过没有 | `candidate` 行的存在；定时报告只列**本次入池**（按 `run_id`，[ADR-0028](决策/ADR-0028.md)） |
| 全文取过没有 | `artifact` 表里有该 work 的行——「要这篇」= `download` + `read`（[ADR-0035](决策/ADR-0035.md)、[ADR-0067](决策/ADR-0067.md)） |

**「要不要」只用两个可空时间戳表达**：

| 列 | 含义 |
|---|---|
| `dismissed_at` | 空 = 没表过态；非空 = 不要（不再主动推荐，仍可被显式搜索到） |
| `dismissed_until` | 空 = 永久；非空 = 到期后允许重新浮现（研究兴趣会变） |

**初版没有写入这两列的入口**：dismiss 顺延，初版不做"不再推荐"过滤，定时报告只列本次入池（[ADR-0051](决策/ADR-0051.md)）。

**不设"收藏"标记**：表达"我要"的现有方式是 `download` / `read` 与（M5 的）`promote`；正向标记会引出"收藏夹算不算 collection"的边界问题，而 [ADR-0032](决策/ADR-0032.md) 明令 sidecar 不长成条目库。

**质量分级留在库里，过滤在读取端**（[ADR-0044](决策/ADR-0044.md)）：分级（A/B/C）与理由随候选落库，**不做写入期淘汰**；掠夺性期刊黑名单与撤稿**无条件排除**。**初版没有分级数据**：A/B/C 分级、`--min-grade` 与 `config/search.toml` 里的质量阈值一并顺延（[ADR-0051](决策/ADR-0051.md)）；读取端过滤的机制保留，等分级落地后按同一阈值生效。

**确认粒度按动作分级**（[ADR-0030](决策/ADR-0030.md)）：`promote`（写入 Zotero）默认需人工确认；入库推荐（LLM 初筛）可配置为需确认或自动；翻译与文本化默认全自动——这条讲的是"要不要人工确认"，与状态无关。

**边界**：`candidate` 只装"入过池"与"表过态"两个事实，不得长出 collection、标签树或引用格式化（[ADR-0032](决策/ADR-0032.md)）。

#### 4.3.7 候选池 → 入库（promote）

```
search → candidates(sidecar：评分/分级/理由/来源)
  → [LLM 初筛 或 用户确认，按动作分级——见 ADR-0030]
  → promote：写入专用 collection（如 `Agent Inbox/<领域>`）+ provenance tag（如 agent/2026-10）
             + 记录 run_id / 决策理由 / 原始响应快照的指针
  → 回滚：按 run_id 找 itemKey → 删除（Zotero 删除进回收站，安全）
```
**这是最重要的安全阀**：agent 往用户的学术资产库里写东西，必须"可批量识别、可批量撤销"；绝不写进用户现有 collection。

#### 4.3.8 仅元信息条目与按需附件

- Zotero 里"元数据条目"与"附件"是独立 item，**没有任何字段要求条目必须有附件**（[REF-ZOTERO §2](调研/Zotero能力.md)）。
- **有元数据即可**：检索、collection 归类、去重、引用与参考文献导出、元数据同步（不占文件配额）、写 child note。**缺附件则不能**：阅读标注、该条目全文检索、页码定位。
- **策略**：默认 promote 为仅元信息条目；PDF 按需获取（[五级回退](调研/README.md)），作为子附件挂到**同一条目**，不重建条目、不影响去重键、不产生第二份 PDF。
- **工程要求**：全文相关查询一律 **LEFT JOIN**；`zotero_link` 允许 `zotero_attachment_key` 为空（仅元信息条目本来就没有附件）。

#### 4.3.9 复现语义：第二次检索到同一篇（且未入库）会发生什么

命中第三层 → **不新建候选、不重新计费检索、不重新调 LLM**，只做"刷新 + 决策保持"。

| 动作 | 内容 | 成本 |
|---|---|---|
| **刷新（每次做）** | `cited_by_count`、`counts_by_year`、`fwci`、`citation_normalized_percentile`、**`is_retracted`（必查，安全信号）**、`oa_status` 与 `pdf_url`（PDF 可能新出现）、`type`/venue（预印本可能已发表）、`refreshed_at`、`seen_count`、`last_seen_at` | 可批量按 ID 取，约 `$0.0001`/百条 |
| **重算（因输入变化）** | 质量分级（输入含引用信号）；引用边（若在图谱范围） | 纯规则计算，0 LLM；分级变化只影响读取端默认过滤，不改写入数据 |
| **复用（缓存命中）** | 中文翻译、各粒度摘要、嵌入向量 | 0 成本 |
| **保持（绝不重置）** | `dismissed_at` / `dismissed_until`、`first_run_id` | — |

**重新翻译的唯二触发条件**：① 源文本变了（OpenAlex 补全摘要；**arXiv 出 v2 改了 `summary`**）；② 生成参数变了（`model_id` / `prompt_version` / `terms_version` / `target_lang`）。

**关键边界（最易犯的错）**：**引用数绝不能进缓存键**。缓存键是 `sha256(源文本 ‖ 目标语言 ‖ 模型 ‖ 提示词版本 ‖ 术语表版本)`；若把整条记录哈希当缓存键，每次引用数变动都会触发全量重翻译。

**与 Zotero 的衔接**：`promote` 写 `zotero_link`（**work 级**，一个 work 只对应一个条目），此后命中走第一层——"已入库"由这行的存在表达，没有状态列；若用户在 Zotero 中删除该条目 → 记 `zotero_link.removed_at`，**不自动重新入库**（尊重删除决定），仍留在候选池可查。

### 4.4 缓存层

**键设计**（照搬 `zotero-mcp/src/zotero_mcp/fulltext_cache.py` 的内容哈希 + profile + 落库即逐出；其原则："文件变了必然换 hash，绝不供给陈旧文本"）：

```
content_hash = sha256(规范化后的源文本)      # 摘要原文 / 正文原文，按 kind 各算一次
derived_key  = (content_hash, kind, lang, model_id, prompt_version, terms_version)
```
把 `prompt_version` 纳入键，是避免"改了提示词却读到旧摘要"的关键；**把 `content_hash` 而不是 `record_uid` 放在首位**，是 ADR-0011 的落地点——同一段原文出现在多条记录（预印本 / 正式版 / 出版社）下只算一次，原文一变自动失效，且**与谁先算出来无关**。

| 缓存 | 失效触发 | 备注 |
|---|---|---|
| 翻译（标题/摘要/关键词） | **源文本内容哈希**、目标语言、模型或 `prompt_version` 变化 | **不整篇翻译**（成本 + 版权）；文本落 `bytes/`，DB 只留缓存键与指针（[ADR-0045](决策/ADR-0045.md)） |
| 摘要（分层） | 同上 + 摘要粒度（一句话/贡献点/方法-结果-局限） | 粒度不同即不同条目；文本落 `bytes/`，DB 只留缓存键与指针 |
| 抽取全文 | 附件/源文件内容哈希变化 | 原始文本永久可复用；**字节在 `bytes/`，sidecar 只存 sha256 指针**（[ADR-0029](决策/ADR-0029.md)） |
| 向量 | 嵌入模型或维度变化 | 需重建索引 |

**落点**：以上四类里，凡产出文本的都落 `bytes/`，sidecar 只留缓存键与 sha256 指针（[ADR-0045](决策/ADR-0045.md)）；`derived_content` **不装文本**——它回答"这段原文配这组参数算过没有"，`artifact` 回答"这份产物来自哪条记录"。

**内容哈希怎么算**（决定缓存命中率，必须固定下来）：先剥标记（MathML/JATS/HTML）→ NFKC → 统一连字符 → 折叠空白 → 大小写策略按 `kind` 定（摘要可比大小写不敏感，正文不行）。**哈希的是"规范化后的源文本"，不是原始字节**——否则同一段摘要只因换行不同就会重算。

**全文通道优先级**：① 原生文本源文本化（arXiv LaTeX 源码 / HTML，见 §4.10）→ ② `.zotero-ft-cache`（零成本，本机 6/6 命中；**M5**）→ ③ Zotero 全文 API（10+ 可 `GET/PUT …/fulltext`；**M5**）→ ④ PDF 自解析（`pymupdf` 已装）。**初版只有 ①（arXiv LaTeX 源码 / HTML）**；出版社 HTML 与 ④ PDF 自解析顺延（[ADR-0051](决策/ADR-0051.md)）。

**成本控制**：初版**不调任何 LLM API**——翻译与摘要在对话里按需产出，靠 `digest list --limit` 限流；专用翻译模型是计划内后续（[ADR-0037](决策/ADR-0037.md)）。


### 4.5 检索与命令接口

命令清单、输出信封、退出码与依赖策略见 [IFACE](03-接口契约.md)；与本地库的边界见 [接口/后端-LibraryBackend](接口/后端-LibraryBackend.md)。

**正文检索不走 SQLite**：`--in body` 时对 `works/` 做线性子串扫描，命中位置切成上下文片段（**前后各 2 行、每篇最多 5 处**，[ADR-0036](决策/ADR-0036.md)、[ADR-0053](决策/ADR-0053.md)）。

**`read` 的物化与缓存**：arXiv 源码 / HTML 从本地原件优先转换；正文与图件按清单绑定，离线与刷新规则见 [ADR-0074](决策/ADR-0074.md)。

**`read` 是定位器，不是搬运工**：返回 `bytes/` 里的 `paper.md` 路径、图件映射与锚点行号索引，全文由 agent 用自己的文件工具读（载荷见 [IFACE-PAYLOAD](接口/输出载荷.md)，[ADR-0053](决策/ADR-0053.md)）。

**按领域列清单（R12）**：本地模式下由 agent 用 `search --refresh false`（绝不联网）按关键词 / venue / 作者 / 年份查库，有缺口才改用 `--refresh true` 联网补；候选池不记方向标签（[ADR-0050](决策/ADR-0050.md)）。不给检索式时 `search` 返回本地库全部 `live` work（受 `--limit` 限制），是「先看看本地有什么」的入口。清单条目不装摘要；R12 要的「中文摘要」与「入库状态」怎么进清单，见 [ADR-0057](决策/ADR-0057.md)。

**退出码的判据是「有没有产出」**：部分源失败或余额降级但主链路产出正常时 `ok=true`、退出码 0，失败源进 `counts.failures[]`；全源失败且零写入才 1（[ADR-0056](决策/ADR-0056.md)）。调度器因此不会把降级当失败而重试花掉额度。参数解析失败不走这条判据：argparse 直接退出，退出码 2、无信封（[IFACE-PAYLOAD §6](接口/输出载荷.md)）。

**调度不进工具**：`sync` 只保证无头、幂等、报告结构化，频率由用户的调度器决定（[ADR-0038](决策/ADR-0038.md)）。

### 4.7 触发方式与运行账本

**调度器中立**（ADR-0005）：采集命令必须**无头 + 幂等 + 可观测**；DSH schedule、外部 agent 定时任务、系统计划任务任选、可组合。

```
# 采集（可被任意调度器无头调用）
academic-search sync [--query <具名查询>] [--refresh auto|true|false]
  → 抓取增量 → 去重与硬排除 → 入候选池（分级顺延、翻译摘要在 agent 侧，见 ADR-0051、ADR-0037）
  → 每条查询各写一套 data/runs/<run_id>/（run.json + report.md），并刷新 data/latest-report.md
    （「新发表 / 新发现」两栏见 ADR-0028；命名、汇总与 stdout 形状见 ADR-0055、ADR-0066）

调度器（任选，可组合）：
  · DSH schedule（如每周一 09:00：读最新 run 报告 → 要点提炼 / 异常提示 / 推荐阅读）
  · 外部 agent 工具自带的定时任务（如 Codex 等），由它调用命令或读取报告
  · 系统计划任务（Windows 任务计划程序 / cron）
```

**幂等与账本**：每次 run 独立事务并写一行 `run`（`run_id` 单调递增）；唯一索引保证重跑不产生重复候选。要不要联网刷新读 `spec_hash` 账本；首次回溯的查询身份与完整性判据见 [IFACE-PAYLOAD §3](接口/输出载荷.md)。

**增量策略**：`from_created_date`/`from_updated_date` 疑似付费层 → 采用"回看 N 天 + 本地去重兜底"，并记录已抓取的 OpenAlex ID（`record_ident(ns='openalex')`）以避免重复计费。**N = `config/search.toml` 的 `[sync] lookback_days`（默认 30）**；尚未完成首次完整联网采集时用画像的 `since_years`，完整性判据与历史账本处理见 [IFACE-PAYLOAD §3](接口/输出载荷.md)。

**具名查询与增量**（[ADR-0027](决策/ADR-0027.md)）：画像里的每条具名查询是一次可重放的采集单元，调度器引用**查询名**而不是画像名；因为窗口现场决定（回看 N 天 + 本地去重），具名查询**不需要各自的游标列**。临时专题就是带 `expires` 的一条查询。**候选池不记方向标签**：一篇候选来自哪次运行、哪条检索式，由 `first_run_id` → `run.spec_hash` 回答（[ADR-0050](决策/ADR-0050.md)）。注意 **`publication_date` 是正式版日期**（实测 arXiv 2009 的论文在 OpenAlex 里是 2012），所以"新论文"的时间窗必须用 arXiv 的日期。

**限流与预算**：初版**不设**请求数 / 并发上限——请求数由「一页 × 启用的源 × 查询数」自然限定，退避沿用各源客户端的既有实现；`search` / `sync` 的额度检查与停止行为见[配置目录 §3](使用/配置.md)，输出按实际进度区分未联网和部分完成；arXiv 严格 3 秒间隔且一天一次足够；Crossref 走 polite 通道；S2 失败不阻断主链路。

**并发**：写事务 `BEGIN IMMEDIATE` + 启动取锁，拿不到即报 `busy` 退出（不排队），保证无头任务失败可见（[ADR-0055](决策/ADR-0055.md)）。

**观测**：JSONL 结构化日志 + markdown 报告 + **结构化 `run.json`**（使"外部 agent 只读消费"成为可能）：新增候选、去重拦截、入库数、失败源与原因、token 与费用消耗。三者按 run 归拢在 `data/runs/<run_id>/`（`run.json` + `report.md` + `responses/`），另维护 `data/latest-report.md` 供调度器一步读取（[ADR-0055](决策/ADR-0055.md)、载荷见 [IFACE-PAYLOAD](接口/输出载荷.md)）。

### 4.8 引用图谱与研究脉络（未来，R10）

**数据基础**（[REF-SOURCES §4](调研/数据源事实.md)）：后向 `referenced_works`；前向 `filter=cites:<OpenAlex W id>`（注意：这里的 `<…>` 是 **OpenAlex 自己的** work id，从 `record_ident(ns='openalex')` 取，不是我们的 `work_key`）；`related_works`（相似推荐，非引用关系）；Crossref `reference[]` 补充。旧 `cited_by_api_url` 勿用。

**存储**：引用边的节点统一为 `work_key`（分组层），表见 [IFACE-DATA §3.10](接口/数据模型.md)：`citation_edge(src_work_key, dst_work_key, source, retrieved_at)`。抓回来的 OpenAlex ID 先经 `record_ident` 解析成 `work_key`——**没解析出来的目标节点暂存为待解析引用**，等它被检索到时再补，不要为了建图去拉全库。

**已知的坑（实测）**：`referenced_works` 可能短于原文参考文献表；被引数会随对方合并/删除而变动，所以引用边要有 `retrieved_at` 并可刷新。

**四种算法（成本递增）**：① 向后引用链；② 向前被引链；③ **主路径分析（main path analysis）**——学术谱系标准做法，给技术演进主线；④ 共被引 / 文献耦合聚类（识别流派）。

**可视化**：先出 **Mermaid / Graphviz**（零依赖、可入文档、diff 友好）；交互式图留待需要时。**大图必须裁剪**：路径裁剪 + 时间轴分层 + 每节点一句话摘要。

**成本**：引用边抓取属 `list+filter` 档（$0.10/千次），无 LLM 成本；被引 2 万条的节点分页取样而非全量展开。

### 4.9 可信、合规与隐私

**"可信"的可执行定义（N1）**：
- 每条结论可落到 `{work_key / DOI / arXiv ID, itemKey, 页码或段落}`；无出处的断言不输出（写进 SKILL.md 硬规则；CLI 侧的锚点保证由 `read` 的输出契约承担，见 [IFACE](03-接口契约.md)、[ADR-0051](决策/ADR-0051.md)）；
- 候选项携带来源与获取时间；**原始请求**进 `run` 账本，**原始响应快照**落 `data/runs/<run_id>/responses/`（只留产生被采纳记录的页与失败页），清单随 `run.json` 记（[IFACE-STORE §5](接口/存储与迁移.md)、[ADR-0055](决策/ADR-0055.md)）；
- 质量信号进决策但不越权：闸门给"分级 + 理由"，取舍留给人或显式配置的策略；
- 已知缺陷显式暴露：DOI 与标题不一致、缺 DOI、venue 缺失 → 标 `metadata_conflict`，不静默采用。

**合规**：
- 只取 OA 版本；DOI→PDF 五级回退（OpenAlex `best_oa_location` → Crossref TDM → Unpaywall → arXiv/PMC → 放弃并记录）；
- **arXiv 禁止自行托管/分发 PDF**；**PMC 只允许 E-utilities / OAI-PMH / BioC 等指定服务做自动化批量抓取**；Unpaywall 须真实 email；
- 翻译/摘要属派生使用，默认只对标题与摘要做，不整篇翻译再分发。

**隐私（N3）**：本地库内容默认不出网；送往云端 LLM 的内容可枚举、可关闭；提供"全离线"档（本地嵌入 + 本地翻译模型），代价是质量与速度。

### 4.10 全文文本化与图件流水线

**目标**：让 LLM 能读全文（PDF 对 LLM 不友好），同时让人能在 Zotero/浏览器里读同一篇的文本版；图件随文保存。

**按需取**：定时 run 不取全文，只有被要求时才走本节的流水线（[ADR-0035](决策/ADR-0035.md)）。

**分层来源（先原生文本，后转换）**：

| 层 | 来源 | 做法 | 保真度 |
|---|---|---|---|
| 1 | **arXiv LaTeX 源码** `/e-print/<id>`（实测可用） | 便携 pandoc `-f latex -t gfm --extract-media=figures/`；主 `.tex` 按 `\documentclass` 判定，PDF 图渲 PNG（`pdftocairo` → PyMuPDF 降级）——装配细则见 [ADR-0056](决策/ADR-0056.md) | ★★★ 公式原生、图为矢量原件 |
| 2 | **arXiv HTML** `/html/<id>`（实测可用） | pandoc `-f html -t gfm` | ★★ MathML → LaTeX |
| 3 | OA 出版社 HTML（MDPI / Frontiers / PLOS、中文期刊官网） | 同上 + 正文容器选择器 | ★★ |
| 4 | Zotero `.zotero-ft-cache` | 直接作纯文本（无结构，够检索）；**M5** | ★ |
| 5 | PDF → MD（PyMuPDF4LLM / marker / MinerU） | 回退 | ★ 公式与双栏易坏 |
| 6 | 扫描件 OCR | 最后手段 | ☆ |

**转换器**：随工具附带**便携 pandoc**（单文件置于 `vendor/`，不改系统环境；`tools/` 只放维护脚本，[ADR-0055](决策/ADR-0055.md)）；`converter` + `converter_version` 进缓存键（作为 `artifact` 与 `derived_content` 上的版本字段），换更好的转换器即触发重转。**PDF 图渲染器与其分辨率也计入 `converter_version`**（渲染器换了，Markdown 里的图件确实不同，[ADR-0056](决策/ADR-0056.md)）。

**必做装配五步**：

1. **抽取正文容器**：arXiv → `<article>`；MDPI → `.html-body`；通用 → `<article>` 或启发式；去掉 nav / footer / cookie 提示 / 推荐阅读；
2. **锚点注入**（R7 溯源的前置条件）：能拿到真实页码时注入 `<!-- page: N -->`；HTML/LaTeX 源注入 `<!-- sec: 3.2 -->` 并**明确标注为近似锚点**；
3. **图件本地化**：`<img>` 与 LaTeX 图片先落到内容寻址的 `bytes/`，再投影到 `works/<proj>/figures/`，Markdown 用相对路径引用；图注抽成 `captions.json`（可参与翻译与检索）；
4. **元信息头**：YAML front-matter（题名 / DOI / arXiv ID / 来源 URL 与版本 / 转换时间 / 转换器版本 / 许可备注；许可未核验时为 null）；
5. **登记**：写入 sidecar 的 `artifact` 表（见 [IFACE-DATA §3.7](接口/数据模型.md)），**记录这份产物来自哪条 record**。

**产物布局**（Markdown 与图绑定，便于整体打包给同学）：

```
bytes/<sha 前2位>/<sha256>        # 唯一字节存储（内容寻址，相同字节只存一份）
works/<proj>/                     # 给人看的投影，删掉可重建（名字见 ADR-0068）
├─ paper.md          # 给 LLM 读的派生文本（由最优来源记录转换而来）
├─ paper.html        # 可选：给 Zotero 索引与标注（Zotero 索引 HTML，不索引 .md）
├─ source.tar.gz     # 可选：arXiv LaTeX 源码（仅个人使用）
└─ figures/
   ├─ fig-01.svg     # 矢量原件（来自 LaTeX/HTML 源）
   ├─ fig-03.png
   └─ captions.json  # 图号 → 图注文本
```

**只有被要过的论文才有 `works/<proj>/`**：定时 run 只落候选，不落产物。

**选择哪条记录做"代表"**：同一 work 可能有多条记录各自能给全文（arXiv 源码 / 出版社 HTML / PDF）。默认优先级见 §4.10 的六层来源表（**按文本质量排，不按版本权威排**：arXiv LaTeX 源码优先于正式版 PDF），**选中哪条写进 `artifact.record_uid`**；产物在 front-matter 与 `artifact` 里标明来源，读出来时能说明"这是预印本"（[ADR-0053](决策/ADR-0053.md)）；若换了代表来源，产物按新记录的 `content_hash` 重新生成，旧产物留在 `bytes/` 里不删（可能仍被其它 work 引用）。

**与 Zotero 的关系**：Zotero 附件只放**人要看 / 要搜**的东西——HTML 快照（可索引、可标注）与 PDF 原件；Markdown 与图件留在 `works/`，避免同步配额与二进制污染（依据见 [REF-ZOTERO §2](调研/Zotero能力.md)）。

**许可边界**：arXiv 源码/PDF 与出版社 HTML **仅限个人使用，不得随工具或组内分享再分发全文**；分享时只发元数据 + 自行生成的中文摘要/笔记 + 引用链接（配合 `export --format bibtex|ris|csljson`）。
