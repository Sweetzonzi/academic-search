# ADR-0028　报告分「新发表 / 新发现」两栏

**状态**：accepted（2026-10-15）

- **决策**：采集报告与 `run.json` 分两栏——**新发表**（`publication_date` 落在本次窗口内）与**新发现**（本次 run 才入池、但发表时间更早）。「首次被检索到」不再单列 `first_seen_at`，收敛为**首次入池的 `run_id`**，时间点从 run 账本取。
- **理由**：① 两个问题正交——「世界上新的」用发表时间，「我才看到的」用入池时间；额度紧张时「上次没扫全」与「世界上真没有」必须分得开；② 发表时间**会变**（预印本→正式版实测可前跳三年、也可倒退两个月，见 [REF-SOURCES §5 第 12 条](../调研/数据源事实.md)），所以它只能当过滤条件，**不能进任何唯一索引或幂等键**；③ 单列时间戳会与既有的 `staged_at`、`run_id` 重复表达同一事实。
- **否决**：**只按 `publication_date` 一栏**——补录历史条目、或将来接入新数据源时，新发现的论文全被当成旧闻；**只按首次入池时间一栏**——无法回答「这个领域最近有什么」，热点判断失真。
- **代价**：报告与 `run.json` 多一栏；`run.json` 需记录本次窗口与查询名，两栏才有意义。
