# ADR-0060　venue 判据：载体 source id 集合 + 项目维护的登记表

**状态**：accepted（2026-10-16）

> **范围**：本条定 `venues` 白名单与 `venue_blacklist` **比什么**，以及「会名 → OpenAlex source id」登记表归谁维护。用户的书写方式不变——`config/profile.toml` 里仍然只写会名（`ICRA`）。引用阈值的形态不在本条内（见 [ADR-0061](ADR-0061.md)）；`--venue` 是否进 `spec_hash` 归 `Q22`。

- **决策**：

  1. **两侧名单共用一条判据**。作品的载体集合 = 其各成员记录 `locations[].source.id` 的并集；`venues` 命中 ⇔ 集合 ∩ 白名单 ≠ ∅，`venue_blacklist` 命中 ⇔ 集合 ∩ 黑名单 ≠ ∅。白名单与黑名单只差方向，判据与数据来源完全相同。
  2. **登记表进版本库、随代码分发**，位置在包内（与 `src/academic_search/schema.sql` 同级），**不放在 `config/`**——后者是各人一份、不进版本库的用户配置。条目 = 会名 + 一个或多个 S-id + 备注。配置里解析不到的名字**报错**，不静默失效；`S…` 允许直写，作为未登记载体的逃生门。
  3. **远端过滤器改用 `locations.source.id:`**（多值用 `|`），替代 `primary_location.source.display_name.search:`。
  4. **本地与远端同判据**。记录落库时保存自己的全部载体 source id，本地过滤读这份集合，不再对 `venue` 字符串做子串匹配。
  5. **给定 `venues` 白名单时跳过 arXiv 腿**：arXiv 无载体概念，取回来也判不了。与 `--source arxiv` 同时给出时，该腿如实返回 0，不报错。
  6. **黑名单的作用粒度保持作品级**（任一成员命中即整个作品排除）。这是现状（`work_is_excluded()`），本条只换判据，不改粒度。

- **理由**：

  1. **白名单归零是四层叠加，只有一层能靠改字符串解决。** [EX-2026-10-16-source-contract](../实验/EX-2026-10-16-检索口径与来源校验.md) §11 实测：三个画像查询带白名单恒返 0 条（50 / 47 / 50 → 0 / 0 / 0）。四层依次是：缩写对不上全称、arXiv 记录载体为空且判不通过、远端过滤器 400、语料里根本没有这些会的记录。
  2. **缩写根本不出现在数据里。** ICRA 的载体名是 `Proceedings - IEEE International Conference on Robotics and Automation/Proceedings`，NeurIPS 是 `neural information processing systems`（同 §11(c)）。任何「按名字匹配」的方案都得先跨过这一步。
  3. **本地映射最多救回 6 条，远端映射能取到 143 篇。** 白名单全称化之后全库可命中 6 条，且 0 条进入那三个画像查询；改用 `locations.source.id:` 之后 `"world model"` 在 ICRA 命中 143 篇、NeurIPS 110 篇（同 §11(d)(e)）。差别不在匹配，在**取数**：白名单筛的是已经抓回来的语料，而语料按「主题词 + 日期降序」抓，天然偏预印本与期刊。
  4. **`locations.` 比 `primary_location.` 宽。** 它能覆盖「主载体是预印本仓库、作品同时也挂在会议 proceedings 上」的情形，而这正是补桥取回的记录的样子（同 §11(c) 第 2 条：按 arXiv DOI 取回的 Work，其 `locations[]` 里只有 arXiv）。
  5. **会议在 OpenAlex 是系列级实体。** ICRA proceedings 一个 S-id（`S4210217939`）覆盖 32 827 篇作品、2023–2026 每年 1347–1882 篇，不需要按年维护（同 §11(d)）。
  6. **S-id 无法自动解析，只能登记。** `/sources` 的 `display_name.search:` 按全称片段能列候选，按缩写搜等于没搜（`ICRA` 只返回一个 6 篇作品的土耳其法学期刊，同 §11(d)）。既然必须人工确认，登记表就该由项目维护、进版本库。
  7. **登记把「写错名字」从静默失效变成报错。** 现在是归一化子串匹配：写错一个黑名单词条，什么都不会发生；改登记表之后，解析不到就是错误。

- **否决**：

  - **继续用 `primary_location.source.display_name.search:`**：实测 HTTP 400，且 400 不改变 `ok`（同 §5(a)），失败是静默的。
  - **只加一张「缩写 → 全称」的映射表**：能修第一层，修不了第三层——全称化后三个画像查询仍是 0 条（同 §11(e)）。
  - **让用户在配置里写 S-id**：把 OpenAlex 的内部编号推给使用者，编号本身无法自查，写错只会得到空结果。
  - **运行时按名字自动解析**：缩写搜不到；全称片段会返回几十个候选（`robotics and automation` 返回 55 个），必须人判断；而且每次解析都是一次全文检索计费。
  - **白名单空值判通过（fail-open）**：`--min-citations` 会因此失去意义——arXiv 侧没有被引数据（同 §6），放行等于不筛。
  - **白名单只作本地过滤**：画像是「按载体找论文」，本地过滤只能在已抓回的语料里筛，而那批语料里没有这些会（同 §11(e)）。

- **代价**：

  1. **记录要能承载「全部载体」。** 现有 `record.venue` 只存一个 `primary_location.display_name` 字符串，判定所需的信息不在库里。存量记录要靠重抓或单实体 GET 回填（单实体 GET 免费，[REF-SOURCES §2](../调研/数据源事实.md)），回填之前它们在带名单的查询里判不出来。
  2. **登记表成为黑白名单的唯一入口。** 想拉黑一个没登记过的载体，得先登记或直写 `S…`。这是「写错名字会报错」的另一面。
  3. **黑名单判据从「主载体名包含某串」变为「任一载体命中」。** 拉黑一个预印本仓库，会连带排除「正式发表、同一作品也挂在该仓库」的论文。现行 `venue_blacklist` 为空（`config/search.toml`），没有迁移负担。
  4. **给定白名单时跳过 arXiv 腿**，会漏掉「尚未在 OpenAlex 建立会议版本」的预印本。
  5. **登记表里的 S-id 会漂移。** OpenAlex 合并或拆分 source 之后旧编号可能失效；校验走单实体 GET（免费），需要一条能定期跑的路径。

- **触发重估的信号**：① 登记表的维护成本超过收益（新增一个载体要人工确认一次）；② OpenAlex 大规模重编 source id，登记表批量失效；③ 出现「跳过 arXiv 腿」漏掉重要论文的真实案例；④ 配置里出现大量 `S…` 直写，说明登记表没覆盖到真实用法。
