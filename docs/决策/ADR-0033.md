# ADR-0033　字节层用两个坐标分两层：`bytes/`（内容）与 `works/`（作品）

**状态**：accepted（2026-10-15）

- **决策**：`bytes/` 与 `works/` 是**两个正交坐标**，不是两个并列的库——

  | | `bytes/` | `works/` |
  |---|---|---|
  | 寻址键 | **字节是什么**（`sha256`） | **哪篇作品的什么产物**（`work_key` + 文件名） |
  | 路径 | `bytes/<sha 前2位>/<sha256>` | `works/<work_key>/paper.md`、`figures/` |
  | 内容 | **全部字节实体**，不分原始与派生 | **人读投影**，文件名可读 |
  | 生命周期 | 只增不减，**文件设只读** | 随时可删，可完整重建 |

  **原始 / 派生不是分界**：arXiv 源码、出版社 HTML、PDF 原件这些**采集来的原始字节**，与 `paper.md`、图件、全文翻译这些**本地算出的派生字节**，实体**都在 `bytes/`**。`works/` 里的同名文件是 `bytes/` 里那份的硬链接（[ADR-0034](ADR-0034.md)）。

- **理由**：
  1. **两个坐标正交，一个替代不了另一个**。一份字节可以被多个作品引用（同一份源码支撑预印本与正式版两条记录、同一张图被两篇论文引用），一个作品有多份产物——**多对多**，中间靠 sidecar 的 `artifact(record_uid, kind, sha256)` 连接。
  2. **`work_key` 会随分组变动，`sha256` 不会**：合并只写 `merged_into`，拆组会产生新键（[ADR-0003](ADR-0003.md)）。若字节按作品归置，每次重组都要搬文件；放在内容坐标下，重组**一个文件都不用动**，只改 sidecar 映射再重新投影。**这就是「投影可重建」的技术含义。**
  3. **`bytes/` 让缓存键就是路径**：`content_hash` 直接就是 `bytes/` 下的路径，不必另建「哈希 → 路径」的映射表（[ADR-0011](ADR-0011.md)）。该表若存在，其路径还会随作品重组而失效。
  4. **`works/` 提供可预测的可读路径**：`SKILL.md` 能直接写「读 `works/<work_key>/paper.md`」，Markdown 的相对引用（`![](figures/fig-01.svg)`）可用，`tar` 一个目录即可打包。

- **命名依据**：候选名里 `store/` 只说了**用途**（「存东西的地方」），`blobs/` 只说了**形态**（BLOB = 二进制大对象，而这层恰恰是给人读的文本与图件，词与义相反），两者都推不出分工。入选的两个名字各自说出**坐标**。

- **`works/` 的目录名用 `work_key`，不用可读标题**：
  - 可读标题**必然不稳定**——实测约 1/3 的论文标题在预印本 → 正式版之间会变，其中 11% 无法用归一化救回；跨来源还有 16% 的标题碰撞（[EX-2026-10-14-identity §3](../实验/EX-2026-10-14-身份与去重.md)）。
  - 用自增号或随机 id 则**破坏可复现性**（两台机器路径不同、删库重建后对不上），直接作废 [ADR-0003](ADR-0003.md) 的核心收益。
  - **可读性由出口提供，不由存储层提供**：`list` / `search` 输出可读清单并附带拼好的 `local_dir`；`open <work_key>` 打开；`export --out <目录>` 的输出目录可以自由使用可读名——因为那是**快照**，不是存储层。
  - **纪律：任何地方不得保存 `works/` 下的路径**（不写进 `SKILL.md` 的硬编码例子、不写进导出包、不落库），一律现场从 CLI 查询。

- **备选方案（当前不采用）**：`works/<slug>--<work_key 前 8 位>/`，例如 `works/2023-liu-attention--6a3f9d2c/`。
  - **好处**：资源管理器里能认出是哪篇。
  - **不采用的理由**：① 元数据变化时要改名，任何被保存下来的路径失效；② 需要 slug 清洗规则（Windows 禁用字符、长度截断、中文标题如何处理）；③ 与「路径可预测」冲突——agent 拿到 `work_key` 拼不出完整路径，必须依赖 CLI 返回 `local_dir`。
  - **这是可逆决策**：`works/` 不承载数据（库里只存 `sha256`，路径全是投影时拼出来的），将来要换命名法只需重建一次投影。唯一会让它不可逆的是有人开始长期保存路径——所以上面那条纪律现在就生效。

- **代价**：① 在资源管理器里直接翻 `works/` 认不出是哪篇（靠 CLI 与 `export` 弥补）；② 两个坐标的映射要靠 `artifact` 表维护，不能从目录结构推断。
