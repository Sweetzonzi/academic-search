# ADR-0062　`spec_hash` 的口径与取数页大小

**状态**：accepted（2026-10-16）

> **范围**：本条定 `spec_hash` 覆盖哪些参数，以及「一次远端取数取几条」。**取代 [ADR-0061](ADR-0061.md) 决策 5**（`--sort citations` 保持展示排序）——排序改为取数条件；ADR-0061 的其余部分继续有效。引用阈值的形态仍按 ADR-0061，本条只把它们纳入 hash。

- **决策**：

  1. **`spec_hash` = 这次会下发的远端请求的声明式参数**的规范化形式。判据只有一条：**它改不改变远端请求**。
  2. **进 hash**：`all_of` / `any_of` / `venues` / `authors` / `since_years`、显式给出的 `from` / `to`、`--source`、`--sort`、`--min-citations`、`--min-fwci`。
  3. **不进 hash**：`--limit`、`--abstract`、`--in`。
  4. **解析后的具体日期不进 hash**：进的是声明式参数（`since_years` 的值、显式给的 `from` / `to`），不是算出来的 `from_date`。否则窗口每天挪一天、hash 每天变一次，「窗口内不重复计费」当场失效。
  5. **一次远端取数固定取一页 100 条**，`--limit` 只截断展示，不再决定请求的 `per_page`；arXiv 侧同理（`max_results`）。
  6. **`--sort` 是取数条件**：`citations` 档下发 `sort=cited_by_count:desc`，默认日期档下发 `sort=publication_date:desc`。两者是不同的切片，各抓一次、都进同一个池。

- **理由**：

  1. **一条判据胜过一张字段表。** 原来的字段集是五项枚举，漏了 `--source`——[EX-2026-10-16-source-contract](../实验/EX-2026-10-16-检索口径与来源校验.md) §4 后果 ③：跑过一次 `--source arxiv` 之后，默认两源在 24 小时内被判新鲜、只查本地。改成判据之后，新增参数不必回来补表。
  2. **计费按次，不按条。** 实测同一条全文检索请求 `per-page=1` 与 `per-page=100` 都是 10 credits / `$0.001`（同 §13）。所以让小 `--limit` 限制取数是**纯损失**——默认 `--limit` 是 20，一次请求本可以带回 100 条。
  3. **它顺手消掉「快照被锁死」这个后果。** 现在一次 `--limit 5 --refresh true` 会把该检索式置为新鲜 24 小时，随后同字段的 `--limit 20` 只读到那 5 条（同 §4 后果 ①）。取数不再依赖 `--limit` 之后，这个后果不再存在。
  4. **排序不是展示偏好，是取数的另一端。** 远端恒按日期降序时，`--sort citations` 只能重排已经取回的那批，而库里被引 ≥100 的条目全靠 `lookup` 逐条补。把排序当取数条件之后，一次 `--sort citations` 就把「被引最高的一批」带进池，与日期序那批互补。
  5. **精度不靠取数端把关。** [DESIGN §4.1](../02-设计说明书.md) 已定「过滤发生在读取端」，语义复核由读取方负责。取数端因此应当偏向召回：多存一批不同切片的条目，比少取而漏掉划算。

- **否决**：

  - **保留五项枚举、只补 `--source`**：下一个参数（`--min-citations` / `--min-fwci`）又要回来补一次，而且枚举本身不表达判据。
  - **把解析后的日期也放进 hash**：窗口每天挪动，`spec_hash` 每天变一次，新鲜度判据失效——与 [ADR-0043](ADR-0043.md) 的「窗口内不重复计费」直接冲突。
  - **保持 `per_page = --limit`**：计费按次，取少不省钱，只减少入库量；而候选池的价值就在存量。
  - **`--sort` 继续只作用于展示**：那等于承认「找经典」只能靠 `lookup` 逐条补，与 [ADR-0061](ADR-0061.md) 的取向相反。
  - **给取数页大小单设一个参数**：按次计费之下没有需要它的场景，只多一个旋钮。

- **代价**：

  1. **`spec_hash` 变体数上升**：同一主题按排序与门槛各成一条新鲜度记录，一次 `--sort citations` 与一次默认档是两次请求（各 `$0.001`）。
  2. **每次请求入库量上升**：默认档从 20 条变 100 条，候选池增长更快。这是刻意取舍——按次计费下多取不花钱。
  3. **`--limit` 的语义收窄为纯展示**：`--limit 5` 之后池子里仍会多出 95 条。要表达「只看几条且不入库」需要新参数，本条不提供。
  4. **单页上限仍是 100**：`--limit > 100` 依旧只能取到一页，要更多得走 cursor 分页——本条不改这一点（现状亦然）。
  5. **`--source` 进 hash 之后**，`--source arxiv` 与默认两源不再互相顶替新鲜度，同一主题的联网次数略增。

- **触发重估的信号**：① 候选池增长速度超出可接受范围；② 出现「只看几条、别入库」的真实需求；③ `spec_hash` 变体数让「窗口内不重复计费」的实际节省变得可忽略；④ OpenAlex 改成按条计费。
