# ADR-0039　领域画像由 agent 写、CLI 只读校验；未配置时走「先草稿、后确认」的引导流程

**状态**：accepted（2026-10-15）

- **决策**：画像的**写**与**读**分给两边——
  - **CLI 只读**：`profile show`（回显当前生效的画像）、`profile check`（解析校验并回显摘要，失败报出错行）、`profile scaffold`（吐出带注释的模板）。**CLI 不提供任何写画像的命令。**
  - **agent 写**：新建与修改都走普通文件写入 `config/profile.toml`；改完必须跑一次 `profile check`。
  - **格式 TOML**：核心链路仅用标准库（[开发/约定](../开发/约定.md)），Python 3.11+ 自带 `tomllib` 可读；可写注释、不必给每个键加引号。JSON 不能注释，YAML 需要 PyYAML。
  - `config/` 与 `data/` **同级**：它是用户配置，不是运行期数据（[ADR-0040](ADR-0040.md)）。

- **未配置时的引导流程**（写进 SKILL.md 与 [使用/配置](../使用/配置.md)）：
  1. `profile show` 报「无画像」→ agent 进入引导；
  2. **agent 先出草稿，不要发问卷**——从本地库已有的主题、当前对话里用户说过的话、必要时一次公开检索试探，拼出画像初稿；
  3. 把初稿逐条摆给用户确认与增删（方向名、关键词、venue 白名单、回看窗口）；
  4. 写文件 → `profile check` → 把解析结果回显给用户。
  - **用户随时可以要求修改**：agent 直接改文件并重跑 `profile check`，没有别的通道。

- **理由**：
  1. **CLI 写配置是漂移源**：CLI 一旦能写，就要处理「文件被手改过」与「CLI 记忆的状态」不一致；而写文件这个动作 agent 本来就会，且改动对用户**可见可 diff**。
  2. **校验必须留在 CLI**：agent 手写的 TOML 完全可能语法有错。`profile check` 是「写完确实能被解析」的唯一保证，也把「格式正确」从 agent 的自觉变成机器的判定。
  3. **「先草稿后确认」优于问卷**：空手问五个开放问题，用户要凭空描述自己的方向；而本地库里已经有他的主题、对话里已经有他的说法。**agent 的信息优势就在于它能先猜，猜错了改起来比从零说更省事。**
  4. 与 [ADR-0037](ADR-0037.md) 同构：CLI 提供结构与校验，智能留在 agent 侧。

- **代价**：
  1. agent 写坏文件的机会存在——靠「改完必跑 `profile check`」这条纪律兜住，纪律写在 SKILL.md 里。
  2. **画像没有版本历史**，且它是**唯一不可重建的用户数据**——sidecar 删了能重建，画像删了就没了。`config/` 必须进用户的备份范围。

- **备选方案（当前不采用）**：CLI 提供 `profile set` / `profile add-query` 一族写命令。不采用的理由见理由 1；且这族命令很快会长成一套自己的配置 DSL，而它换来的只是「不用写文件」。
