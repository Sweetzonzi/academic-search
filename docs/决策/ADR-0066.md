# ADR-0066　`sync` 的运行粒度、产物形状与落地口径

**状态**：accepted（2026-10-16）

> **范围**：本条只定 `sync` 的**产物形状**——一次调用写几行 `run`、`run.json` 与 stdout 装什么、报告是一份还是 N 份——外加落地前必须写死的几处口径（刷新档位、查询解析、窗口与首次执行、响应留档、额度阈值）。采集本身（取数、去重、落池、硬排除）沿用 `search` 的流水线，不在这里重开。本条定义的口径落在末尾列出的位置（2026-10-16 已同步）。

- **决策**：

  1. **运行粒度：一条具名查询 = 一行 `run`。** `sync` 为它实际执行的每条查询各写一行，字段沿用现有单值列（`spec_hash`、`query_name`、`window_from` / `window_to`、`refreshed`、`counts`、`responses`、`last_success_watermark`）。`data/runs/<run_id>/` 因此仍是「一次 run 一套留档」，[ADR-0055](ADR-0055.md) 决策 1 的字面与结论都不动，`schema.sql` 与 `schema_version` 不动。
     - 不采用「一次调用一个 `run` + 逐查询子表」：那张子表的每一行**恰好就是一行 `run`**；而 `refreshed`、`window_from` / `window_to` 是单值列，装不下「5 条里 3 条刷新、2 条跳过」，最终还是得下沉成一张按查询的表——也就是现在这张。

  2. **`run.json` 的字段收敛为单数。** [IFACE-PAYLOAD](../接口/输出载荷.md) §3 的 `queries[]` / `spec_hash[]` 改成 `query`（可空；`search` / `lookup` 的 run 为 null）与 `spec_hash`（同）。一次 run 永远对应一条检索式，数组没有第二个元素。
     - 现在改是零成本：该文档仍是草案、没有任何实现引用它；一旦被实现引用，§9 的「只增不删」就会把它锁死。

  3. **`run.json` 装两栏清单**，给 [ADR-0028](ADR-0028.md) 的「报告与 `run.json` 分两栏」一个落点：`items: {new_published: [...], new_discovered: [...]}`——新发表 = `publication_date` 落在本次窗口内；新发现 = 本次 run 才入池（`candidate.first_run_id` = 本次 `run_id`）而发表更早。
     - 条目取 [IFACE-PAYLOAD](../接口/输出载荷.md) §2 的**可溯源最小集**：`work_key`、`title`、`published_at`、`doi`、`arxiv_id`、`sources[]`；**不带摘要与正文**（与 [ADR-0057](ADR-0057.md) 同一判据）。
     - 排序按 `published_at` 降序；不设条数上限——一次 run 的取数上限是「一页 100 条 × 启用的源」，合并去重后只会更少。
     - `counts` 不增加两栏的计数：它们的行数就是 `items` 的长度，同一个数记两处就是两处会漂（[AGENTS](../../AGENTS.md) 第 0 节第 1 条）。

  4. **`sync` 的 stdout：逐 run 自包含，不设调用级合计。**

     ```
     data = {
       runs: [
         {run_id, status, query, spec_hash, refreshed, window: {from, to},
          counts: {new_candidates, dedup_blocked, by_source: {}, failures: [{source, reason}]},
          cost: {usd, basis, requests}},
         …
       ],
       degraded?: {reason}
     }
     ```

     - 每个元素是 `data/runs/<run_id>/run.json` 的**逐字真子集**：去掉 `command`、`responses`、`timezone`、`started_at` / `finished_at` 与 `items`（结果清单不进 stdout，[ADR-0056](ADR-0056.md) 决策 1 不变）。
     - **不设调用级 `counts` / `cost` 合计**：它们都是纯折叠（求和 / 拼接），与 `runs[]` 里的值各占一个家。调度器要总数自己 fold（一行 `jq` / PowerShell）。
     - `network` 不再是 `sync` 的顶层字段：它就是 `runs[].refreshed` 的或。[IFACE-PAYLOAD](../接口/输出载荷.md) §1 的「检索类命令必带 `network` / `cost`」限定为**单 run 命令**（`search` / `lookup`）。
     - `degraded` 仍是**调用级**的唯一位置（部分查询跳过刷新、额度降级都归它）。
     - `ok` 与退出码也是调用级的：全部 run 都 `failed` 且零写入才 `ok=false`、退出码 1；只要有一条产出就是 0（[ADR-0056](ADR-0056.md) 决策 5）。

  5. **报告的单元：每条 run 一份，`latest-report.md` 是「最近一次调用」的汇总。**
     - `data/runs/<run_id>/report.md`：那一条查询的报告，头部与同目录的 `run.json` 同源，正文两栏（新发表 / 新发现），用决策 3 的同一份数据渲染。
     - `data/latest-report.md`：**最近一次调用**的汇总——按查询分节，每节就是该 run 的报告内容。它不再是「某个 run 的副本」（[ADR-0055](ADR-0055.md) 决策 1 的措辞据此收窄），因为「调度器一步读取」要的正是这一次调用的全貌。
     - 单查询调用时两者内容相同，仍然各写一份（位置固定比省一次写入重要）。

  6. **初版只有 `sync` 落 `data/runs/<run_id>/`。** `search` / `lookup` 只写 `run` 账本行（`responses` 列为 NULL），不建目录。留档的消费者是调度器与事后审计，交互式检索没有这层消费者；而按交互次数增长的 `data/runs/` 正是 [ADR-0055](ADR-0055.md) 代价 5 担心的那件事。`run.json` 的 `command` 字段保留。**将来把联网的 `search` / `lookup` 也纳入同一套留档**（`run.json` + `responses/`）：届时要一并给它们的 `run.json` 定 `items` 语义——`sync` 那两栏是报告语义，交互式检索没有。触发信号见文末 ⑥。

  7. **`sync` 有 `--refresh auto|true|false`，默认 `auto`**，三值与 `search` 同义（[ADR-0043](ADR-0043.md) 决策 2），[IFACE](../03-接口契约.md) 的 `sync` 行补上它。
     - `auto` 按**每条查询自己的 `spec_hash`** 判；跳过时该 run 仍写行（`refreshed=否`、`cost=0`）。
     - 同一批次里若两条查询的 `spec_hash` 相同，后一条会命中前一条刚写的账本而跳过——这是账本判据的直接结果，不额外去重。
     - 部分查询跳过时，`degraded.reason` 给一句话汇总（如「3/5 条查询在新鲜度窗口内，跳过联网」），不为此在 `runs[]` 上加字段。

  8. **`--query` 的解析与跳过语义。**
     - 缺省（不给 `--query`）= 画像里全部 `enabled=true` 且未过期的查询。
     - 显式 `--query <名>` 而名字解析不到 → `invalid_args`，`message` 列出画像里的可用名。
     - 名字解析到但 `enabled=false` 或已过期 → 同样 `invalid_args`：显式点名一件画像明说不要做的事是调用方的错，静默跳过会让整次调用白跑。
     - 画像缺失 → `no_profile`；画像存在但一条可跑查询都没有 → `invalid_args`。
     - `Query.expired()` 的到期判据由此有了第一个消费方。

  9. **窗口与首次执行。**
     - 窗口现场算：`config.date_window` 给 `window_from` / `window_to`，写进 run 行与报告头部。
     - **「首次执行」按查询判**：该 `query_name` 在 `run` 里还没有 `status='ok'` 的行，就用它自己的 `since_years`；否则一律用 `lookback_days`。不新增列——判据直接读账本（[ADR-0027](ADR-0027.md) 的「不需要游标列」）。
     - 窗口上界恒为今天，不拿「本次实际取到的最大 `publication_date`」回填：窗口是**请求的口径**，用取到的结果当上界会让「这次取到哪一年」悄悄改变下一次的窗口。
     - [ADR-0055](ADR-0055.md) 决策 6 的「首次运行（无水位）」原先只有全局读法；按全局判有一个反直觉后果：画像里**后来新加**的方向（[ADR-0041](ADR-0041.md) 决策 4 的「把临时检索写进画像」正是这条路径）永远只有 `lookback_days`，它自己的 `since_years` 从不生效。

  10. **`responses[]` 的留档口径。**
      - `run.responses` 与 `run.json` 的 `responses[]` 记 `{n, sha256, source, url, page, status}`；字节落 `data/runs/<run_id>/responses/<n>-<source>.json`，`n` 从 1 起、按请求发生顺序。
      - `page` = 该响应对应的取数页；初版取数固定一页 100 条（[ADR-0062](ADR-0062.md) 决策 5），因此恒为 `1`。
      - 留档判据：该响应**产生了至少一条写入 `record` 的记录**，或该请求失败（[ADR-0055](ADR-0055.md) 决策 2）。空页与整页被去重拦掉的页不留——留档要回答「这次看到了什么」，把去重之后的判断当判据会丢掉「看到过但没要」的那一半。
      - 客户端要新增能力：`HttpClient` 现在取完即弃，需要保留本次 run 内每条请求的原文与元数据，供收尾时挑选落盘。

  11. **额度降级：补上 [ADR-0051](ADR-0051.md) 决策 5 缺的阈值与检查点。**
      - `config/search.toml` 新增 `[quota] min_remaining_usd`，默认 `0.05`。
      - 检查点：每条查询开始取数前、以及每个源返回后，读 `HttpClient.rate_remaining_usd`；低于阈值即停止本次 run 的剩余腿，等价 `--refresh false`——`refreshed` 记否、`cost` 记已花、`degraded.reason` 记「余额不足，只查本地」。
      - 默认值依据：实测 23 次联网 `search` 的账本合计 `$0.023`（约 `$0.001` / 次，[EX-2026-10-16-source-contract](../实验/EX-2026-10-16-检索口径与来源校验.md) §1），`0.05` 约合 50 次检索的余量；无 key 档日额度 `$0.10` 时它会在当天较早触发，正是要保护的场景。
      - **不加请求数 / 并发上限**：[DESIGN](../02-设计说明书.md) §4.7 的「单次 run 的请求数 / 并发 / 退避上限显式配置」在初版收窄为「不设上限」——请求数由「一页 × 启用的源 × 查询数」自然限定，退避沿用各源客户端的既有实现。

  12. **范围外**：存量记录补载体 source id（[OPEN](../06-待决事项.md) 的 `Q30`）**不进 `sync` 的收尾**；该条的候选从三个减到两个（一次性脚本 / 独立子命令）。

  13. **删掉「水位」这个词与 `run.last_success_watermark` 这一列。** 它把两件事压在一个名字下，拆开各自命名，术语本身不再保留：
      - **「`spec_hash` 账本」**：回答「这个检索式刷过没有、什么时候刷的、要不要再刷」——判据是 `run` 表里 `status='ok'` 的行。名字沿用 [ADR-0043](ADR-0043.md) 已经在用的「账本」，不另造词。
      - **「首次执行」**：回答「用哪个窗口」——该 `query_name` 在账本里没有成功行就是首次执行，用 `since_years`；否则用 `lookback_days`（决策 9）。
      - 要指「上一次成功跑到哪天」时，直接写「上一次成功运行的 `window_to`」，不给它起名词。
      - 逐处替换：[IFACE-DATA](../接口/数据模型.md) §3.8 删掉该列的行、「增量不依赖水位」改成「增量不需要游标列」；[DESIGN](../02-设计说明书.md) §4.7 的「幂等与水位」改成「幂等与账本」、「首次运行（无水位）」改成「首次执行」、「不需要各自的水位」改成「不需要各自的游标列」；[IFACE](../03-接口契约.md) 的 `sync` 行「水位 + `run_id`」改成「账本行 + `run_id`」。
      - [ADR-0027](ADR-0027.md) / [ADR-0038](ADR-0038.md) / [ADR-0055](ADR-0055.md) 的正文**不改**（记录类一经接受不再改写），只在状态行标 `partially superseded by ADR-0066`。
      - 代码侧：`schema.sql` 删列、`store.finish_run` 去掉该参数。迁移机制现在只会加列，要补一格删列能力（`schema_version` +1）；实测该列 213 行全为 NULL，删除零数据损失。

- **理由**：

  1. `run` 行的存在理由就是「**这条检索式**上次什么时候刷的」（[IFACE-DATA](../接口/数据模型.md) 的总表），实现也是按 `spec_hash` 查的（`store.last_refresh_at`）。刷新判据、窗口、首次运行本来就按查询各记各的；把多查询塞进一行，只是把同一件事换个地方存。
  2. [ADR-0027](ADR-0027.md) 已经把具名查询定义为「一次可重放的采集单元」——采集单元就是 run 的粒度，两者不该是两层。
  3. stdout 不设合计：合计是纯折叠，给了就与逐 run 值构成两个家（[AGENTS](../../AGENTS.md) 第 0 节）；省下的那一次 fold 由调度器付，代价是一行脚本。
  4. 报告按 run 一份、latest 给调用汇总：调度器引用的是**查询名**（[ADR-0027](ADR-0027.md)），一次调度一条查询就得到一份完整报告；而「一次跑全部查询」的人要的是全貌，`latest-report.md` 因此必须是调用级的。
  5. 首次窗口按查询判，是因为画像会长大：把新方向写进画像就指望它回溯几年，是 `since_years` 这个字段存在的唯一理由。
  6. 留档判据用「写入了 `record`」而不是「进了候选」，是让快照回答「这次看到了什么」；候选是去重之后的判断，用它当判据会让「看到过、被拦掉」的页无据可查。
  7. 额度阈值必须有数才可执行：`rate_remaining_usd` 早就解析出来了，缺的只是「低于多少就停」与「在哪停」；不写死一个数，[ADR-0051](ADR-0051.md) 决策 5 就永远停在纸面。

- **代价**：

  1. 一次多查询 `sync` 产生 N 个目录、N 份 `report.md`，`data/runs/` 按查询数增长；[ADR-0055](ADR-0055.md) 代价 5 的担心提前生效。
  2. 调度器与 agent 要自己 fold 花费与计数，看不到「这一轮合计花了多少」。
  3. `run.json` 与 stdout 仍是子集关系，需要一层字段裁剪函数（[ADR-0056](ADR-0056.md) 代价 1 同样）。
  4. `--query` 点到禁用或过期的查询直接报错，比「静默跳过」更容易打断调度器；换来的是不会整次白跑。
  5. 首次窗口按查询判，意味着删掉某条查询的历史 run 行会让它重新按 `since_years` 回溯一遍（多花一次钱）——没有保护，也不该有。
  6. 额度阈值 `0.05` 是从「约 `$0.001` / 次」外推的估计值，不是从真实余额曲线校准的；无 key 档 `$0.10` / 天下，它会在当天较早触发。

- **备选方案（当前不采用）**：

  - **一次调用一个 `run` + 逐查询子表**：见决策 1 的理由——子表内容与 run 行相同，等于把一张表拆成两张。
  - **stdout 同时给逐 run 与调用级合计**：两处记同一个数；真到「要一眼看合计」的那天，加的是渲染层而不是契约。
  - **`report.md` 一次调用一份**：更贴合「调度器一步读一份」，但要么给批次一个新命名（[ADR-0055](ADR-0055.md) 刚取消过按日期的报告命名），要么让报告与它所在的 run 目录失去对应关系。
  - **首次窗口按全局判**（[ADR-0055](ADR-0055.md) 决策 6 的字面读法）：后来加入的方向永远只有 `lookback_days`。
  - **`search` / `lookup` 也落 `data/runs/<run_id>/`**：`command` 字段已经留了位置，但初版没有消费者——**将来纳入**，见决策 6 与文末 ⑥。

- **触发重估的信号**：① `data/runs/` 的增长需要 GC；② 出现「一次跑全部查询、且要一份合计」的真实请求；③ 报告拆成每查询一份之后，使用者反而更常读 `latest-report.md`（那时该把报告单元改成调用级）；④ 额度阈值在真实使用中误触发或迟触发；⑤ 出现「画像里新加的方向只回溯了 30 天、漏掉要看的论文」的真实案例；⑥ 出现「要复盘某次交互检索当时看到了什么」的真实需求。

- **落点**：

  - [IFACE](../03-接口契约.md) 的 `sync` 行（补 `--refresh` 三值、`data.runs[]` 形状、报告单元）；
  - [IFACE-DATA](../接口/数据模型.md) §3.8（删 `last_success_watermark` 行、「增量不依赖水位」一句改写、`responses` 的 `n` / `page`）；
  - [ADR-0055](ADR-0055.md)（决策 1 的「副本」措辞、决策 6 的「首次」粒度）、[ADR-0056](ADR-0056.md)（决策 1 的 `sync` 形状）、[ADR-0051](ADR-0051.md)（决策 5 的阈值落点）；
  - [ADR-0027](ADR-0027.md) / [ADR-0038](ADR-0038.md) / [ADR-0055](ADR-0055.md) 的**状态行**标 `partially superseded by ADR-0066`（正文不改，记录类一经接受不再改写）；
