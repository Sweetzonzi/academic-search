# ADR-0050　删除 topic 标签

**状态**：accepted（2026-10-15）

- **决策**：
  1. **候选池不再有 `topic` 列**，`search` 去掉 `--topic` 参数，`ad-hoc` 这个缺省值随之取消。
  2. **"专题"只由画像里的一条具名查询承载**（名字 + 检索式 + 年份窗 + 可选 `expires`），不再有"候选池侧的化身"（[ADR-0027](ADR-0027.md) 的②删除）。
  3. **"一篇候选来自哪次运行、哪条检索式"由 `first_run_id` → `run.spec_hash` 回答**，不另设标签。
  4. **按方向看已入池结果与综述取材的"本地优先"**：本地模式下由 agent 用 `search` 查库（`--refresh false` 绝不联网），检索式当场给（关键词 / venue / 作者 / 年份）；只有本地缺口才 `--refresh true` 联网补。
- **理由**：
  1. **标签的活由已有字段干**：候选行已经通过 `first_run_id` 指向那条 run，run 上有 `spec_hash`（[ADR-0043](ADR-0043.md)）。再养一个多值方向标签就是第二处真相源，同 [ADR-0008](ADR-0008.md) 的"没有字段两处可改"。
  2. **"一篇论文同时属于两个方向"这个多对多没有真实需求**：R12 要的是"给定领域或主题列出清单"，领域当场用关键词表达即可，不需要给每篇候选贴方向。
  3. **它从未被完整定义**：多值怎么落库、`ad-hoc` 是"一个方向"还是"没有方向"、它与 run 的归因分工，三件都没定；删掉比补全便宜。
  4. **命名空间混装**：专题标签与临时检索标签共用一处且不查冲突（[ADR-0041](ADR-0041.md) 决策 3），是模糊的温床。
- **代价**：
  1. **不能再问"这篇候选属于哪些方向"**，也不能直接列出"某个方向跨多次 run 累积的池子"；替代是当场给检索式查库（近似匹配，不如标签精确）。
  2. **本地查询要支持 venue / 作者 / 年份过滤**：目前只明确了 FTS5 覆盖英文标题与摘要原文（[ADR-0036](ADR-0036.md)），M1 实现时要把这些字段的筛选落到 sidecar 上。
  3. **不做按方向筛池**：不给 `--topic` 增设筛选语义，替代路径见代价 1。
- **触发重估的信号**：若实际使用中反复需要"按方向列出跨 run 的累积清单"，且关键词查库明显不够，再考虑给候选池加方向归属（届时先定多对多的落库形态）。
