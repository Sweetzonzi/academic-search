# ADR-0027　专题的组织方式

**状态**：accepted（2026-10-15）

> **取代**：本条决策里的"② 候选池上的一列 `topic` 标签（多值）"由 [ADR-0050](ADR-0050.md) 删除——专题只由画像里的具名查询承载，候选池不记方向归属。

- **决策**：一个「专题」（临时研究方向、开题方向、要盯三个月的新领域）**不是独立实体**，而是两样东西的组合：① 领域画像里的一条**具名查询**（名字 + 可重放的 filter + 年份窗 + 可选 `expires`）；② 候选池上的一列 `topic` 标签（多值）。调度器引用的是**查询名**，命令用 `--query <name>` 指名。
- **理由**：① tag 挂在结果上、查询配方在输入侧，只有「查询」这一项是 tag 表达不了的；② 增量本来就无状态（回看 N 天 + 本地去重，见 [DESIGN §4.7](../02-设计说明书.md)），具名查询因此**不需要存每条查询的水位**，可随时重放；③ 独立专题实体要带状态机、预算与生命周期，会引入第二个真相源，与 [ADR-0008](ADR-0008.md) 的「各自权威、无字段两处可改」相悖。
- **否决**：**只打 tag、查询不入库**——下次检索的口径只剩会话上下文，一旦上下文压缩就丢失；**独立专题实体**——多一张带状态机的表，收益仅是省掉画像里的一个配置字段。
- **代价**：专题的寿命由人维护（`expires` 到期即删条目），没有暂停/归档状态机；预算与频率仍写在画像/配置层，不进 sidecar schema。
