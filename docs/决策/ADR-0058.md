# ADR-0058　摘要按需带出：`lookup` 固定带全文摘要，`search` 用 `--abstract` 开关

**状态**：partially superseded by [ADR-0059](ADR-0059.md)（2026-10-16 接受，2026-10-16 收窄）

> **范围**：本标准回答 `record.abstract` 这一列在结果条目里**出不出、出多少、取谁的**。它是对 [ADR-0057](ADR-0057.md) 的收窄——ADR-0057 定下的「摘要与正文不进载荷」对**大清单**仍然成立，但它的理由不足以覆盖单篇场景，本条补上这一半。设计背景见 [ADR-0053](../接口/输出载荷.md)（载荷契约的家）。
>
> **被收窄的部分**：决策 3 里 `[abstract] chars` 的默认值 `240` 已由 [ADR-0059](ADR-0059.md) 改为 `800`；本条其余部分继续有效——`lookup` 带全文摘要、`search` 的 `--abstract` 开关、字符数走配置、两级取值规则、载荷不带来源标记。

- **决策**：

  1. **`lookup` 固定带完整摘要**：条目新增 `abstract`（string），不做截断、不需任何开关。
  2. **`search` 引入 `--abstract` 开关**（布尔，默认 `false`）：关时条目不含 `abstract` 键；开时每条带上**截断到 `config/search.toml` 的 `abstract.chars` 个字符**的摘要。
  3. **字符数走配置，不写死在参数里**：`search.toml` 的 `[abstract] chars`，默认 `240`。改配置即改截断长度，不需要动契约。**但这个缺省值必须同时在代码里兜底**：`config/` 整个目录不进版本库（`.gitignore`），因此要在 `src/academic_search/config.py` 里补一个 `DEFAULT_ABSTRACT_CHARS = 240`，与既有的 `DEFAULT_MAX_AGE_HOURS` / `DEFAULT_LOOKBACK_DAYS` 同一套写法；否则换了机器就没有这个键，同一条命令的行为不可复现。
  4. **多篇成员摘要不一致时按两级取值**：第一级看**版本层级**（`role=published` 优先于 `preprint`），第二级在同一层级内看**文本保真度**（`arxiv` 原生 `<summary>` > `crossref` 原生 `<abstract>` > `openalex` 由 `abstract_inverted_index` 还原）。取到第一个非空即停。
  5. **载荷不另加来源标记字段**：`abstract` 只有一个字符串值，不带「这条来自哪个源、是不是还原产物」的标记。来源可靠性问题**写在使用方可见的位置**（`SKILL.md` 与 `references/`），由文档说明而非字段承担。

- **理由**：

  1. **单靠标题无从判断相关性。** 摘要的第一用途不是「内容预览」，而是「判断要不要点开」；缺少它时使用者只能退回外部检索去确认一篇论文讲什么。
  2. **ADR-0057 的理由建立在「大清单」这个场景上，而它的适用范围写的是 `search` / `lookup` 两者。** 逐条对照，它的五条理由在单篇上有四条失效或不适用：①「摘要服务另一个动作」——`lookup` 的动作本身就是「看确定的这一篇」；②「体积」——单篇一条摘要不构成量级问题；③「不把派生内容的失效带进台账」——该条约束的是按 `content_hash` 分派的**派生**中文摘要，而 `record.abstract` 是原生书目列，不是派生内容；⑤「`--limit` 护栏」——与单篇无关。只有④「载荷形状不该随参数变」在本决策下需要单独处理，见理由 5。
  3. **承接摘要的替代通道目前都未接线。** ADR-0057 的代偿是把摘要交给 `digest`（[ADR-0045](ADR-0045.md)、[ADR-0054](ADR-0054.md)）与 `textify` + `read`（[ADR-0035](ADR-0035.md)），而这两条今天都还不能用，且 `read` 服务的是全文而非摘要。把摘要留在没有任何通道承载的状态，等于清单在其主要用途上不可用。
  4. **摘要会随版本漂移，取值必须有规则。** 2026-10-16 实测（[EX-2026-10-14-identity §6](../实验/EX-2026-10-14-身份与去重.md)）：9 组预印本／正式版配对里 2 组实质变化（22%），最坏 Jaccard 0.53，正式版篇幅近乎翻倍；标题那边可比数字是 28 组里 11%。**样本仅 9 篇，22% 只能当量级指示**，但足以支撑「版本层级优先」。同一批实测还发现 Crossref 侧 **88% 没有 `abstract` 字段**，故保真度级里原生来源排在 OpenAlex 还原之前。
  5. **`--abstract` 不破坏「同一检索式命中同一本账本」。** 开关影响的是**输出形状**，不是**检索式**：`spec_hash` 只由 `--all-of` / `--any-of` / `--venue` / `--author` / `--since-years` / `--source` 决定，`--abstract` 与 `--limit` 一样不进 `spec_hash`。因此 ADR-0057 理由④所担心的「同一检索式账本对不上」不受影响。
  6. **截断而非全文，是为了让清单场景可用。** 30 条 × 240 字符约 7 KB，而全文摘要约 45 KB——判断相关性通常读到方法句就够，多出来的部分留给 `lookup`。

- **否决**：

  - **`search` 也默认带全文摘要**：体积理由（ADR-0057 理由②）在清单上确实成立，全库规模上来后不可接受。
  - **新增一条专门取摘要的命令**：`SKILL.md` 的决策树已经把「先 `search` 找到条目、再 `lookup` 看这一篇」写成推荐动线，摘要正落在这条动线的终点，不必再造一个入口。
  - **取值只看文本保真度（`arxiv` > `openalex`）**：把版本权威性与字符保真度压成一条链，会在论文已有正式版时给出预印本的表述。两者正交，必须分两级。
  - **载荷里加 `abstract_source` 标记**：信息有用，但会让每一个解析载荷的地方都为「可能还原产物」分摊复杂度。改由接触这条边的第一现场（使用方文档）说明，成本更低。

- **代价**：

  1. **`lookup` 的输出体积不再恒定**：①`search` + `--abstract` 与 `lookup` 的载荷形状不同——解析方要注意 `abstract` 键**可能缺席**（`search` 未开 `--abstract` 时）或**被截断**。契约里按「可空且可能截断」处理。
  2. **摘要可能不是作者最终稿**：按决策 4，当一篇只有预印本记录时给的就是预印本摘要；按决策 5，`abstract` 不带标记，使用者无法从载荷本身察觉。这是接受决策 5 那条取舍的代价，缓解办法是文档说明（实现时落在 `references/cli-reference.md`）。
  3. **摘要可能不是逐字符原文**：通常的解释路径经 OpenAlex 还原产物时会有词序与标点失真（OpenAlex 官方明确不提供纯文本摘要）。同上，不在载荷里体现。
  4. **`content_hash` 的原像随之改变**：摘要文本的取值规则变了，`digest` 接线时的分派依据要按本决策的第 4 条重新对齐。

- **触发重估的信号**：① `digest` 接线后，中文摘要与原生摘要在清单里同时出现导致信封重新变重；② 出现真实的「`search --abstract` 因单次信封过大而不可用」；③ 双边样本扩大后，摘要漂移率显著低于或高于目前的量级指示（22%）。
