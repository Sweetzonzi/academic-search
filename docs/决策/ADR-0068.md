# ADR-0068　`works/` 的目录名改成可读

**状态**：accepted（2026-10-18）

> **取代**：[ADR-0033](ADR-0033.md) 里「`works/` 的目录名用 `work_key`、不用可读标题」那一条，以及它下面同名的备选方案段。**其余结论不变**：`bytes/` 与 `works/` 仍是两个正交坐标、`works/` 里每个文件仍是 `bytes/` 的硬链接、`works/` 仍可完整重建、路径仍不落库。
>
> **读旧 ADR 时**：[ADR-0015](ADR-0015.md) / [ADR-0029](ADR-0029.md) / [ADR-0034](ADR-0034.md) / [ADR-0047](ADR-0047.md) / [ADR-0053](ADR-0053.md) 正文里的 `works/<work_key>/` 都是改名前写的，按本条的形状理解；它们各自的结论不受影响（ADR-0047 里「`works/<work_key>/` 不可读」这句只剩 `work_key` 本身成立）。

- **决策**：

  1. **投影目录名**：`works/<年>-<首作者>-<标题>-<work_key>/`，例如
     `works/2026-Rao-SkyJEPA-Learning-Long-Horizon-World-Models-for-7u5b7uczgsxqbhoifdfh/`。

  2. **`work_key` 恒为最后一段，用全 20 位**。它是身份锚点：目录名的前几段都会随元数据变，只有这一段不会。反解规则就是「取最后 20 个字符」，因此不允许省略、不允许截短、不允许放在中间。

  3. **各段的取值与清洗规则**（纯函数，只依赖展示记录）：

     | 段 | 取值 | 清洗 |
     |---|---|---|
     | `<年>` | 展示记录 `published_at` 的前 4 位 | 缺失则**整段省略**（不留 `0000`） |
     | `<首作者>` | 展示记录 `authors[0]` 的**姓氏**（按最后一个空格切；中文名无空格则整段保留） | 截 12 字符；清洗后为空则整段省略 |
     | `<标题>` | 展示记录 `title` | Windows 禁用字符（`<` `>` `:` `"` `/` `\` `\|` `?` `*`）与控制字符换成空格 → 空白折叠成 `-` → 去首尾 `.`/`-` → **按词边界截到 50 字符**（且总名不超过 84，超出继续截，最少留 20）；为空则用 `untitled` |
     | `<work_key>` | `work_key` | 原样，20 位小写 base32 |

     **保留大小写与非 ASCII**：这是给人看的名字，不做 `title_key` 那种小写归一（那是匹配键，见 [ADR-0023](ADR-0023.md)）。

  4. **「展示记录」与检索结果同源**：就是 `aggregate_work` / IFACE-SOURCE §5 用来填 `title` / `authors` / `published_at` 的那条（`published` 角色优先，否则最早见到的一条）。名字里出现的标题必须与 `search` 显示的一致，否则同一篇在两处叫两个名字。

  5. **改名策略：写盘入口对账**。`download` / `read` 在落盘前按当前元数据算出期望名；若 `works/` 下已有该 `work_key` 的目录但名字不同，`os.rename` 过去（投影里全是硬链接，改名不搬字节）。**改名失败不阻断**：继续用现有目录并把它作为 `work_path` 返回——投影可重建，展示层动作不该挡住取件。

  6. **合并后的空壳目录在对账时清掉**：`works/` 下尾段是某个已 `merged_into` 别处的 `work_key` 的目录，删掉（按 `make_writable` 逐个去只读，Windows 上只读文件删不掉）。删除同样不阻断。

  7. **反解只看尾段**：任何「从目录回到 `work_key`」的地方（当前是 `search --in body`，将来是重建与清理）取目录名最后 20 字符并校验 `[a-z2-7]{20}`；**不匹配的目录跳过**，不报错——`works/` 里可能有手工放进去的东西。

  8. **纪律改写**：原纪律是「任何地方不得保存 `works/` 下的路径」。现在改为：**保存没有危害，但可读段会随元数据变**，所以过期的路径可能打不开；需要时用 `download` / `read` 载荷里的 `work_path` 重取（它们永远返回当前目录）。**尾段是身份，前面是渲染**——这一句替代了原来的禁令。

  9. **不变的两件事**：`bytes/` 的目录名仍是哈希（可读性对内容寻址没有意义，改了还会破坏去重与缓存键即路径的性质）；**不分年层**，`works/` 下直接就是作品目录。

- **理由**：

  1. **原来的三条否决理由今天只剩一条硬的**（[ADR-0033](ADR-0033.md) 的备选方案段）：① 元数据变化要改名会让保存的路径失效——已由决策 2 与 8 化解（尾段是身份，改名是 O(1) 的 rename）；③ 从 `work_key` 拼不出完整路径——[ADR-0067](ADR-0067.md) 之后 `download` / `read` 的载荷本来就返回 `work_path`，真正仍在「拼」的只有 `--in body` 的反解，一条正则即可。剩下 ② 清洗规则是一次性工程。
  2. **ADR-0033 自己承认这个代价**：「在资源管理器里直接翻 `works/` 认不出是哪篇」。这条代价在使用中确实顶到了痛处——`works/7u5b7uczgsxqbhoifdfh/` 必须点开文件才知道是哪篇，而「投影是给人看的」正是这一层的存在理由。
  3. **现在换是零成本窗口**：`works/` 下只有 3 个目录，改名是三次 `os.rename`；ADR-0033 也写过这是一条「可逆决策」——投影不承载数据，换命名法只需重建一次。
  4. **收益不止浏览**：`tar` 一个目录打包、复制给同事、将来 `export` 与 Zotero 附件命名都能复用一个 slug 函数；而可读性由「出口提供」在初版里没有出口（`export` 未实现、`search` 也不返回目录）。
  5. **年份打头是安全考虑，不只是审美**：Windows 的保留名（`CON` / `NUL` / `COM1`…）只对**名字主体**生效，`2026-…` 天然撞不上；顺带让资源管理器按年份排序。

- **实测**（本机真库，2026-10-18；名字由 `identity.projection_slug()` 算出，也就是这三个目录现在的名字）：

  | `work_key` | 目录名 | 长度 |
  |---|---|---|
  | `7u5b7uczgsxqbhoifdfh` | `2026-Rao-SkyJEPA-Learning-Long-Horizon-World-Models-for-7u5b7uczgsxqbhoifdfh` | 76 |
  | `jvqsqwlmxogrmckg55n4` | `2026-Zhang-Skytopia-Monocular-Drone-Navigation-with-Action-jvqsqwlmxogrmckg55n4` | 79 |
  | `hxfa4uro3pmplq5bjdsq` | `2026-Xie-SafeDriveVLA-Navigation-Conditioned-World-Model-hxfa4uro3pmplq5bjdsq` | 77 |

  三篇原题 91 / 80 / 106 字符，按 50 截断后总名落在 76–79；路径深度实测仍是 `works/<79>/figures/<58>.pdf` 这一档，离 260 的 Windows 上限还有余量。截断只按词边界，**可能留下虚词**（上表第一行结尾的 `for`）——不值得为它引入停用词表。

  **落地后的验收**（同日）：三个存量目录各跑一次 `download --refresh false`——零请求、9 个投影文件与 `bytes/` 的 inode 不变、`bytes/` 仍只读，目录名即上表；`tests/test_projection.py` 与 `tests/test_identity.py` 守名字、改名、合并空壳与尾段反解。

- **代价**：

  1. **路径不再是 `work_key` 的纯函数**：它变成元数据的渲染，元数据刷新（标题漂移实测约 1/3，[EX-2026-10-14-identity §3](../实验/EX-2026-10-14-身份与去重.md)）会让名字变。这是本次改动的定义，不是缺陷；缓解是尾段身份与载荷返回当前路径。
  2. **`paths.work_dir()` 不再只吃 `work_key`**：名字要先由 `store` 算（SQL 在 store、拼路径在 paths，DEV-CONV §4 的分工不破），删 `works/` 重建时必须查库才能知道目录叫什么。
  3. **每次写盘多一次对账**：读一次 `work_member` + 可能一次 `os.rename`；rename 失败会让目录名与实际元数据不一致（不阻断，只是名字旧）。
  4. **文件系统的边界仍然存在**：大小写不敏感（靠尾段区分，不会冲突）、单段上限 255、路径总长 260（总名控制在 84 以内）。
  5. **第一次改名会打断「已经记住的那个路径」**：三个旧目录会变成新名字，之前抄下 `works/7u5b…/` 的人需要重取。

- **触发重估的信号**：

  1. 出现「保存下来的路径打不开、且尾段也失效」的事故——说明尾段锚点不够，需要稳定别名（索引文件或 `works/by-key/<work_key>` 的一层联接）。
  2. 目录名频繁变动（元数据刷新常改标题）——说明该退回「首建即定、不追改名」。
  3. `--in body` 频繁跳过不匹配的目录——说明 `works/` 有手工目录混入，需要一次目录卫生检查。
