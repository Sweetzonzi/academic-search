# ADR-0065　`lookup` 的 `--refresh` 与 `search` 同义：`true` 先刷再查本地

**状态**：accepted（2026-10-16）

> **范围**：本条只改 `lookup` 的刷新闸门——去掉「本地标识命中就不联网」这条例外，让两条命令的 `--refresh` 三档同义。刷新写哪些列（[DESIGN §4.1](../02-设计说明书.md) 的「刷新（每次做）」清单）、冲突怎么标（[ADR-0064](ADR-0064.md)）、账本怎么记（[ADR-0056](ADR-0056.md)）都不重开。

- **决策**：

  1. **三档统一**，与 [ADR-0043](ADR-0043.md) 决策 2 的表逐字一致，`lookup` 不再有例外：

     | 值 | `lookup` 的行为 |
     |---|---|
     | `true` | **无条件先刷，再查本地**——即使本地已按标识命中 |
     | `auto`（默认） | 本地标识**未命中**才联网；命中即查库返回 |
     | `false` | 绝不联网 |

  2. **`--title` 在 `true` 下降级为只查本地**，并在 `data.degraded.reason` 里说明——标题不是标识，用不了免费的单实体 GET（见理由 3）。**不报错**。
  3. **刷新的对象是标识解析出的那一篇**：`--doi` 走 `/works/doi:<doi>`、`--arxiv` 走 `/works/doi:10.48550/arXiv.<id>`，外加 Crossref / arXiv 的同标识记录；它们与已有记录归组后，引用与安全信号按「刷新（每次做）」清单更新。
  4. **`auto` 不引入 per-work 新鲜度账**：`lookup` 的 `auto` 仍是「缺了才补」，不按 `refreshed_at` 判新鲜——后者需要第二本账，本条不做。

- **理由**：

  1. **`true` 与 `auto` 在 `lookup` 里曾经完全不可分。** 联网闸门是 `work_key is None and refresh != "false"`，两档走同一条路、也都不看新鲜度——**三档实际退化成两档**，而文档一直按三档写。
  2. **「省钱」这一半理由已不成立。** 决策 8 的理由是「命中即返回是省钱的正确入口」，但单实体 GET 免费：实测 `GET /works/doi:10.48550/arXiv.2506.18537` 的响应头 `x-ratelimit-cost-usd = 0`（[EX-2026-10-16-source-contract](../实验/EX-2026-10-16-检索口径与来源校验.md) §16(g)），而本实现记的就是这个头（`sources/http.py` 的 `_record_cost()`），不是自己的估算。命中后再刷一次的价格是 $0。
  3. **剩下那一半理由（「标识确定，外面没有新的」）问错了问题。** 刷新不只用来发现新论文，也用来**更新信号**——引用数、`counts_by_year`、`fwci`、**`is_retracted`**、`oa_status`、`pdf_url`、`type` / venue（预印本可能已正式发表）。一条只以 arXiv 记录进库的论文，其 OpenAlex 孪生记录带来的正是这些；不刷就永远拿不到。
  4. **代价是零、收益是具体的。** `Transformer World Model for Sample Efficient Multi-Agent Reinforcement Learning`（`arXiv:2506.18537`）在库里只有 arXiv 记录、`cited_by_count` 为 `null`；OpenAlex 有同 DOI 的记录 `W6967012949`（被引 0）与载体 source id。改后一次 `lookup --arxiv 2506.18537 --refresh true` 即补齐。`null` 与 `0` 的差别不是洁癖：阈值判据 fail-closed，**一篇真有几百被引却只以 arXiv 记录入库的论文，在这个库里永远查不出来**。
  5. **机制早就在了。** `group.ingest()` 对已存在的 `(source, source_id)` 走 `store.update_record()`（只覆盖非 None 列、空 JSON 不覆盖）＋ `touch_seen()`；缺的只是 `lookup` 那道闸。

- **否决**：

  - **给 `lookup` 的 `auto` 也加按 `work` 的新鲜度判据**：需要第二本账（现在只有按 `spec_hash` 的），而 `lookup` 的默认档本来就只在缺了时才联网，加账换不到可观测的收益。
  - **`--title` 下允许付费刷新**（`filter=title.search:` 或 `search=`）：把 `lookup` 从零成本入口变成有时付费的入口；且标题匹配可能落到另一篇上，刷新出来的不是用户问的那一篇。
  - **`--title` 下 `true` 直接报 `invalid_args`**：能力上的硬缺口没必要升级成错误——降级并如实标注与「余额不足只查本地」同一口径（[ADR-0051](ADR-0051.md)），agent 据此可以改用 `--doi` / `--arxiv`。
  - **保留现状、只把文档改成两档**：那等于承认 `--refresh true` 在一半命令上不生效，而 `true` 的字面意思就是「强制」。

- **代价**：

  1. **`lookup --refresh true` 开始写 run 行**：命中刷新时 `requests` 为 1–2、`cost=0`，账本行数会涨（[ADR-0056](ADR-0056.md) 的记账规则不变）。
  2. **`lookup` 不再是绝对的零成本入口**：`--doi` / `--arxiv` 的 `true` 档现在一定会发请求——虽然免费，但要吃速率间隔（arXiv 3 秒）。
  3. **多一次覆盖的机会**：刷新会按「取到的才写」更新本地记录；冲突仍按 [ADR-0064](ADR-0064.md) 标 `metadata_conflict`、不静默覆盖。
  4. **`--title` 的降级是一个能力缺口**：知道标题却想要最新引用数的用户，必须自己先拿到 DOI 或 arXiv ID。

- **触发重估的信号**：① 单实体 GET 开始计费；② `lookup` 的 `true` 档出现「刷新把本地更准的值覆盖掉」的真实案例；③ 出现按 `work` 判新鲜度的真实需求（那时再评估第二本账）。
