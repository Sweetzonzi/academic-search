# ADR-0051　初版范围再收敛

**状态**：accepted（2026-10-15）

> **范围**：本条改写 [ADR-0031](ADR-0031.md)、[ADR-0032](ADR-0032.md)、[ADR-0044](ADR-0044.md)、[ADR-0046](ADR-0046.md)、[ADR-0047](ADR-0047.md) 中与初版交付面有关的口径；"初版 = M0–M3""不接 Zotero、桥接整体顺延到 M5"的结论不变。
>
> **命令名**：决策 1 里的六条用户命令中，`textify` 由 [ADR-0067](ADR-0067.md) 定为 `download`（原始字节）+ `read`（可读文本）；条数与其余结论不变。

- **决策**：
  1. **命令面 = 六条用户命令 + 三条支撑命令**：用户动作是 `search` / `lookup` / `textify` / `digest` / `read` / `export`；支撑命令是 `sync`（无头采集 + 报告）/ `verify`（字节校验）/ `profile`（画像只读校验）。`bundle` 是 `export` 的别名，不另设命令。
  2. **`export` 初版不实现**：命令形状与 `--format` 取值（`md|zip|bibtex|ris|csljson`）保留在 [IFACE](../03-接口契约.md)，实现与验收顺延到初版之后；初版其余功能都不依赖它。R11 的"导出包能被非 Zotero 用户直接使用"与场景 S7 随之一并顺延。
  3. **质量闸门分两半**：初版**只做纯规则硬排除**——`is_retracted`、`paratext` / `erratum` 等类型、掠夺性期刊黑名单；**A/B/C 分级、分级理由与 `--min-grade` 顺延**（[ADR-0044](ADR-0044.md) 决策 4 的读取端过滤机制保留，但初版没有分级数据可过滤）。
  4. **来源矩阵**：初版 = OpenAlex（主）+ arXiv（预印本）；Crossref 只在 `lookup` 里兜 DOI；**出版社 HTML 与 PDF→MD 回退不在初版**（[EX-2026-10-14-textify §7](../实验/EX-2026-10-14-文本化.md)：两者都未测，清洗逻辑要各写各的）。
  5. **不做预算闸门**：初版不设 `--budget`、不因超限拒绝执行。要求的是**成本可见 + 余额降级**——检索类命令在返回信封里给出实际花费与是否联网（`cost` / `network`）；读到 `x-ratelimit-remaining-usd` 低于阈值时**降级为只查本地**（等价 `--refresh false`）并在输出里标注。
  6. **`dismiss` 初版不产生**：`candidate.dismissed_at` / `dismissed_until` 两列保留，但初版没有任何写入入口，也不做"不再推荐"的过滤；定时报告只列本次入池（按 `run_id`，[ADR-0028](ADR-0028.md)）。
  7. **`--require-citation` 不作为 CLI 参数**：CLI 侧的锚点保证由 `read` 的输出契约承担（必须带 `work_key` + 锚点，[IFACE](../03-接口契约.md)）；"无出处的断言不输出"是 SKILL.md 的硬规则，不是工具开关。

- **理由**：
  1. **命令面原先有两套口径**：REQ §4 与三条 ADR 说"六条"，[IFACE](../03-接口契约.md) 却把 `sync` / `verify` / `profile` 也算在初版。选 IFACE，因为这三条各自有验收判据（无头报告、字节校验、画像可用），把它们移出初版会让 R1 与 R11 落空。
  2. **`export` 在初版没有消费方**：初版的阅读闭环止于 `read`；导出物服务于"交接给同学"，而接收侧（Zotero 或文件库）要到 M5 才成形。
  3. **分级需要真实语料标定**：[ADR-0044](ADR-0044.md) 自己写着"默认阈值 B 是估计值，待真实语料校准"。没有语料先写分级规则，等于用猜测固定一个会变的口径；硬排除是纯安全信号，零标定成本。
  4. **来源矩阵必须与实验结论对齐**：出版社 HTML 的清洗逻辑要各写各的，PDF→MD 完全未测；把它们写进初版等于把两个未验证的坑塞进关键路径。
  5. **额度是硬约束，闸门不是**：无 key 时 OpenAlex 日额度 $0.10，真正的风险是"不知道花了多少"与"余额耗尽后还在发请求"，而不是"某次 run 超了自定上限"。花费上报 + 自动降级直接命中前两点，且不需要新配置面。
  6. **`dismiss` 没有消费方时，加写入口只是增加契约面**：初版推荐的入口是定时报告（只列本次入池）与显式查询，两者都不依赖"不再推荐"过滤。

- **代价**：
  1. **初版没有交接包**：同学只能读 `works/` 下的产物或看 `search` 结果，导出能力要等 `export` 实现。
  2. **初版返回的结果没有质量分级**：只有撤稿标记与黑名单，读者要自己判断"值不值得读"；读取端过滤机制在，数据要等分级落地。
  3. **没有预算硬闸门**：花费只能事后看；若出现失控的批量抓取，只能靠降级与人工干预。
  4. **PDF 回退缺失**：非 arXiv 且无 HTML 的论文在初版没有全文通道，只能等 M5 的 `.zotero-ft-cache` 或后续补 PDF 自解析。

- **触发重估的信号**：① 出现"要一份结果交接给同学"的真实请求；② 检索结果里反复出现该被排除的 venue；③ 出现一次花费失控或额度耗尽的 run；④ 需要读一篇非 arXiv 且无 HTML 的论文。
