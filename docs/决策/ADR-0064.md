# ADR-0064　L1 补桥：桥是声明，不是标识

**状态**：accepted（2026-10-16）

> **范围**：本条定 L1 补桥的一致性校验落在哪一层，以及 `record_ident` 的写入顺序与可变更性。判据（标题 + 年份 + 首作者）与后果（冲突标 `metadata_conflict`、不归组）由 [IFACE-SOURCE §8](../接口/数据源适配.md) 与 [DESIGN §4.1](../02-设计说明书.md) 已定，本条不重开。

- **决策**：

  1. **落点**：校验放在 `group.ingest()` 的 L1 分支——它是唯一的收口。
  2. **桥是「声明」，标识是「事实」**：`record_ident` 增加一列性质（`ident` / `bridge`）。来源自带、可当事实用的标识写 `ident`；`bridges_from_locations()` 的产物写 `bridge`。
  3. **`ident` 不可改，`bridge` 可被接管**：`ident` 沿用先写者占位；`bridge` 在另一条记录带着**它自己的**同值 `ident` 到来时可被接管——比较两侧内容，通过则归组并把该行提升为 `ident`，不通过则把该行移交给新的持有者，并把原持有者标 `metadata_conflict`。
  4. **归组前校验**：任何由桥触发的 L1 归组，在 `merge_works()` 之前先做标题 + 年份 + 首作者校验；不通过则标 `metadata_conflict`、不归组、不动 work。
  5. **顺序不再是判据**：桥可接管之后，两侧谁先入库不再决定 L1 是否合并。

- **理由**：

  1. **先写者永久占位是病根。** `upsert_ident()` 是 `INSERT OR IGNORE`、`(ns, value)` 是主键——桥一旦被当成标识写下去，真正的持有者再也拿不回它（[EX-2026-10-16-source-contract](../实验/EX-2026-10-16-检索口径与来源校验.md) §7 的两条反例）。
  2. **上游记录本身是拼的。** `W2795843265` 的标题是 Zenodo 的 VOLE-Field，日期与首作者却是 World Models 的；`W2626637010` 同理（同 §14(a) 实测）。所以「请求的标识出现在 `locations[]` 里」这条一致性检查**必然放行**——能识别的只有跨来源内容比对。
  3. **「先校验后写」会把 L1 的可靠性交给入库先后。** arXiv 侧记录只带自己的标识、没有反向桥；若对面还没入库，桥被丢弃之后再也补不回来。把桥标成可接管的声明，直接消掉这个与语义无关的偶然量。
  4. **判据与后果规范层已定**，本条只补落点与顺序，不引入新概念。

- **否决**：

  - **先校验后写**（只在对面已在库时写桥）：L1 是否合并取决于两侧谁先入库。
  - **未验证桥单独存一张表**：查询面变成两处 UNION；而「声明可接管」用同一张表加一列就能表达。
  - **把校验放在 `run_lookup()`**：`parse_work()` 从 `locations[]` 取桥，**`search` 路径同样产生桥**，放在 `run_lookup()` 会漏掉搜索路径。
  - **桥别名完全不写**：`ident` 只在来源自带的字段里出现，arXiv 侧没有反向桥，L1 将永远不触发。

- **代价**：

  1. **`upsert_ident()` 的不变量被放宽**：「INSERT OR IGNORE 即终局」此后只对 `ident` 成立，`bridge` 行可被改写。
  2. **`ingest()` 的 L1 分支多一次查询**：接管时要把两侧记录读出来做内容比对。
  3. **存量需要一次性处理**：本次按「删掉上游坏记录、别名归位、拆开 work」订正了 §7 那两条（同 §14(c)），`record` 1610 → 1608。
  4. **复发风险**：同一个 arXiv DOI 再 `lookup` 一次，那两条上游记录会重新入库。桥校验挡得住**错误归组**，挡不住**记录本身进池**；要挡住需要一份「已知坏的上游 id」名单，本条不提供。

- **触发重估的信号**：① 出现记录被接管后仍反复入库的真实案例；② 接管规则在真实数据上把正确的桥判成冲突；③ 需要表达「同名不同篇」之外的冲突类型。
