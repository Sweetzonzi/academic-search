# ADR-0072　作者白名单按 OR 匹配

**状态**：accepted（2026-10-21）。本决策明确 `search --author` 与画像 `authors` 的组内逻辑，并取代 [ADR-0066](ADR-0066.md) 决策 9、13 中首次回溯只按查询名判断的部分。

- **决策**：
  1. 多个作者条件取 OR：`--author A B` 匹配包含 A 或 B 的论文。作者组与主题、日期、载体及引用条件之间仍取 AND；不增加共同署名模式。
  2. OpenAlex 只生成一个 `raw_author_name.search:` 条件，其值为带引号的姓名短语以 ` OR ` 连接。arXiv 使用 `(au:"A" OR au:"B")`；单作者维持单条件。
  3. 本地保留大小写不敏感的子串匹配，但在每个作者姓名内独立判断，不把两个人的姓名拼成一个字符串来命中查询。各来源的姓名归一化能力不同，本决策只统一组内 OR，不承诺同名消歧。
  4. 非空作者条件的 `canonical_spec` 增加 `author_match: "any"`，避免复用多作者 AND 的采集新鲜度。`sync` 的首次回溯完成判据同时匹配查询名和当前 `spec_hash`；同名查询的条件或来源改变时重新按 `since_years` 回溯。已有语料保留，不改数据库结构。
- **理由**：作者白名单用于跟踪一组研究者；共同署名会漏掉这些研究者各自发表的论文。
- **依据**：[OpenAlex 官方搜索说明](https://help.openalex.org/api/searching/) 要求在同一个作者搜索值中用 OR 组合短语；真实请求核验见 [EX-2026-10-21-search-semantics §2](../实验/EX-2026-10-21-检索语义.md)。arXiv 的作者表达式以离线构造测试验证，未新增真网实测。
- **代价**：带作者条件的存量查询需要重新采集一次；同姓、姓名变体与来源显示名差异仍可能导致误命中或漏匹配。
