# ADR-0057　检索载荷只带可溯源最小集，摘要与正文不进载荷

**状态**：partially superseded by [ADR-0058](ADR-0058.md)（2026-10-16 接受，2026-10-16 收窄）

> **范围**：本条只定 `search` / `lookup` 返回的**结果条目**（[IFACE-PAYLOAD §2](../接口/输出载荷.md)）装什么、不装什么，并回答 [R12](../01-需求说明.md)「清单每条带来源、年份、入库状态与中文摘要」里摘要那一项怎么落地。不改命令面、不新增参数，关闭 [OPEN](../06-待决事项.md) 的 `Q23`。
>
> **被收窄的部分**：决策 2 里「摘要一律不进检索载荷」这一半，连同本条对 `lookup` 的适用性，已由 [ADR-0058](ADR-0058.md) 接管——`lookup` 条目带完整摘要、`search` 新增 `--abstract` 开关。**本条其余部分继续有效**：决策 1 的六项可溯源最小集下限与它的超集保留规则、决策 2 里「正文不进载荷」、决策 3 不做分页与计数。改动依据见 [ADR-0058](ADR-0058.md) 理由 2、3。

- **决策**：

  1. **清单的契约内容是可溯源最小集**：`work_key` + `title` + `published_at` +（`doi` 或 `arxiv_id` 等标识）+ `sources[]` + `first_seen` + `dup_suspect`。前六项是 agent 引用一篇论文的下限（硬规则「无出处的断言不输出」）；`dup_suspect` 是另一条硬规则「疑似同一篇但未合并、引用时必须说明」的唯一依据，少了它 agent 无法如实回答。实现当前返回的是它的**超集**（另有 `authors` / `venue` / `language` / `type` / `oa_status` / `pdf_url` / `updated_at` / `cited_by_count` / `last_seen` / `openalex_id` / `is_retracted`），**超集保留**；将来要瘦身在超集里减，不扩这个下限。

  2. **摘要与正文一律不进检索载荷**（**摘要这一半已交由 [ADR-0058](ADR-0058.md)，当前以该条为准**）：`abstract` 是 `record` 的书目列（[IFACE-DATA](../接口/数据模型.md)），只作 FTS5 的索引源与 `content_hash` 的原像；中文摘要走 `digest list` / `digest put`，文本落 `bytes/`（[ADR-0045](ADR-0045.md)），正文走 `textify` + `read`。清单里将来要提示「有摘要」，只放一个布尔或 `content_hash` 指针，**不放文本**。

  3. **不做分页与计数模式**：全库清单的条目数由 `--limit` 兜住（默认 20）。全库继续变大不改载荷形状，也不加 `--offset` / 游标 / `--count-only`。

- **理由**：

  1. **摘要服务的是另一个动作**：清单回答「有哪些、哪篇值得点开」，摘要回答「这篇讲了什么」。[R12](../01-需求说明.md) 的「带中文摘要」是为当写作素材，那该由导出产物与文本化通道承担，不该让每一屏清单都背着最重的一列。
  2. **体积**：条目已含变长的 `sources[]` 与 `authors[]`，摘要是其中最重的一列（几百到几千字符）；全库上万条时会让信封涨一个数量级，而 agent 多数时候并不读它——真读就直接 `read` / `textify`。
  3. **不把派生内容的失效带进检索台账**：中文摘要的键是 `content_hash` 等六元组（[ADR-0045](ADR-0045.md)、[ADR-0054](ADR-0054.md)），键一变摘要就得重算；放进载荷等于让检索结果的形状跟着派生内容抖动。
  4. **同一检索式的载荷形状不该随参数变**：`--limit` 已经不在 `spec_hash` 里（[OPEN](../06-待决事项.md) 的 `Q22`），再加「带不带摘要」这类开关，会让「同一检索式命中同一本账本」更难说清。
  5. **`--limit` 已是够用的护栏**：它按合并后的 work 数计，默认 20；本地库规模还小，一个 `--limit 200` 就能全取回。为「将来可能很大」现在就造分页，是把复杂度押在还没出现的需求上。

- **代价**：

  1. **R12 / S9 的「中文摘要」在清单里暂时落空**：清单只给来源与年份，要带摘要的写作素材得等 `digest` 接线后走导出通道——本条不解决它，只把它挡在载荷之外。
  2. **「入库状态」还没有字段**：R12 要的这项今天不在条目里；真要做应当在载荷里加一个枚举（如 `candidate` / `promoted` / `dismissed`），而不是拼接文本。
  3. **没有分页意味着大库的单次信封可能不可用**：有人为了「看全」把 `--limit` 拉大时信封会很大。这是有意接受的风险。

- **触发重估的信号**：① 出现一次真实的「列清单」因为单次信封过大而不可用或超时；② `digest` 接线后「摘要进清单」被证明是常规动作而非偶发需求；③ R12 的「入库状态」被排进里程碑。
