# ADR-0055　运行留档、安装形态与运行环境

**状态**：accepted（2026-10-15）

- **决策**：
  1. **一次 run 一套留档**：`data/runs/<run_id>/` 装 `run.json`、`report.md` 与 `responses/`（原始响应），另维护 `data/latest-report.md` 副本供调度器一步读取。取消 `data/reports/<date>.md` 与 `data/snapshots/` 两个命名。
  2. **快照范围**：只留「产生被采纳记录的页」与「失败页」，空页与全被去重拦掉的页不留；初版**不主动删**（清理规则留给将来显式的 GC 命令）。
  3. **安装形态**：代码与数据都在仓库内（clone + `.gitignore`）；**每个宿主的 skill 目录只放薄 bundle**（`SKILL.md` + `references/` + 一行 launcher），代码与数据只有一份。launcher 按 `--root` → `ACADEMIC_SEARCH_ROOT` → 同目录 `root.txt` 的顺序解析仓库根。
  4. **备份纪律写进文档**：因为数据在仓库内，**重新 clone 或 `git clean -xdf` 会丢 `config/`**（其中 `profile.toml` 是全项目唯一不可重建的用户数据）。README、[使用/配置](../使用/配置.md)、[使用/快速开始](../使用/快速开始.md) 三处都要写这条提示。
  5. **`vendor/` 装运行时依赖**：便携 pandoc 放 `vendor/pandoc/`；`tools/` 保持「维护脚本」的单一职责（[AGENTS.md](../../AGENTS.md) 第 8 节）。
  6. **增量窗口**：统一「回看 N 天」，`N` = `config/search.toml` 的 `[sync] lookback_days`（默认 30）；**首次运行**（无水位）改用画像里的 `since_years`。窗口同时写进 `run.window_from/window_to` 与报告头部。
  7. **并发**：写事务用 `BEGIN IMMEDIATE`，命令启动时取锁，拿不到立即报错退出（`error.code=busy`、退出码 1），**不排队**；只读命令不受影响。
  8. **时区**：库里时刻一律 UTC（ISO-8601 带 `Z`），日期型字段存 `YYYY-MM-DD` 原值不换算；面向人的报告按本地时区渲染，并在报告头部标明时区。
  9. **`verify` 抽样**：`--sample N`（默认 20，`0` = 全量），发现不匹配即退出码 1 并列出文件，不做自动修复。

- **理由**：
  1. **三样产物同生命周期**：`run.json`（账本导出）、`report.md`（人读面）、`responses/`（证据）都属于「这一次 run」，分三个目录只会让清理与备份需要同步多处。
  2. **快照不该混进 `bytes/`**：`bytes/` 的语义是「内容实体 + 只读 + 引用计数 GC + verify 抽样」，而快照只被只增不删的 `run` 引用（引用计数永不归零）、被改写没有安全含义、可清理。四条里有三条对不上——判据同 [AGENTS.md](../../AGENTS.md) 第 8 节那句「能不能烂」。
  3. **宿主目录注定要装多份，但只该是薄的那一层**：不同宿主的 skill 扫描根不同，SKILL.md 与 references 必须各装一份；代码与缓存若也各存一份，升级与数据一致都会变成噩梦。
  4. **数据放仓库内是明确的取舍**：路径直观、备份就是复制仓库；代价用「备份纪律写进三处文档」来对冲，而不是靠用户自己想到。
  5. **`N` 是初版唯一的省钱参数**：没有它，每次 sync 都按画像的年份窗翻页，「增量」名不副实；首次运行必须有回溯，否则新画像第一跑只有 30 天语料。
  6. **无头场景最怕排队**：定时任务撞锁时「等 30 秒」会变成隐藏状态；立即失败会留下 `run.status=failed` 与退出码 1，调度器看得见。
  7. **时区口径影响可复现**：两台机器跑同一批查询应得到同样的库；而「新发表」的日期边界对人来说应当是本地日期——两者分开，各取所需。

- **代价**：
  1. **数据与代码同处一个可被 `git clean -xdf` 清掉的位置**：靠三处文档提示与用户备份纪律兜住，没有技术强制。
  2. **launcher 多一层解析**：换机器要重写 `root.txt` 或设环境变量；每加一个宿主就多装一份薄 bundle。
  3. **`vendor/` 让仓库变大**（pandoc 约 200 MB 落地）：换来的是「装好就能跑」。
  4. **不排队意味着手工与定时撞车时有一方失败**：需要 SKILL.md 明确「失败就重试一次，不要循环重试」。
  5. **快照不主动删**：`data/runs/` 会持续增长（只留采纳页与失败页，量级可控），清理要等显式 GC 命令。

- **触发重估的信号**：① `data/runs/` 增长速度超出预期；② 真实出现「多宿主共享数据」的需求（例如两个宿主要同时写）；③ 撞锁在真实使用中频繁发生。
