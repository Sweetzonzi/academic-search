# ADR-0073　本地结果分页

**状态**：accepted（2026-10-21）。取代 [ADR-0057](ADR-0057.md) 决策 3 中禁止本地分页与 `--offset` 的部分。载荷最小集与正文通道继续按该条执行；摘要按 [ADR-0058](ADR-0058.md)。实现与验收登记在 [PLAN §2](../04-里程碑与计划.md)。

- **决策**：
  1. `search` 增加 `--offset N`，默认 `0`，表示跳过筛选、去重与排序后的前 N 个 work，再按 `--limit` 返回。适用于有检索式的结果与无检索式的全库清单；`lookup` 与 `sync` 不增加此参数。
  2. `offset` 与 `limit` 是非负整数；负数返回 `invalid_args`。`limit=0` 或偏移超过已匹配结果时返回空列表。完整顺序是「候选预算 → 过滤与 work 聚合 → 排序 → offset / limit 切片」，不能先分页再过滤。
  3. 日期或被引排序保持既有主序与空值排后规则；主排序值相同时按 `work_key` 升序确定顺序。同一数据状态下，相同查询的连续分段不重复、不遗漏；数据库变化可能改变页边界，不提供跨命令快照。
  4. `offset` 是展示参数，不进入 `spec_hash`，不改变远端取数深度或刷新策略；纯粹换展示偏移不能成为再次联网的理由。远端取数继续按 [ADR-0062](ADR-0062.md)，自动继续采集另行决策。
  5. 保留现有 `items[]` 与 `counts.local` 形状：`matched` 是 offset / limit 之前的匹配数，`returned` 是本次实际返回数。预算截断仍按 [ADR-0070](ADR-0070.md) 标记，计数不能冒充全库总数；只取完候选预算不能宣告全库耗尽。本次不增加 `--count-only` 模式。
- **理由**：
  1. `limit` 限制一次输出量，不能表达继续阅读后面的结果；不断增大它会重复输出前面的条目。分页允许 agent 按预算逐批阅读。
  2. 载荷大小应由每批的 `limit` 控制；分页符合小载荷目标，条目结构不因偏移变化。
  3. 查询身份回答取数条件与新鲜度，展示偏移回答返回哪一段，既有 [ADR-0062](ADR-0062.md) 已允许二者独立。
  4. 「库小，调大 limit 即可」是阶段性实现取舍，不能作为长期禁止分页的依据。语料规模与候选截断的实测见 [ADR-0070](ADR-0070.md)。
- **代价**：每批仍可能重新过滤、聚合和排序候选，分页只减少输出量，不承诺减少数据库计算量；数据库变化时调用方应按 `work_key` 去重。游标、跨命令快照与远端续取需要各自的需求和设计依据。
