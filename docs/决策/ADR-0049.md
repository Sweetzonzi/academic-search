# ADR-0049　检索式来源分工

**状态**：accepted（2026-10-15）

> **范围**：本条决策 4 与触发信号里提到的 `--topic` 已由 [ADR-0050](ADR-0050.md) 删除——"按方向看已入池结果"改为用 `search` 查库（关键词 / venue / 年份）。

- **决策**：
  1. **`search` 只接受当场给的检索式**（`--all-of` / `--any-of` / `--venue` / `--author` / `--since-years`）；**不再接受 `--query <具名查询>`**。它的产物是**结果列表**。
  2. **`sync` 独占具名查询**：`--query` 可给零到多条，缺省跑画像里全部启用的查询；产物是 `run.json` + `reports/<date>.md`，stdout 只给 run 摘要、**不返回结果清单**。
  3. 两条命令仍**共用同一条流水线、同一本 run 账本**；`--refresh auto` 的判据按 `spec_hash` 各记各的时间（[ADR-0043](ADR-0043.md)）。
  4. 交互式看某个方向的已入池结果，初版走"`sync` 采集 → 读报告"与关键词查池；`--topic` 及其筛池问题已由 [ADR-0050](ADR-0050.md) 删除。
- **理由**：
  1. **一个来源对应一个产物**：具名查询是"画像策展的方向"，产物应当是**可归档、可给调度器读的报告**；临时检索是"当下的问题"，产物应当是**给 agent 回答的结果列表**。让 `search` 也能跑具名查询，就会出现"用策展检索式跑出的一批结果没有报告"这种错配。
  2. **输出契约因此可预测**：`search` → 结果；`sync` → 报告。SKILL.md 的决策树可以简化成"问题用 `search`，方向用 `sync`"。
  3. **能力没有丢**：临时变定期的桥还在——把临时检索写进画像，它就变成 `sync` 的查询（[ADR-0041](ADR-0041.md) 决策 4）；`sync` 仍受 `spec_hash` 账本保护，重跑刚跑过的查询会跳过刷新并注明。
- **代价**：
  1. 交互式"看我这个方向最近有什么"要经过 `sync` + 读报告两步，不再是单条 `search`。
  2. 按方向列出**累积**的池子没有直接入口，替代是当场给检索式查库（[ADR-0050](ADR-0050.md)）。
- **触发重估的信号**：若实际使用中"按方向查池"成为高频动作，考虑给 `--topic` 加筛池语义，或恢复一条只读的池子入口。
