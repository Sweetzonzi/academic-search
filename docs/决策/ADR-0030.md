# ADR-0030　入库确认按动作分级

**状态**：accepted（2026-10-15）

> **取代**：本条中"候选池状态集合保留 `new` / `promoted` / `parked` / `hidden`"的部分由 [ADR-0044](ADR-0044.md) 取代——候选池没有状态列；"确认按动作分级"本身不变。

- **决策**：把「是否需要人工确认」从**全局开关**改为**按动作分级**——`promote`（写入 Zotero）默认需人工确认；入库推荐（LLM 初筛）可配置为需确认或自动；翻译与文本化默认全自动。候选池状态集合保留 `new` / `promoted` / `parked` / `hidden`。
- **理由**：① 三类动作的风险不对称——往用户的学术资产库里写东西影响面大（虽可按 `run_id` 回滚），翻译只是可重建的派生数据；② 一根总闸会让低风险动作也被卡住，或让高风险动作悄悄通过。
- **否决**：**单一确认开关**——实现最简，但翻译这类零风险动作也要人工点一次；**全自动入库**——状态退化为 `new → promoted`，与 [REQ 非目标 6](../01-需求说明.md) 冲突。
- **代价**：策略要按动作存三份配置，且需要一条默认值（写 Zotero 需确认、其余自动）。
