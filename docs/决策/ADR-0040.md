# ADR-0040　配置集中在 `config/`，一份配置一个固定文件名；画像只有一份

**状态**：accepted（2026-10-15）

> **范围**：本条提到的 `topic` tag 已由 [ADR-0050](ADR-0050.md) 删除；"查询名必须唯一"的结论不变。

- **决策**：
  1. **所有可配置内容集中在 `config/`**（与 `data/` 同级），一份配置一个 TOML，**文件名固定**：
     - `config/profile.toml` —— 领域画像（**只有一份**）；
     - `config/sources.toml` —— 启用的检索数据库与各自开关；
     - 将来新增的配置照此办理：一文件一职责、文件名固定。
  2. **CLI 只读它认识的那几个固定文件名，目录里的其它文件一律忽略**——用户复制、改名、留多份备份都不影响工具行为。
  3. **画像是唯一的**：没有 `--profile`，「切换画像」这件事不存在。要跑子集就用 `--query <名字>` 收窄到单条（由 `sync` 执行，见 [ADR-0049](ADR-0049.md)）。
  4. **密钥不进配置文件**：`config/` 里只放开关与非敏感参数，API key 走环境变量。

- **理由**：
  1. **一个只有一个文件的目录不值得存在**：若 `profiles/` 只装一份画像，它就不该是一个目录；而一旦这个目录要存在，它就该承担「所有配置」，否则每加一类配置就要再开一个顶层目录。
  2. **固定文件名消掉一整类状态**：没有 `--profile`、没有「当前用哪个」、没有跨画像查重、也没有「画像名进不进 tag」的取舍。查询名仍是唯一的寻址单位（[ADR-0027](ADR-0027.md)），但约束退化成「同一份画像内不重名」。
  3. **备份与分享退化成文件操作**：复制 `profile.toml` 改名就是备份；发给同学的那份由他自己改回 `profile.toml` 放进自己的 `config/`。**工具不参与这件事，也就不需要为它设计任何东西。**
  4. **密钥不进配置**是「配置可以随便备份、随便发」的前提；否则 `config/` 立刻变成一个要小心对待的秘密文件。

- **代价**：
  1. **没有「整批切换」**：项目期的临时查询组只能逐条写 `expires` 或手动删。[ADR-0027](ADR-0027.md) 的临时专题机制已覆盖大半。
  2. 用户想同时保留「工作版」与「个人版」时得自己管两份文件；工具只认 `profile.toml`。

- **备选方案（当前不采用）**：`profiles/<自由名>.toml` 多画像 + `--profile <名>` 选择，把画像名当「批次」。
  - **好处**：项目期的临时查询组可以整份删掉；方便把一组查询单独发给同学。
  - **不采用的理由**：它引入了「选择哪一个」这个隐藏状态（换机器、换会话就丢），并把「查询名唯一」的约束从文件内扩散到全局；而这两样换来的能力——临时专题、分享一组查询——用 `expires` 和复制文件都能达成，而**复制文件是用户本来就会的动作**。
  - **仍可复用的一条结论**：查询名必须唯一（`topic` tag 就是它）；只是约束范围从全局退回到「同一份画像内」。
