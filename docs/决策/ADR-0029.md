# ADR-0029　全文类产物的字节进 `bytes/`，sidecar 只存指针

**状态**：accepted（2026-10-15）

- **决策**：**全文类产物的字节一律进 `bytes/`（内容寻址），sidecar 只存 sha256 指针与元数据**——包括抽取出的纯文本与转换后的 `paper.md`。sidecar 的 `derived_content` **只保留短派生文本**（标题/摘要/关键词的翻译与分层摘要）的 `text` 列。
- **理由**：① 全文是大块字节，进 DB 会让侧车膨胀、备份与迁移变贵；② 与 [ADR-0011](ADR-0011.md) 的「文件字节按 sha256 内容寻址、相同字节只存一份」一致——预印本与正式版原文相同时天然只存一份；③ 人读路径仍在 `works/<work_key>/` 投影上，可完整重建。
- **否决**：**全文进 sidecar 的 `text` 列**——查询统一，但 DB 随全文膨胀且备份代价不可控；**全文一律进文件、sidecar 连指针都不存**——无法按内容哈希复用，也失去「这份产物来自哪条记录」的溯源。
- **代价**：① SQLite 的 FTS5 **无法直接索引正文**，正文检索须另走一层（最终取文件扫描，见 [ADR-0036](ADR-0036.md)）；v1 的 FTS5 只覆盖标题、摘要与翻译；② 全文类 kind 的 `derived_content.text` 允许为空，取全文要先经 `artifact` / `text_cache` 拿 sha256 再读 `bytes/`。
