# ADR-0008　权威归属：Zotero 管「我的库」，sidecar 管「领域语料 + 派生数据」

**状态**：accepted（2026-10-14）

- **决策**：两个语料库、两种权威，而不是某一方通吃；**作品身份由 sidecar 自己持有**（`record_uid` 确定性派生、`work_key` = 首领记录的 `record_uid`，第三方 ID 只作 `record_ident` 别名，见 ADR-0003）。`promote` 是**单向复制 + provenance**，不是双向同步。
- **理由**：① Zotero 的价值（人工策展、同步/导出/引用格式化、阅读器与标注）只对人工策展的小库成立；② 机器规模语料塞进 Zotero 会污染库、拖慢 UI，又提供不了图查询；③ 把"我的库"搬进 sidecar 等于放弃 Zotero 的阅读器/标注/Word 插件，并要重建条目模型与导出——正是 R8 要避免的；④ 两库各自权威、单向流动，就不存在"同一份数据两处可改"。
- **否决**：**sidecar 作为唯一权威、Zotero 只当镜像/导出端**——写入 Zotero 的通道约束（10+、HTTP、无跨库事务）一条都不会减少，换权威不解决写入问题，只额外背上镜像维护、附件管理、引用格式化与同步；**双向同步**——冲突不可判定，必然静默丢数据。
- **代价**：需维护 `dateModified`/`version` 快照与 stale 检测；命令上要显式区分 `--scope local` 与 `--scope corpus`。
- **翻转条件（诚实记录）**：如果用户**实际上从不打开 Zotero**、只把它当存档/导出端，则 Zotero 权威的好处不成立而写入约束仍在，此时"以 sidecar 为主、Zotero 仅作导出"更优。见 `OPEN §1`。
