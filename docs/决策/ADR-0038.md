# ADR-0038　调度不进工具：工具只保证 `sync` 无头、幂等、报告结构化

**状态**：partially superseded by [ADR-0066](ADR-0066.md)（2026-10-16 接受）；被取代的是代价 2 里「幂等性靠水位与 `record` 去重」的措辞——现在说「靠 `spec_hash` 账本与 `record` 去重」，结论不变。

- **决策**：工具**不内置定时器、不读也不存频率配置**。`sync` 只承诺三件事——无头可跑、幂等、产出结构化报告（`run.json` + markdown）；频率与触发方式由用户在自己的调度器里设置（DSH schedule / Windows 任务计划 / cron 均可）。
  - 领域画像**不含调度字段**，避免"配置里写了一份、实际调度器里是另一份"的漂移。
  - 文档只给推荐起点（每周一次），它不是配置项。

- **理由**：
  1. **"任何调度器都能驱动"本来就是验收判据**（[REQ §5](../01-需求说明.md)）；自己再做一层调度只会制造两套真相。
  2. **额度约束是动态的**：OpenAlex 无 key 时每日 $0.10，有 key 时约 $1（[RUN-M0](../运维/M0-额度与增量实测.md)），合适的频率随额度、随研究节奏变化，写死在工具里必然要改。
  3. **避免常驻进程**：与"不做常驻服务"的非目标一致，少一个需要守护、需要排障的部件。

- **代价**：
  1. 用户要自己配一次调度器——这是 [R11](../01-需求说明.md)"三步可用"之外的一步，快速开始文档必须写清楚。
  2. 工具不提供频率语义；**幂等性靠水位与 `record` 去重**，不靠调度。

- **备选方案（当前不采用）**：在画像里加 `schedule` 字段并由工具注册到系统调度器。不采用的理由见理由 1——那等于用配置文件再描述一遍调度器已经描述的东西。
