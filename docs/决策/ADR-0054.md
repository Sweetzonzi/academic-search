# ADR-0054　派生文本的通道、键与译名表

**状态**：accepted（2026-10-15）

> **取代**：[ADR-0037](ADR-0037.md) 里 `digest put` 的命令行草形（逐条 `--work/--kind/--lang/--model/--prompt`）由本条决策 1 取代——改为 stdin 收 JSON 数组的批量形状；「CLI 不调 LLM」与「两段式通道」的结论不变。

- **决策**：
  1. **I/O 形状**：`digest list --limit N [--kind K] [--lang L]` 输出统一信封，`data.items[]` 含 `work_key`、`kind`、`lang`、`content_hash`、`source_text`；`digest put` **从 stdin 读 JSON 数组**（`--file` 亦可）：每项含 `work_key` / `kind` / `lang` / `model_id` / `prompt_version` / `text`。一次可提交多条，长文本不必过命令行转义。
  2. **kind 兼表粒度**：`title` / `abstract` / `summary.oneline` / `summary.points` / `summary.mrl`（方法-结果-局限）；`lang` 用 BCP-47（默认 `zh`）。粒度进缓存键，不加列。
  3. **译名表独立成文件**：新增 `config/terms.toml`（`[[term]]` 下 `en` / `zh`），`terms_version` = 该文件内容的 `sha256` 前 8 位；缓存键里的 `glossary_version` **更名为 `terms_version`**。`digest list` 带出当前版本，`put` 原样回传。
  4. **`content_hash` 细则写死**：剥 MathML/JATS/HTML 标签集合 → NFKC → 连字符与引号统一 → 折叠空白 → 按 `kind` 的大小写策略；细则与 **3 个测试向量**（同一段文本的不同写法必须得到同一 hash）放 [IFACE-SOURCE](../接口/数据源适配.md)。
  5. **`derived_content` 不装文本**：只留缓存键与 `sha256` 指针，文本落 `bytes/`（与 [ADR-0045](ADR-0045.md) 一致；[DESIGN §4.2.4](../02-设计说明书.md) 里带 `text` 列的旧草图随之修正）。

- **理由**：
  1. **批量形状是上下文预算的直接结果**：一次交互通常要处理一批条目，逐条调用会把「命令拼装」变成 agent 的主要工作，而且长文本经命令行参数极易踩转义与换行。
  2. **粒度必须进键**：缓存键里没有粒度列，若 `kind` 不表粒度，「一句话摘要」与「方法-结果-局限」会互相覆盖——这是最容易犯且最难发现的一类缓存错误。
  3. **译名表要有家**：`glossary_version` 出现在缓存键里却没有任何文件与版本规则，是个填不出来的键；同时它与 [术语表](../术语表.md)（项目术语）**同名不同物**，必须改名消歧。
  4. **hash 细则决定命中率**：只写原则等于把命中率交给实现者的手感，而「第二次请求零成本」是初版验收判据之一。

- **代价**：
  1. **调用方要拼 JSON**：比逐条参数多一层构造，SKILL.md 里要给一个最小示例。
  2. **`terms.toml` 是又一份配置**：改一个词会让相关译文缓存整批失效（这是正确行为，但要有心理预期）；空表也必须有默认版本号。
  3. **`hash_version` 不进键**：算法将来若变更，旧行不会报错，只会变成不可达的垃圾（需要 GC 而不是正确性），初版接受。

- **触发重估的信号**：① 批量 `put` 的单次体积经常撞上命令行或管道上限；② 译名表在真实使用中膨胀到需要分类或分域；③ 摘要粒度出现新的固定形态。
