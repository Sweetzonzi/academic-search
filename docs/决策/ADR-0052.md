# ADR-0052　数据源适配层

**状态**：accepted（2026-10-15）

- **决策**：
  1. **适配层独立成契约**：新增 [IFACE-SOURCE](../接口/数据源适配.md)，逐源给出「字段路径 → `record` 列」映射、解析步骤、取不到时的语义（NULL 还是「未知」）、源能力矩阵（哪源有哪列、哪源支持哪类查询参数）。[DESIGN §4.1](../02-设计说明书.md) 只留一句「有适配层」+ 链接。
  2. **日期列重塑**：`record.publication_date` 更名为 **`published_at`**（该源给出的主日期），新增 **`updated_at`**（该源记录的最近更新：arXiv `updated`、OpenAlex 刷新时间）。日期仍是 `YYYY-MM-DD` 原值、不做时区换算。
  3. **规范类型枚举六值**：`article` / `preprint` / `chapter` / `thesis` / `paratext` / `other`；映射表逐源给出。**硬排除 = `paratext` ∪ 黑名单**。
  4. **黑名单进配置**：`config/search.toml` 的 `[quality] venue_blacklist = [...]`（**文件缺失或留空 = 空列表**，示例见[配置目录](../使用/配置.md)）；规则本身写进 [IFACE-SOURCE](../接口/数据源适配.md)。
  5. **work 级聚合规则逐列写死**（多源记录合成一条对外结果）：见 [IFACE-SOURCE](../接口/数据源适配.md) 的聚合表；安全信号用**或运算**（`is_retracted` 任一为真即真），引用信号取最大，展示元数据取 `role=published` 的记录、否则取最早。
  6. **补桥时机**：每次 run 收尾时批量补一次 L1 桥——把本次新记录里「有 DOI 或 arXiv ID 但缺对方标识」的集中成一次 `filter=doi:…|…`（≤100 条/次），顺带取回 `locations[]` 与引用信号。
  7. **源文本规范化随源走**：摘要还原（OpenAlex 倒排索引）、剥 JATS/MathML（Crossref）、纯文本直取（arXiv）写进 [IFACE-SOURCE](../接口/数据源适配.md)，`content_hash` 的规范化细则与 3 个测试向量同处定义。
  8. **源标识归一化补一条**：arXiv 的 `source_id` **去掉版本后缀**（`1501.00001v2` → `1501.00001`），使 v1/v2 是同一条记录。

- **理由**：
  1. **格式差异是表层的，语义差异才是真的**：同一列在不同源里根本不是同一种东西——OpenAlex `publication_date` 是正式版日期（实测 arXiv 2009 → 2012），arXiv 有 `published`/`updated` 两个；`type` 三套枚举互不兼容；`venue` 在 arXiv 侧不存在。映射表不写死，实现者只能各拍一遍。
  2. **`record` 的列集是 OpenAlex 中心的**（`fwci`、`oa_status`…）。这可以接受，但必须显式写成源能力矩阵，否则会有人拿 Crossref 记录去填 `fwci`。
  3. **硬排除跨源判，需要先有内部枚举**：paratext/editorial/erratum 是 OpenAlex 的说法，arXiv 与 Crossref 各有一套；没有规范枚举，硬排除只能写在某一个源的解析里。
  4. **补桥决定「预印本↔正式版」能不能自动合并**：L0 对这对记录天然无效（不共享强标识），L2 有约 4% 假阳性且初版不提供人工确认入口（[ADR-0047](ADR-0047.md)），所以只能靠 L1；而 L1 需要主动去取对面的字段。
  5. **写死源文本规范化是缓存命中率的前提**：同一段摘要因换行或引号写法不同就重算，会让「第二次请求零成本」这条验收失效。

- **代价**：
  1. **多一份契约要维护**：源字段会变（官方改字段名或废弃字段），改动要同步 IFACE-SOURCE 与解析实现。
  2. **列更名是破坏性变更**：`publication_date` → `published_at` 会改到 SKILL.md 示例、报告模板与任何已写下的查询；好在 schema 尚未实现，此时改零迁移成本。
  3. **批量补桥把请求集中到 run 收尾**：单次 run 末尾多一次（或几次）批量请求，失败时该次 run 的合并质量下降（记录为 `counts.failures`，不阻断主链路）。
  4. **Crossref 的 `is-referenced-by-count` 不写入 `cited_by_count`**：口径不同，混写会让 work 级「取最大」失去意义；代价是 Crossref-only 的论文没有引用信号可用。

- **触发重估的信号**：① 某个源改了字段或新增了有用的信号；② 补桥在真实语料上长期命中率低（说明 L1 通道不可靠，需要重新评估 S2 通道）；③ 规范 type 枚举出现无法归类的取值。
