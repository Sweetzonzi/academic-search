# ADR-0067　全文入口按产物拆分

**状态**：accepted（2026-10-18）

> **取代**：[ADR-0035](ADR-0035.md) 决策 2 里以 `textify` 作为「要这篇」入口的写法，与 [ADR-0053](ADR-0053.md) 决策 2 的「`read` 不隐式写盘」。两条的其余结论不变——`artifact` 有行即证据、不设 `kept` 状态；全文不进信封、`read` 仍是定位器。

> **物化细则**：[ADR-0074](ADR-0074.md) 明确决策 2/5 的优先级、转换清单与缺损提示；默认不追远端版本，显式 `read --refresh true` 更新原件后转换，本地原件或转换器变化使派生缓存失效。

- **决策**：

  1. **命令面按产物拆成两条**：`download` 取**原始字节**（arXiv LaTeX 源码 / arXiv HTML / PDF），`read` 取**可读文本**（`paper.md` 定位器）。`textify` 不再是命令；转换流水线以模块与内部步骤的形式保留（`textify.py`、`converter_version`）。初版六条用户命令因此是 `search` / `lookup` / `download` / `digest` / `read` / `export`。

  2. **`read` 懒物化**：有 `paper_md` 产物就直接返回定位器；没有时本地能重投影（`bytes/` 里的实体还在）就重投影、不联网；再不行才取件（LaTeX 源码 → HTML 回退）并转换。**已存在但版本旧时不更新**——更新是 `download` 的动作，由调用方决定。`--refresh false` 时绝不联网，最终取不到报 `projection_missing`。

  3. **版本分两处记**：`record.source_version` 记远端最新版本（arXiv 的 `vN`），由 `search` / `sync` / `lookup` 在刷新元数据时写入；它为空时 `download` 也补一次（一次 feed 请求，读到就落回 `record`），否则按决策 4 每次取件都要整份重下。`artifact.source_version` 记这份字节的版本，由 `download` 写入：`auto` 钉住该版本取件，`true` 取最新、此列仍是取件时 `record` 的值（宁可低估，不误报「已是最新」）。**本地版本不落 `record`**：删掉 `bytes/` 之后 `record` 会断言一件不存在的事实；同一事实两处存正是 [ADR-0066](ADR-0066.md) 决策 12 删掉 `last_success_watermark` 的理由。

  4. **缓存判据是版本相等**：`download --refresh auto` 只在「该 kind 没有 artifact」或「两侧版本不等」时取件，相等即复用、零请求。**任一侧为 NULL 视为不等**。

  5. **`--refresh` 三档在两条命令上同义**：`auto` 按决策 4 判；`true` 无视版本、带 HTTP 验证器做条件 GET（304 则复用已有字节）；`false` 绝不联网。

  6. **`download --source`**：`auto`（默认）= LaTeX 源码优先、失败回退 arXiv HTML；`latex` / `html` 指定即不回退；`pdf` **只在显式给出时下载，且只下载不解析**（PDF→MD 仍属顺延项）；`all` = 三者都取。

  7. **`read` 拿不到 arXiv 记录即报 `source_error`**，不降级成元数据——`read` 的承诺是正文。

  8. **载荷**：`read` 仍是定位器（全文不进信封，[ADR-0053](ADR-0053.md) 决策 2 的理由不变），新增 `doc.source_version` / `doc.remote_version` / `doc.stale`；`lookup` 新增 `versions:{remote, local}`；`search` / `sync` 的载荷不变（[ADR-0057](ADR-0057.md) 的最小集）。

  9. **schema**：`artifact.kind` 增 `source_html` / `source_pdf`（`paper_html` 是输出产物，不是抓来的原件）；`record` 增 `source_version`，`artifact` 增 `source_version` / `etag` / `last_modified`；`SCHEMA_VERSION` 3→4，走既有的加列迁移。

- **理由**：

  1. **按产物分比按动作分更贴近使用者的问法**：「我要原件」与「我要能读的正文」是两个需求。按动作分时，`textify` 一个命令同时承担取件、转换、落盘、投影，`read` 只负责定位，于是「想读一篇但本地没有」要经过「一条命令 → 一个错误码 → 再来一次」。
  2. **懒物化把「缺」这一种情况吃掉**：`projection_missing` 于是只在「不允许联网且取不到」时出现，不再是读一篇的常规路径。
  3. **版本挂在元数据刷新上，省掉每次读都发一次条件 GET**：arXiv 有 3 秒请求间隔，而 `search` / `sync` 本来就要刷新 `record`。实测 arXiv feed 的 `<id>` 带版本（`.../abs/2610.17916v1`），`/e-print/<id>` 与 `/html/<id>` 都返回 `ETag` 与 `Last-Modified` 且支持 304。
  4. **现在改是零兼容负担**：`textify` 与 `read` 都还没接线（argparse 不认这两个子命令），改名不需要背历史包袱，与 [ADR-0047](ADR-0047.md) 决策「现在删零成本」同类。
  5. **`download` 与 `export` 的边界不重叠**：`download` 只写本地库（`bytes/` + `works/`），把字节复制到用户目录仍是 `export` 的职责（[ADR-0035](ADR-0035.md) 决策 3 不变）。

- **实测**（2026-10-17，本机直连 arXiv，单次探针）：

  | 观测 | 结果 |
  |---|---|
  | `HEAD /e-print/2610.17916` | 302 → `/src/2610.17916`；`ETag`、`Last-Modified: Wed, 14 Oct 2026 05:12:25 GMT`、493 897 B |
  | 带 `If-None-Match` 与 `If-Modified-Since` | 两者都返回 **304**（正文不重发） |
  | `HEAD /html/2610.17916` | `ETag`、`Last-Modified`、377 312 B；`If-None-Match` → **304** |
  | `1706.03762` 的 v1 与 v7 | `ETag` 与 `Last-Modified` 都不同（新版 `/src` 的 `ETag` 形如 `"sha256:…"`） |

  这张表说明两件事：**e-print 也会随版本更新**（同一条 `record` 覆盖所有版本，因为 `vN` 在派生 id 时被归一化掉），以及**版本信号不必自造**——HTTP 验证器够用，且复验几乎免费。

- **代价**：

  1. **`read` 从只读定位器变成会写盘的命令**：要进写锁（冲突即 `busy`），失败要分层（取件失败 vs 转换失败），并且 SKILL 必须写一条「不要对着候选列表逐篇 `read`」，否则一次误用就是几十篇下载。
  2. **陈旧窗口 = 元数据刷新间隔**：`read` 不判新旧，只在载荷里标 `stale`。要确认最新版得跑 `download`。若调用方普遍在 `read` 之后立刻 `download`，说明这条分工不成立。
  3. **NULL 版本的过渡期**：现存 `record` 的 `source_version` 全为空（新列）。照「NULL 视为不等」硬跑，过渡期内每次取件都会把源码包整份重下，所以 `download` 在它为空时先读一次 feed 补上（一次小请求，之后不再发生）；feed 也读不到时才退回取最新版、`artifact.source_version` 留空——那一次缓存不成立，下一次仍会取件。
  4. **HTML 重渲染不升版本**：arXiv 侧重新生成 LaTeXML 输出时版本号不变，缓存不会跟新；`--refresh true` 是逃生口。
  5. **`download --source all` 每篇最多 3 个请求**，受 arXiv 3 秒间隔约束，批量使用要自己控节奏。

- **触发重估的信号**：

  1. 调用方反复在 `read` 之后立即 `download`——说明「默认不更新」把成本推给了使用者；
  2. 出现「读到旧版本却被当成最新」的真实事故——说明 `stale` 标注不够醒目，或该改成默认复查；
  3. HTML 重渲染造成的陈旧产生可见质量问题——届时考虑对 `source_html` 每次物化都做条件 GET。
