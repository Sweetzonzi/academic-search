# ADR-0047　命令面收敛

**状态**：accepted（2026-10-15）

> **范围**：本条理由 3 的「初版六条命令」清单口径由 [ADR-0051](ADR-0051.md) 取代——命令面为六条用户命令 + 三条支撑命令（`sync` / `verify` / `profile`），`bundle` 并入 `export` 且 `export` 初版不实现；"不设 `dedupe` / `stage`、不提供人工分组入口"的结论不变。

- **决策**：
  1. **不设 `dedupe` 与 `stage` 两条命令**。去重（`group()`）与落池（`ingest`）是 `search` / `lookup` / `sync` 的**内部步骤**——联网结果先落库、查询只面对数据库（[ADR-0043](ADR-0043.md)），没有任何调用方需要单独触发它们。
  2. **初版不提供人工分组入口**（不设 `regroup` / `merge` / `split`）。**自动**重新分组保留：记录后来拿到强标识、OpenAlex 侧发生合并或拆分时，分组任务照常合并与重定向（[ADR-0026](ADR-0026.md)、[DESIGN §4.2.5](../02-设计说明书.md)）。
  3. **面向用户的入口仍只有检索与阅读**；"这篇来自哪几条记录"由结果里的 `work` 与来源信息回答。
- **理由**：
  1. **它们不是动作，是流水线的一步**：`stage` 没有调用方；`dedupe` 只返回判定而不落写。[DESIGN §4.2.2](../02-设计说明书.md) 已把 `ingest` / `group()` 写成实现路径，[ADR-0002](ADR-0002.md) 也已把"去重交给代码"定为分工。
  2. **人工分组的前提是把哈希样标识交给人**：`work_key` 与 `works/<work_key>/` 都是不可读的哈希样标识（[ADR-0033](ADR-0033.md)），让人对着它们做合并 / 拆分不现实；要做就必须先做成"可读清单 + 选择"的界面，那是一块独立的工作量。
  3. **命令面越小越好**：每条命令都要有对外契约、测试与文档；初版承诺的六条命令（`search` / `lookup` / `textify` / `digest` / `read` / `export`）已覆盖全部用户动作。
  4. **现在删零成本**：CLI 尚未实现，删除没有兼容负担；一旦发布，`SCHEMA_VERSION` 只增不删就会让改名变贵。
- **代价**：
  1. **误合并没有人工修复路径**：L2 弱判据的实测假阳性约 4%，而人工拆组又不在初版。该后果由 [ADR-0048](ADR-0048.md) 处理——初版 L2 只登记待确认、不自动归组。
  2. **外部来源的候选没有入池入口**：只有 CLI 自己的客户端抓到的结果会落库；agent 从别处拿到的候选清单无处安放。若出现真实需求，再考虑一个受控的导入命令。
- **触发重估的信号**：① 实际语料中出现必须人工拆开的误合并；② 出现"把外部结果放进池子"的真实请求；③ 需要按主题给人做策展视图。
