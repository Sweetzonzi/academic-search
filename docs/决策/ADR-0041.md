# ADR-0041　临时检索与具名查询并列：同一种检索式的「有名字」与「当场给」

**状态**：accepted（2026-10-15）

> **取代**：本条决策 1 中"`search` 两种入口并列"的部分由 [ADR-0049](ADR-0049.md) 取代——`search` 只接受当场给的检索式，画像里的具名查询由 `sync` 独占；**决策 3 的 `topic` 标签整体由 [ADR-0050](ADR-0050.md) 删除**；"临时变定期的桥"（决策 4）不变。

- **决策**：
  1. `search` **两种入口并列**：
     - `--query <具名查询>`：用画像里存着的检索式（可重放，[ADR-0027](ADR-0027.md)）；
     - `--all-of` / `--any-of` / `--venue` / `--author` / `--since-years`：**当场给检索式**（临时检索）。**字段语义与画像完全一致**，不发明第二套语法。
     - 两者互斥；都不给时无法联网检索，只能查库（等价于 `--refresh false`，[ADR-0043](ADR-0043.md)）。
  2. **临时检索的结果照样落候选池**，与定期任务共用去重与缓存：`record` 按 `(source, source_id)` 幂等、`candidate` 防重复推荐、派生文本按 `content_hash` 复用（[ADR-0011](ADR-0011.md)、[ADR-0028](ADR-0028.md)）。**第二次拼出同样的检索式不重复计费。**
  3. **`topic` 标签**：临时检索打 `--topic <名字>`，缺省 `ad-hoc`。
     - `topic` 与画像里的查询名**共享同一个命名空间**（都是候选池上的标签），但**不做冲突检查**。
     - 因此 `--topic <已存在的查询名>` 是一个**有意义的动作**：把这次临时检索发现的结果归入那个方向。
  4. **临时变定期的桥**：想把某次临时检索变成定期任务，就是把它写进画像——agent 直接编辑 `config/profile.toml` 再加一条 `[[query]]` 即可（[ADR-0039](ADR-0039.md)），不需要别的命令。

- **理由**：
  1. **agent 的绝大多数检索是临时的**。画像服务于「定期发现我方向上的新论文」，而「帮我查一下 X 有没有人做过」是另一种动作——不能要求用户先把它写进配置再查。
  2. **但两者是同一种东西**：都是「一个检索式 → 一批候选」。区别只在检索式**存不存下来**。所以不新增命令、不新增表，只多一组入参。
  3. **结果必须落池**，否则「检索缓存层」这个定位不成立：临时查过的东西下次要重新联网、重新计费、可能重新推荐。
  4. **`--all-of` / `--any-of` 与画像字段同名**，避免「配置文件里一套语法、命令行里另一套」这种最典型的漂移源。

- **代价**：
  1. 临时检索会往候选池里灌入画像之外的论文——**这是有意的**，但意味着「候选池 ≠ 我的方向」，按 `topic` 筛才能看出哪些来自定期任务。
  2. `topic` 不做冲突检查，同一个标签可能既来自画像又来自临时检索；这是特性不是缺陷（见决策 3）。
  3. **临时检索的检索式不留档**，除非用户让 agent 写进画像。要复盘「上次是怎么查的」只能靠对话记录；缓解是让 `search` 也把原始请求写进运行账本（与 `sync` 共用 `run`）。
