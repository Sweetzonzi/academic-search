# ADR-0035　全文按需取：定时 run 只落元数据与摘要，「要这篇」= 产物落盘，不落状态

**状态**：accepted（2026-10-15）

> **取代**：本条中"初版候选池的三态"一节由 [ADR-0044](ADR-0044.md) 取代——候选池没有状态列；「要这篇」= `textify`、不落状态的结论不变。

- **决策**：三条规则——
  1. **定时 run 不取全文**：一遍 `sync` 只落元数据、标识与摘要进候选池；全文（arXiv 源码 / 出版社 HTML / PDF / 抽取文本）**只在被要求时才取**。
  2. **「要这篇」的语义 = `textify`**：取来源 → 转换 → 字节落 `bytes/`、投影落 `works/`、`artifact` 表登记。**不设 `kept` 状态**——「要过」的证据是 `artifact` 里有该 work 的行，是既成事实，不是决策标志。
  3. **「拿走」= `export` / 复制到指定路径**：`export --work <work_key> --out <路径>` 从 `works/` 复制出去（给同学、放进写作目录、交给别的工具都走这一条）。`works/` 是投影，不是最终归宿。

- **理由**：
  1. **成本与规模**：候选池是 10³–10⁴ 量级，其中被真正读过的通常只有几十篇。全量取全文 = 全量下载 + 全量转换 + 全量磁盘占用，而绝大多数永远不会被打开。
  2. **状态少一个是少一处不一致**：若用 `kept` 标志表达「要」，它就必须与 `artifact` 的存在保持同步；两者不一致时（标志了但转换失败、转换成功但标志没写）就要仲裁。**让产物本身当证据，天然不会不同步。**
  3. **`textify` 本来就幂等**：`content_hash` + `converter_version` 在缓存键里，重复要求零成本命中（[DESIGN §4.4](../02-设计说明书.md)）。所以「要了就取」没有额外代价。
  4. **与初版定位一致**：初版是一个**缓存**层——缓存的意义是按需填充，不是预取全部（[ADR-0032](ADR-0032.md)）。

- **初版候选池的三态**（[DESIGN §4.3.6](../02-设计说明书.md)）：`new`（新入池）/ `parked`（看过不要，保留可查）/ `hidden`（不再推荐）。`promoted` 保留定义但**初版不会出现**（没有 Zotero）。因此 `works/` 下**只会出现被要过的论文**。

- **代价**：
  1. **「要了但暂时拿不到」无法表达**：`textify` 失败（无 OA 原生文本、PDF 解析失败）只报错，不落标志。用户重试或换来源即可；若日后证明这是常见摩擦，再考虑加标志。
  2. **正文检索只覆盖取过全文的那部分**。这是规模的直接结果，不是缺陷——而它也让备选方案的取舍变简单：contentless FTS5 与文件扫描的**覆盖范围完全相同**，选择只取决于实现复杂度与使用体验（已定为文件扫描，见 [ADR-0036](ADR-0036.md)）。

- **备选方案（当前不采用）**：加 `kept` 状态表达「要了但先不取全文」。不采用的理由见理由 2；且初版里「要」与「取全文」之间没有别的动作，拆分没有收益。
