# ADR-0069　数据目录不可写先报 `data_not_writable`

**状态**：accepted（2026-10-19）

> **范围**：本条只回答「数据目录不可写时错误怎么报」。只读仓库根要不要降级成「可读不可写」模式是另一个问题，本条**不做**（见「否决」第 3 条）；`busy`、`io_error`、`internal_error` 的其余判据不变。

- **决策**：

  1. **连库之前先探写**：`store.connect()` 在打开 sidecar 前，在 `data/` 里建一个临时文件再删；失败即抛 `error.code=data_not_writable`，message 带**解析后的绝对路径**与三条修法（把仓库放到可写位置 / 设 `ACADEMIC_SEARCH_ROOT` / 见 `skills/academic-search/SKILL.md` 的环境要求一节）。**库文件本身是只读**（目录可写、文件被设只读）同样在这一步报，message 指向文件而不是目录。
  2. **SQLite 的原话只映射两种**：`unable to open database file`（WAL 建不出 `-wal` / `-shm`）与 `readonly database`（库文件被设只读）。其余 `sqlite3.OperationalError` 仍按未分类缺陷走 `internal_error`——不拿一个兜底去掩盖真故障。
  3. **不碰库的命令不受影响**：`version`、`profile` 只在内存里读配置，只读仓库根上照常工作；这也意味着**它们不能当环境自检**（`skills/academic-search/SKILL.md` 的环境要求一节有自检口径）。

- **理由**：

  1. **实测：库可读、命令不可用。** 把 `data/` 目录的写权限去掉后，`sqlite3.connect()` 成功、`SELECT` 也读得到，但 `PRAGMA journal_mode = WAL` 需要新建 `-wal` / `-shm`，于是抛 `unable to open database file`；它被 `cli.main` 的兜底 `except` 原样塞进 `internal_error`。用户看到的是「未分类缺陷」，而真实原因是权限。
  2. **这条错误比「刷新失败」更严重**：`--refresh false` 也走同一条连库路径，所以在只读挂载上**连本地缓存都查不了**——「零成本离线可审计」的承诺整体失效，而不只是某次刷新失败。
  3. **错误码比 message 稳定**：调用方（agent 或脚本）要能一眼分辨「换参数」与「换目录」。`io_error` 的语义是「本地读写失败（含只读属性、跨卷硬链接）」，把权限问题塞进去，等于让「先做什么」这一列继续含糊。
  4. **预检比事后映射快**：写探针在连库前失败，省掉一次 SQLite 初始化；同时能在 message 里给出**具体是哪个目录**（事后只有 `unable to open database file` 这一句）。

- **否决**：

  1. **复用 `io_error`、只把 message 写清楚**：不用动错误码全集，但 agent 无法按 code 分支；message 一改就失效，而 `code` 是契约。
  2. **只在 CLI 入口探测**：`store.connect()` 才是所有写路径的汇合点（`service` 的四个命令、测试、将来的子命令）。入口探测会漏掉直接调 service 的调用方。
  3. **只读根自动降级为「可读不可写」并继续查本地**：需要绕开 WAL（`mode=ro` + `query_only`）、跳过 `run` 账本、并定义哪些命令拒跑——这是产品语义变更，不是错误映射。留作独立决策；实现之前，报 `data_not_writable` 比「静默只读、账本缺行」更诚实。
  4. **把 `mkdir` 失败与 WAL 失败合成一条 message**：两者都要带路径，但原因不同（目录不存在 vs 没有写权限）。决策 1 的探针先报前者，决策 2 的映射兜住后者。

- **代价**：

  1. **每次连库多一次文件创建/删除**：本机可忽略（远小于一次查询）。
  2. **预检与真正连库之间有竞态**：探测后目录被改成只读仍会失败——决策 2 的映射是兜底。
  3. **错误码全集多了一个值**：必须在 [IFACE-PAYLOAD §6](../接口/输出载荷.md)、[cli-reference](../../skills/academic-search/references/cli-reference.md) §10 与 `envelope.ERROR_CODES` 三处同步；`SCHEMA_VERSION` 不变（只增不删）。

- **触发重估的信号**：① 出现「只读挂载上要能查本地」的真实需求（那时做决策 3 的降级模式）；② 探针在慢盘上被观测到明显开销；③ 出现第三种「连得上库但不能写」的原因（例如文件被独占锁）。
