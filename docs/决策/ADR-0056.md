# ADR-0056　契约补口：五处实现前必须写死的口径

**状态**：partially superseded by [ADR-0066](ADR-0066.md)（2026-10-16 接受）；被取代的是决策 1 的 `sync` stdout 形状（从单 run 的真子集改为 `data.runs[]` 逐 run 自包含），其余四处不变。

> **范围**：本条只补齐 [IFACE](../03-接口契约.md) / [IFACE-PAYLOAD](../接口/输出载荷.md) / [IFACE-SOURCE](../接口/数据源适配.md) 在实现前缺定义的五处口径，**不推翻任何既有决策**。其中「`search` 落候选池」是 [ADR-0043](ADR-0043.md) 决策 1 已有的结论在接口契约里的漏抄，此处只是把它补回文档。

- **决策**：

  1. **`sync` 信封的 `data` 是 `run.json` 的真子集**（不含 `responses`、不含任何路径字段）：
     `{run_id, status, queries[], spec_hash[], refreshed, window:{from,to}, counts:{new_candidates, dedup_blocked, by_source:{}, failures:[{source, reason}]}, cost:{usd, basis, requests}}`，另有仅降级时出现的 `degraded:{reason}`。字段名与 [IFACE-PAYLOAD §3](../接口/输出载荷.md) 的 `run.json` 逐字相同——**不维护第二套词表**。

  2. **三个检索命令都落候选池**：`search` / `lookup` / `sync` 在联网结果落库时写 `record` + `record_ident` + `candidate`（[ADR-0043](ADR-0043.md) 决策 1）。`run.query_name` **只有 `sync` 填**，`search` / `lookup` 产生的 run 行为 NULL——NULL 即「匿名检索式」，**不新增枚举**。推论一：`--refresh false` 且命中已有记录时**仍写 run 行**（`refreshed=否`、`cost=0`），与 `auto` 档跳过刷新时写 `refreshed=否` 的行为一致。推论二：`candidate.first_run_id` 可以指向一次交互式 run，因此先前被 `search` 查过、但从未出现在某条具名查询结果里的 work，会出现在下一次 `sync` 的「新发现」栏——这是 [ADR-0028](ADR-0028.md) 定义的直接结果（新发现 = 本次 run 才入池），**不新增列区分来源**。

  3. **`textify` 的 LaTeX 装配**：
     - 主 `.tex`：候选名优先（`main.tex` / `ms.tex` / `paper.tex` / `Manuscript_arxiv.tex` / `<arxiv-id>.tex`）→ 否则在解包目录里找含 `\documentclass` 的文件 → **多于一个候选即报错，不自动选**。单一 `.tex` 文件与 gzip 单文件按同一入口处理，`.ltx` 等价于 `.tex`。
     - PDF 图渲染器顺序：`pdftocairo` → PyMuPDF → 保留 PDF 链接并标注。`pdftocairo` 的解析顺序是 PATH → `ACADEMIC_SEARCH_PDFTOCAIRO` 环境变量 → `D:\texlive\*\bin\windows\pdftocairo.exe`；缺失不是错误，是**降级**。
     - **渲染器是缓存键的一部分**：`converter_version` 记 pandoc 版本与渲染器标识（`pdftocairo@<路径推断版本>` / `pymupdf@<版本>` / `none`）。换渲染器 → 换 `converter_version` → 触发重转（[ADR-0016](ADR-0016.md)）。
     - **渲染分辨率（200 dpi）不是独立参数**，归渲染器标识。

  4. **`digest list` 的 `content_hash` 是只读信息，`put` 不接受调用方给的 hash**：CLI 按 `work_key` 现算。`source_text` 的取值规则见 [IFACE-SOURCE §5](../接口/数据源适配.md)；载荷带 `chars`，**不截断**。`skipped[].reason` 取固定枚举 `not_found` / `no_source_text`。**不设 `hash_mismatch` / `terms_mismatch`**：键由 CLI 现算，这两个条件在实现里不可达，列出来只会变成没人能触发的分支。**明说边界**：CLI 能保证「键算得对」，**不能**判断 `text` 是否真的属于该 work——那是 `put` 调用方的责任。

  5. **部分失败与降级不改变退出码**：退出码回答「**这次运行有没有产出可用的东西**」，不回答「每个源是否都顺利」。只要有源失败或降级发生但主链路产出正常 → `ok=true`、退出码 **0**，失败源进 `counts.failures[]`、降级进 `degraded`；**全部源失败且零写入**才 `ok=false`、退出码 1。另把 [IFACE-PAYLOAD §6](../接口/输出载荷.md) 的「可重试」一列拆成两列：`重试同一命令`（是/否）与 `若否，先做什么`。

- **理由**：
  1. **`data` 缺定义就会长出事实契约**：[IFACE-PAYLOAD](../接口/输出载荷.md) 有「未在本文定义的字段不得出现在信封里」这条硬规则，而 `sync` 的 `data` 从没定义过——实现者随手塞的东西会直接变成契约。选「轻摘要」而非内联全文，是因为 [PLAN 的 M3 验收](../04-里程碑与计划.md) 的判据落在**磁盘上的** `run.json` 与 `report.md`；`stdout` 的职责是让调度器一眼判断成败，`responses` 是审计证据，不该进 stdout。
  2. **`search` 落池是省钱的必要条件**：不落池，临时检索拿到的记录就没有 `candidate` 行，"推过没有"只能用「有没有 record 行」近似——而那是另一件事（缓存 ≠ 入池）。两者混同之后，[R12 综述取材](../01-需求说明.md)「本地语料优先」与候选池推荐会同时失真。
  3. **主 `.tex` 由文件内容定，不由目录顺序定**：实验样本 8/8 都含 `\documentclass`，而 `os.listdir` 取第一个 `.tex` 在多文件工程里会静默拼错；拼错的产物是一份看着正常的残缺 Markdown，**这比报错贵得多**。渲染器与分辨率进 `converter_version`，是因为 [ADR-0016](ADR-0016.md) 的规则是「换转换器即触发重转」，而渲染器换了 Markdown 里的图件确实不同。
  4. **让调用方传 hash 等于让它自证一件它无法验证的事**：模型手里的文本与一个哈希值之间没有任何可校验的对应关系，回传只会制造「照抄」这一种"成功"。改为 CLI 现算之后，键**不可能对不上**；代价是发现不了张冠李戴，而那本来就超出 CLI 的可见范围——与其给一个假的保证，不如把边界写在契约里。
  5. **退出码不能同时表达「降级」与「失败」**：`REQ R3` 要求单源不可用时降级而非失败；若这种情况给退出码 1，调度器会把它当失败任务重试，而重试要再花一次额度——这与 [ADR-0051](ADR-0051.md) 决策 5「成本可见 + 余额降级」的取向正好相反。**判据要落在"产出"上**：一次 run 只要产出了可用结果，它就不是失败。

- **代价**：
  1. **`sync` 的 stdout 与 `run.json` 变成两份内容**：靠「真子集」这条规则约束，不维护第二套词表；实现上应当是同一个序列化函数加一层字段裁剪。
  2. **交互式 `search` 会写 `run` 行**：账本增长更快，且「新发现」栏会混入先前被 `search` 查过的 work。若将来这成为噪声来源，需要新的一列或新的过滤语义——初版接受。
  3. **主 `.tex` 判定失败时 `textify` 直接失败**：多文件工程里若作者把 `\documentclass` 放在宏文件里，会误判成"找不到主文件"。届时的人工出路是在 `textify` 里显式给入口文件——这属于后续补参数，初版不做。
  4. **PyMuPDF 是第一个非标准库的运行时依赖**（[DEV-CONV §1](../开发/约定.md) 的"重活放独立依赖"涵盖它）：未安装时 PDF 图退化为打不开的 `<embed>` 链接并被标注，不会让整篇失败。
  5. **`digest put` 的键校验无法发现译文张冠李戴**：这是契约的固有边界，靠 `put` 调用方的纪律兜底，工具侧不设假闸门。

- **触发重估的信号**：① 「新发现」栏被交互式 `search` 的产物污染到需要过滤；② 出现 `\documentclass` 判定失败的真实论文；③ PyMuPDF 渲染质量在真实语料上明显劣于 pdftocairo；④ 调度器把部分失败当成功而漏掉了该追的源故障。
