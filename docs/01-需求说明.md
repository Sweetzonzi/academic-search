# 需求说明 —— 面向本课题组的 LLM 文献检索与阅读辅助技能

> 本文回答"要做什么、怎么算做完"。设计见 [DESIGN](02-设计说明书.md)，事实依据见 [调研索引](调研/README.md)。
> 需求编号（R*/N*）在设计文档与实施计划中被引用。

---

## 0. 项目定位

**一句话**：面向本课题组的 **LLM 文献检索与阅读辅助技能**——让组里每个人的 AI 助手都能按自己的研究方向找到论文、把论文变成 LLM 读得懂的文本、读懂并讲清楚，还能把结果交接给同学。

| 维度 | 定位 |
|---|---|
| **服务对象** | 本课题组成员及其 LLM 助手（DSH、Codex、Cursor 等有 shell 的 agent）。**各人研究方向不同，领域画像各自独立**，互不干扰 |
| **核心价值** | ① **检索**：按领域定时或按需找论文，先本地去重再联网；② **阅读辅助**：全文文本化（Markdown + 图件 + 锚点）、中文摘要、精读问答、引用可溯源；③ **综述取材**：按领域列出既有论文清单，供人撰写综述或相关工作章节时取材（工具不代写综述，见 §4） |
| **形态** | 一个**技能包**：`SKILL.md`（告诉 agent 何时用）+ 确定性 CLI（干活）+ 画像模板；装进 agent 的 skill 目录即可用，无常驻服务、无数据库服务 |
| **与文献管理器的关系** | **不绑定**：装了 Zotero 的人用它管条目与附件；没装的人走文件库后端（`FileBackend`），工具行为一致 |
| **明确不是** | 不是共享文献库（各人本地独立，靠导出文件交接）；不是论文下载站（只取 OA，且不再分发全文）；不替代 Zotero/EndNote；不是无人审核的全自动入库机器人 |

**典型使用入口**：在会话里说"找一下最近关于 XXX 的论文""这篇讲了什么""图 3 说明了什么"——skill 被触发，CLI 在后台完成检索、去重、文本化、翻译与摘要，agent 只负责组织回答。

---

## 1. 原始需求（逐字引用）

> 现在打算做一套学术检索skill之类的东西给agent用于定时任务或用于回应用户的科研需求，能够让llm通过公开数据库如openAlex，arxiv等获取用户研究领域的有价值的可信的论文，存到本地，翻译摘要缓存，并能够按用户需求查阅检索总结阅读等。考虑可以访问本地的zotero sqlite存储，增删改查，而不是自己实现一套数据库体系。当然，网络查找论文前还应去重等。未来可能还有研究脉络可视化，顺着引用找上去之类的需求。分析分析这些需求。

## 2. 需求解读（原话 → 可验收需求）

| 编号 | 原话依据 | 需求 | 可验收判据 |
|---|---|---|---|
| **R1** | "用于定时任务" | 周期性的领域增量采集（由选定调度器无头触发） | 命令无头可跑、可重入；每次运行产出 `run.json` + 报告；重跑同一时间窗不产生重复候选 |
| **R2** | "用于回应用户的科研需求" | 交互式按需检索与答疑 | 用户提问后 skill 被触发，并在一次回答内给出带出处的结果 |
| **R3** | "通过公开数据库如 openAlex，arxiv 等获取" | 多源检索（OpenAlex 主、arXiv 补预印本、Crossref 兜 DOI） | 单源不可用时链路降级而非失败。**初版来源矩阵**：OpenAlex + arXiv 是采集源，Crossref 只在 `lookup` 里兜 DOI（[ADR-0051](决策/ADR-0051.md)） |
| **R4** | "有价值的可信的论文" | 质量闸门 + 可溯源 | 每条结果带来源与获取时间；撤稿（`is_retracted`）与掠夺性期刊在初版即被排除。**A/B/C 分级与分级理由顺延出初版**（[ADR-0051](决策/ADR-0051.md)） |
| **R5** | "存到本地" | 正式条目入 Zotero，派生数据入 sidecar，默认不下载 PDF | 条目在 Zotero UI 可见可管理；sidecar 删除后可由 Zotero + 网络重建。**初版不实现，顺延到 M5**（[ADR-0032](决策/ADR-0032.md)）：初版只把派生数据写进 sidecar，不产生条目 |
| **R6** | "翻译摘要缓存" | 标题/摘要中文翻译与摘要生成，带缓存与失效 | 同一篇第二次请求零成本命中缓存；改提示词后旧缓存不命中 |
| **R7** | "查阅检索总结阅读" | **阅读辅助**：全文文本化（Markdown + 图件 + 锚点）、本地检索、条目读取、总结与精读问答 | LLM 能基于 `paper.md` 回答方法/公式/图表细节并给出锚点；需要看图时能取到对应图件；无出处的断言不输出 |
| **R8** | "访问本地的 zotero sqlite 存储，增删改查，而不是自己实现一套数据库体系" | 复用 Zotero 作为条目存储；**读**走 sqlite（离线可用），**写**走 Zotero 官方通道 | 读取不要求 Zotero 运行；不直接改 `zotero.sqlite`。**初版不实现，顺延到 M5**（[ADR-0032](决策/ADR-0032.md)）：初版不读也不写任何 Zotero 存储 |
| **R9** | "网络查找论文前还应去重" | 联网前先查本地与候选池 | 已在库论文不再被推荐或写入；同一 DOI 不产生第二条 |
| **R10** | "未来……研究脉络可视化，顺着引用找上去" | 引用图谱：向后溯源 + 向前追踪 + 可视化 | 给定种子论文可产出可读的演进脉络图（远期验收） |
| **R11** | 本项目定位（面向课题组） | **可分发，且每人一份画像**：同学能自行安装、配置自己的领域画像，并把结果导出交接（一人一份，不是一人多份，见 [ADR-0040](决策/ADR-0040.md)） | 三步可用（放入 skill 目录 → 生成画像 → 试跑一次检索）；导出包能被非 Zotero 用户直接使用（**随 `export` 顺延**，[ADR-0051](决策/ADR-0051.md)） |
| **R12** | 需求补充（综述辅助） | **综述取材**：给定领域或主题，能列出该领域既有论文的清单（本地语料优先，缺口才联网），标明入库状态与来源，可导出 | 清单每条带来源与获取时间；`md`/`bibtex`/`ris`/`csljson` 导出随 `export` 顺延（[ADR-0051](决策/ADR-0051.md)）；**不产出综述正文**（边界见 [ADR-0031](决策/ADR-0031.md)） |
| **N1** | "可信" | 可溯源、来源可验证、质量闸门、缺陷显式暴露 | 见 [DESIGN §4.9](02-设计说明书.md) |
| **N2** | 成本可控（隐含） | 外部 API 额度与 LLM token 双预算 | 检索类命令在返回信封里给出花费口径与是否联网；余额不足时停止后续请求，使用本地结果并标注实际进度，字段语义见 [IFACE-PAYLOAD §1](接口/输出载荷.md)。**不做预算闸门**（[ADR-0051](决策/ADR-0051.md)） |
| **N3** | 隐私（隐含） | 本地库内容默认不出网；可选全离线 | 云端调用内容可枚举、可关闭 |
| **N4** | 可维护（隐含） | 可重建、可回滚、接口契约稳定 | 一次 run 的入库可一键撤销；JSON 契约只增不删 |

## 3. 使用场景

场景按**触发来源**分三类：**定时推送**（S1、S2）、**会话内按需**（S3、S5、S8）、**任务型产出**（S4、S6、S7、S9）。

另有两条需求**排在 v1 之外**：**了解陌生领域**（先经典与综述、再前沿的地图式清单）与**追研究热点**（跨轮的主题差分）——两者都要聚合产物，而 v1 只做清单（[ADR-0031](决策/ADR-0031.md)）。

| 场景 | 触发 | 期望行为 |
|---|---|---|
| **S1 每周增量**（定时） | 任意调度器（DSH schedule / 外部 agent 定时任务 / 系统计划任务） | 抓取领域新论文 → 去重 → 质量分级 → 入候选池 →（可选）翻译摘要 → 产出 `data/runs/<run_id>/` 下的 `run.json` + `report.md` |
| **S2 会话内汇报**（定时 + 交互） | 同上的调度器唤醒 | 读最新 run 报告，提炼要点、指出异常、给出推荐阅读清单 |
| **S3 领域问答**（交互） | 用户问"最近有没有关于 X 的新方法" | 先查本地库与候选池，再联网补充，回答带出处 |
| **S4 精读与中文摘要**（交互） | 用户问"这篇讲了什么，跟我的方向什么关系" | 取全文（原生文本优先）→ 生成中文摘要 → **M5** 起若已入库则写入子笔记 |
| **S5 归属确认**（交互） | 用户丢来 DOI/标题问"我库里有没有" | 命中则返回本地条目与所在 collection/标签；未命中给出候选 |
| **S6 脉络追溯**（交互，远期） | 用户问"这个方向是怎么演进的" | 抓引用边 → 主路径/前后向链 → 输出 Mermaid/Graphviz 图 + 每节点一句话说明 |
| **S7 结果转交**（交互） | 同学要某次检索的结果 | `export --format md\|zip\|bibtex\|ris\|csljson` 产出可直接接收的包（含元数据、中文摘要、图件），**不含受版权限制的全文**。**初版不实现 `export`，本场景顺延**（[ADR-0051](决策/ADR-0051.md)） |
| **S8 全文问答**（交互） | 用户问"这篇的控制器是怎么设计的""图 3 说明了什么" | 基于 `paper.md` 与 `figures/` 回答，给出锚点；需要看图时把对应图件交给视觉模型，而不是渲染整页 |
| **S9 综述取材**（交互，任务型） | 用户说"帮我看看 XX 领域都有哪些论文" | 以本地语料为主列出该领域的论文清单（联网只补缺口），每条带来源、年份、入库状态与中文摘要，可导出为写作素材；**不产出综述正文** |

## 4. 范围与非目标

**在范围内**：英文文献为主的检索与入池；本地 Zotero 库（或文件库）的读与（升级后）写；中文翻译与摘要；**为 LLM 生成 Markdown 全文与图件**；引用图谱；把结果导出成交接包给同学。

**初版范围（M0–M3）**：交付物是一个「LLM 用的文献检索缓存层」——**六条用户命令**（`search` / `lookup` / `download` / `digest` / `read` / `export`）+ **三条支撑命令**（`sync` 无头采集与报告 / `verify` 字节校验 / `profile` 画像只读校验）+ sidecar 缓存 + 薄 `SKILL.md`。其中 **`export`（含 `bundle` 别名）初版不实现**：命令契约保留，实现与验收顺延（[ADR-0051](决策/ADR-0051.md)）；**不接 Zotero**，与库相关的读写整体顺延到 M5（[ADR-0032](决策/ADR-0032.md)）；**引用图谱与研究脉络（R10、S6）不在初版**（[ADR-0046](决策/ADR-0046.md)）；**A/B/C 质量分级不在初版**。下表 R5、R8 以及第 5 节中涉及 Zotero 的判据均属 M5，涉及导出的判据随 `export` 顺延。

**非目标（明确不做）**：
1. 替代 Zotero 的文献管理功能；
2. 自建条目数据库或元数据权威；
3. 全量抓取出版商全文或整篇翻译再分发；
4. 覆盖 CNKI/万方等中文数据库（见 [OPEN](06-待决事项.md) 的 `Q8`）；
5. 常驻 MCP 服务；
6. 不做任何人工确认的**全自动入库**——`promote` 默认需人工确认，确认粒度按动作分级（见 [ADR-0030](决策/ADR-0030.md)）；
7. **不做团队共享库**——课题组成员研究方向各异，只需同一套工具；协作通过导出文件交接，不通过共享数据库；
8. **不做全文再分发**——arXiv 源码/PDF 与出版社 HTML 仅限个人使用，导出物只含元数据、自产摘要与引用链接；
9. **不代写综述**——工具只做检索、分级、摘要与清单整理，综述的论证、取舍与写作由人完成；系统综述的检索方法学（检索式留档、纳排计数）同在外（见 [ADR-0031](决策/ADR-0031.md)）。

## 5. 验收标准

**必须成立**：
- 同一查询重跑 0 条重复候选；
- 已入池论文 0 次重复写入；
- 未下载 PDF 的条目也能给出中文摘要；
- 撤稿（`is_retracted`）与掠夺性期刊黑名单在任何档位都不返回；
- 同一份字节在 `bytes/` 只存一份，`works/` 删掉可完整重建（[ADR-0033](决策/ADR-0033.md)）；
- 一次 run 的入库可一键撤销（**顺延到 M5**）；
- 删除 sidecar 后条目视图可由 Zotero + 网络重建一致（缓存除外）（**顺延到 M5**）；
- 采集命令无头可跑且产物为结构化报告（任何调度器都能驱动、任何 agent 都能读）；
- **阅读辅助闭环**：对一篇 arXiv 控制类论文，LLM 能基于 `paper.md` 回答方法细节并给出锚点，图件可被引用；
- **同学无需 Zotero** 即可完成"检索 → 阅读"闭环（R11）；"→ 导出"一段随 `export` 顺延（[ADR-0051](决策/ADR-0051.md)）。

**量化目标（观测，不是闸门）**：每次检索在信封里报告实际花费与是否联网；单次 run 的 OpenAlex 花费目标 < 每日额度 20%；摘要缓存命中率 > 80%（稳态）；单条目本地检索延迟 < 100 ms（正文扫描的实测见 [ADR-0036](决策/ADR-0036.md)）。

**一条容易被忽略的边界**：本地库目前只有 **5 条目 + 6 附件 + 1 个 collection（"世界模型"）+ 3 个 tag**（见 [REF-ENV](调研/本机环境.md)）。因此本项目的定位是"**外源检索为主、本地库为锚**"，而不是"把已有库管起来"——这也是初版不接 Zotero 的原因之一（[ADR-0032](决策/ADR-0032.md)）。
