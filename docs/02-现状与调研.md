## 2. Zotero 能力边界

### 2.1 写入通道（三选一）

| 路线 | 前提 | 能力 | 来源 |
|---|---|---|---|
| **本地 API 写入** | **Zotero 10.0+**（10.0 于 2026-08-17 发布；当前 10.0.6，2026-10-07） | items / collections / saved searches 的 `POST`/`PUT`/`PATCH`/`DELETE`、标签删除、全文写入、三阶段文件上传（<4 GB，仅 `imported_file`/`imported_url`） | 文档（Local API、版本历史） |
| Web API | zotero.org 账号 + 开启同步 + API key | 同上（云端路径）；官方建议并发 ≤4，遇 `Backoff` / `429` 退避；批量写 ≤50 对象/请求 | 文档（Write Requests、Basics） |
| 连接器通道 | Zotero 运行中（**9.x 亦可用**） | `POST /connector/import`（BibTeX/RIS/CSL JSON 等字符串）、`POST /connector/saveItems`（Zotero JSON 数组）、`saveSnapshot`、`saveAttachment`、`updateSession`、`getSelectedCollection` | 源码 `chrome/content/zotero/xpcom/server/server_connector.js`：`saveItems` 在 293-344 行、`import` 在 794-846 行；保存目标取自 UI 当前选中集合或 `lastViewedFolder`（30-66 行） |

**本地 API 写入的授权语义**（文档）：`POST /api/local/authorize` 带 `Zotero-Server-ID` 头，弹窗 "Allow / Always Allow / Deny"；返回 `{key, remember}`；**默认单次 key**（首个成功写请求即消耗），"Always Allow" 才可复用；拒绝 → `403 {"denied":true}`；每分钟最多 5 次会弹窗的请求，超出 429 + `Retry-After`。

**本地 API 其他差异**（文档）：

- 读请求**无需认证**、无速率限制、离线可用；
- 写请求必须带 `Zotero-Server-ID`（缺 → `428`，不匹配 → `412`）；
- Zotero 10+ 的对象版本是**本机局部版本**，与 Web API 版本无关；官方要求"跨运行存数据的客户端按 server ID 分区"；
- **默认不分页**（一次返回全部匹配），需显式传 `limit`/`start`；
- 支持执行已保存搜索：`<prefix>/searches/<key>/items`；
- 附件下载：`<prefix>/items/<key>/file` 返回 302 到 `file://` URL；
- 全文：`GET/PUT <prefix>/items/<key>/fulltext`，`POST /fulltext` 批量上限 10，`GET /fulltext?since=`；
- 不支持 Atom；`PATCH …/file` 分块上传返回 405。

### 2.2 对象模型

- Zotero 的"元数据条目"与"附件"是**两个独立 item**（`items` + `itemTypes` 区分；附件另有 `itemAttachments.parentItemID`）。**没有任何字段要求条目必须有附件**；`fulltextItems` 只为已索引附件建行。
- `itemData` 是固定字段集的 EAV：`itemData(itemID, fieldID, valueID)`，**无 `key`/`version`/`synced`/`libraryID` 列**，必须 join `items`（实测 `PRAGMA table_info`）。
- 附件的 `linkMode`：0 = 导入文件（本机 6/6 均为 0）。

### 2.2.1 Zotero 可索引与可标注的格式（源码依据）

| 格式 | 全文索引 | 可标注 | 依据 |
|---|---|---|---|
| PDF | ✅（走 pdftotext 转换器） | ✅ | `xpcom/fulltext.js:226-231` |
| **HTML** | ✅ | ✅ | 同上；`xpcom/data/item.js:2022`：「标注父项必须是 PDF、EPUB 或 HTML 快照」 |
| EPUB | ✅（专门流程） | ✅ | `fulltext.js:412-434`、`541-546` |
| text/plain | ✅（带 charset 时） | ❌ | `fulltext.js:559-567` |
| **Markdown `.md`** | **未验证**（非一等类型，可能落入 text/plain 分支也可能被跳过） | ❌ | 无对应的 MIME 处理分支 |

**含义**：想让文本版论文在 Zotero 里**被搜到、被标注**，附件应当是 **HTML 快照**；Markdown 属于"给 LLM 读"的形态，放 sidecar 的 blob 目录更合适。

### 2.3 Extra 字段的真实行为

Zotero 会**解析** `Extra` 字段内容：`Zotero.Item.prototype.getExtraField`（源码 `xpcom/data/item.js:311-312`）调用 `Zotero.Utilities.Internal.extractExtraFields()`；保存时会做字段迁移与规范化（`item.js:5375-5679`，包括"未知字段存入 Extra"与"从 Extra 迁移到正式字段"）。**结论：Extra 不是自由文本框**，其中的 `键: 值` 行会被解释，内容还会随导出进入 BibTeX 等格式。

### 2.4 直接修改 `zotero.sqlite`

官方立场是**只读**：Zotero 的缓存层会破坏 SQLite 文件锁，**运行中修改极易损坏数据库**，且绕过数据校验与外键检查（文档：Direct SQLite Database Access）。本项目遵守该约束：**读用副本，写走官方通道**。

### 2.5 Zotero 10.0 的其他相关变化（文档）

撤销/重做、批量编辑、全文检索显著加速、中日韩**整短语**检索与重音不敏感检索、数据库自动压缩；开发者条目明确列出 "Local API write support"。升级会迁移数据库结构（本机当前 `databaseSchema=37`），**不可逆**。

### 3.2 额度实测（无 key 状态）

| 观测 | 值 |
|---|---|
| 无 key 每日额度 | `x-ratelimit-limit-usd: 0.1`，**且按出口 IP 共享**（同一网络的其他人也在用这个池子） |
| **有 key 免费额度** | **$1/天**（10 倍），每日 00:00 UTC 重置——无 key 的 $0.10 不是"免费档"，只是"匿名档" |
| `filter` 查询单价 | `x-ratelimit-cost-usd: 0.0001`（$0.10/千次） |
| `search=` 查询单价 | `0.001`（$1/千次，**贵 10 倍**） |
| **单实体 GET** | **免费**（`/works/W123` 文档标注 Cost: Free；实测在额度耗尽后仍返回 200） |
| **错误响应** | **免费**（任何 4xx/5xx 计 0 credits；实测 429 之后单实体 GET 依然通） |
| 批量按 ID 取 | `filter=ids.openalex:W1\|W2\|W3` → 200，一次取回 3 条，`cost: 0.0001`（用于批量刷新引用数） |
| 另一种写法 | `filter=openalex_id:W…\|…` → **429**，有效性未确认 |
| 速率上限 | 无 key 10 req/s；免费 key 30 req/s；年费档 50 req/s（预算是真正的约束，不是速率） |
| 重置时刻 | `reset: 44361` 秒 ≈ **12.3 小时** → 与"每日 00:00 UTC 重置"一致 |
| 探测消耗 | 本轮十几条请求后 `remaining-usd: 0.0235`；续探最终耗尽到 `0`；随后**同一 IP 的匿名额度一整天都是 429**（2026-10-14 实测，连 subagent 的探测一起算） |

> **给定时任务的含义**：$1/天 = 1 万次 `filter` 或 1000 次 `search`。免费 key 是必须项，不只是"额度 ×10"，而是"从共享池换成自己的池子"。

### 3.3 摘要与覆盖率

- OpenAlex 摘要以倒排索引给出（`{token: [pos,…]}`，因法律原因不提供纯文本），需还原为有序文本（**实测**还原出 1260 字符）；arXiv 直接给 `summary`（实测长度 1411）。
- OpenAlex 摘要覆盖率官方口径：**2022 年后作品 >60%、2000 年前约 45%**，尾部偶有噪声 → 摘要缺失是正常分支。

### 3.5 实测坑（每条均为真实请求结果）

1. **自由文本噪声极大**：`search=attention is all you need` → `count: 3208007` → 自由文本只用于"发现"，存在性判定走结构化 `filter`。
2. **权威记录可能无 DOI / arXiv ID**：`W2626778328`（"Attention Is All You Need"）`type=preprint`、`publication_year=2025`、`locations_count=11`、`ids.arxiv=None`、无 DOI。
3. **DOI 与标题可能错配**：`10.48550/arXiv.2210.03629` 返回记录的标题是另一篇论文（"Distributing Accountability, Not Capability…"）。
4. **`ids.doi` 可能指向他文**：GPT-4 技术报告 `W4327810158` 的 `ids.doi = 10.4230/lipics.cosit.2024.11`。
5. **质量陷阱**：按 `cited_by_count` 排序首位为 OA 期刊论文，`fwci=136.35`、`citation_normalized_percentile≈0.99999416`、2024 年单年 1310 次引用（引用灌水特征）。
6. **filter 值必须转义**：标题含 `,` 或 `:` 的请求直接 400。
7. **语法有新旧之分**：`filter=title_and_abstract.search:` 与 `default.search:`（后者是 `fulltext.search` 的弃用别名）仍可用但已弃用；新写法是 `search=` 与 `search.title_and_abstract=`；`select=` 只能选顶层字段。
8. **增量入口不确定**：`from_created_date`/`from_updated_date` 文档标注为付费计划功能，无 key 实测 429；`updated_date` 会因引用数重算而变动，是噪声源。
9. **跨源身份现实**：OpenAlex `ids` **不含 arXiv 键**（arXiv 副本体现为 `locations[]` 中的 `pmh:oai:arXiv.org:…` 命名空间 id，且 location id 大小写敏感）。
10. **被合并/删除的 Work ID 直接 404，没有跳转**：官方删除日志（`.../works/deleted_ids.csv.gz`，实测 160.6 MB 压缩、**5,231 万条**、滞后约 3 周）里取 5 个真实 ID 实测 → **全部 404、无 `Location` 头**；存活对照 200。官方文档同时存在"301 重定向"与"404 无跳转"两种说法，**实测以后者为准**；且 2025 年 Walden 切换后**不再提供"旧 ID → 新 ID"的映射表**。→ 把 Work ID 当不可变主键是不可靠的。
11. **预印本与正式版是同一条 Work**：官方示例 `10.48550/arxiv.1102.1523` + `10.1109/mcse.2011.37` → 同为 `W2146292423`；本机实测两篇同结论。二者靠 **location 级 `version`** 区分，**没有 `is_preprint_of` 字段**（`related_works` 是"主题相似"，勿混用）。**arXiv 的 v1/v2 是否各成一条 Work：官方未记载**（本机样本表现为一条）。
12. **`publication_date` 是正式版日期**：实测 arXiv 2009 年的论文在 OpenAlex 里是 2012（期刊版）；arXiv 2024-01 的是 2023-11（会议版）。→ "领域新论文"的时间窗必须用 arXiv 的 `published`/`updated`，不能用 OpenAlex 的 `publication_date`。
13. **额度的真实口径**（文档值见 §3.1，实测值见 §3.2）：无 key 的 $0.10/天是**匿名档且按出口 IP 共享**；**有免费 key 是 $1/天**（10 倍，00:00 UTC 重置）。**单实体 GET 与所有 4xx/5xx 免费**——实测额度耗尽后单实体 GET 仍返回 200（这也是本次能免费验证"删除 ID 404"的原因）。
14. **中文文献不在覆盖范围内**：CNKI / 万方 / 维普在官方全部 125 个文档页里**一次都没出现**——既没被列为数据源，也没被列为"不覆盖"。官方给的收录路径是"把作品放进我们已经在抓的地方，对多数期刊就是通过 Crossref 注册 DOI"（[getting-indexed](https://help.openalex.org/how-to/getting-indexed/)）。**"不覆盖"是从其完全缺席 + 官方收录路径推出的结论，不是官方原话**。
15. **扩展语料默认不可见**：约 1.9 亿条低质记录（大量无 DOI 的机构库/DataCite 记录）**默认不出现在 API 结果里**，且自 Walden 切换后是**静态**的；要取需加 `corpus=all`。→ 无 DOI 的学位论文/技术报告即便有 Work ID，也可能查不到。
16. **arXiv → OpenAlex 的桥是"可构造的 DOI"**：`10.48550/arXiv.<id>` 在 DataCite 里从 2006 年（含 `math/0601001`）到当天新论文都存在，`filter=doi:` 可命中；但**已知有 DOI→错误记录**的错配（见第 3 条），必须校验。Crossref 不认识这些 DOI（实测 404）；arXiv API 的 `<arxiv:doi>` 是作者手填的（实测 3 篇仅 1 篇有）。

### 3.6 文本格式可得性（本领域实测）

实测样本：arXiv `eess.SY`（系统与控制）2026-10 最新两篇

| 目标 | 结果 |
|---|---|
| `https://arxiv.org/html/<id>` | **200**，`text/html`，123 KB / 997 KB（含数学标记） |
| `https://arxiv.org/e-print/<id>`（LaTeX 源码包） | **200**，`application/gzip`，1.0 MB / 681 KB |
| `https://arxiv.org/abs/<id>` | 200 |

来源盘点（智能无人系统 / 自动化 / 控制方向）：

| 来源 | 文本可得性 | 说明 |
|---|---|---|
| **arXiv**（eess.SY、cs.RO、math.OC、eess.IV） | ★★★ HTML + **LaTeX 源码** | 本领域预印本主战场 |
| **MDPI**（Sensors、Drones、Machines、Actuators） | ★★★ 免费 HTML/XML | 本领域投稿量很大 |
| Frontiers / PLOS | ★★★ 免费 HTML | — |
| **中文期刊**（自动化学报、控制与决策、控制理论与应用、机器人） | ★★ 官网免费 HTML/PDF | 可补 OpenAlex 对 CNKI 覆盖不足 |
| IEEE（TAC、TCST、TIE、RA-L、ICRA/IROS、CDC/ACC） | ★ PDF 为主 | Xplore HTML 视图对脚本不友好 |
| Elsevier（Automatica、Control Engineering Practice、ISA Transactions） | ★ ScienceDirect HTML 需机构权限，脚本易被拦 | 多回落到 PDF→MD |
| Springer（Nonlinear Dynamics、JINT、Autonomous Robots） | ★★ 订阅 HTML；OA 免费 | — |
| 学位论文 / 标准 / 教材 | ✗ PDF only | OCR 兜底 |

**结论**：本领域"文本友好"来源占比高（arXiv + MDPI + 中文期刊），"原生文本优先、PDF→MD 兜底"的分层路线能覆盖大部分论文。

## 4. SQLite / FTS5 中文检索实测

| 查询 | `unicode61`（默认） | `tokenize='trigram'` | `LIKE` |
|---|---|---|---|
| 剩余使用寿命 | 0 命中 | ✅ | ✅ |
| 世界模型 | 0 命中 | ✅ | ✅ |
| 寿命预测 | 0 命中 | ✅ | ✅ |
| 神经网络（4 字） | — | ✅ | ✅ |
| 图神经（3 字） | — | ✅ | ✅ |
| 模型 / 寿命 / 世界（**2 字**） | 0 命中 | ❌ **仍失效** | ✅ |

**结论**：默认分词器对中文完全失效；trigram 可用但只对 **≥3 字**有效，2 字词需 `LIKE '%…%'` 兜底或先分词（如 jieba）再索引。

## 5. DSH（agent 宿主）能力事实

| 项 | 事实 |
|---|---|
| skill 扫描根（rank 顺序） | `<projectRoot>/.dsh/skills`(100) → `<projectRoot>/.agents/skills`(200) → `customSkillDirs`(300) → `~/.dsh/skills`(400) → `~/.agents/skills`(500) → bundled(600)；`projectRoot` = 最近的含 `.git` 的祖先目录（本工作区 `D:\Files\Project_Paper` 与 `D:\Files` 均无 `.git`，故取 cwd） |
