### 4.2. S1：缓存时长入口待决

**问题**：是否删除 `search --max-age`，统一由 `config/search.toml` 的 `refresh.max_age_hours` 控制新鲜度？现行参数来自 [ADR-0043](决策/ADR-0043.md) 决策 5，去留尚未确定；本批保留 CLI 兼容行为。

- **保留的用途**：某一次查询希望采用不同的自动过期时长，例如常态 24 小时、单次 2 小时；不必修改配置，也不必每次强制刷新。
- **删除的收益**：`--refresh true` 已能强制刷新，`false` 已能完全离线；普通调用使用配置中的 `auto` 策略即可。减少覆盖层级能统一 `search` 与 `sync`，也减少 agent 需要选择的参数和零值歧义。
- **建议方案（待采纳）**：删除单次时长覆盖，保留 `--refresh auto|true|false`；`auto` 只读取配置。配置的数值校验、小数与零值语义随该方案一起明确，不把删除 CLI 参数等同于取消新鲜度缓存。
- **实施条件**：采纳后新增 ADR，取代 ADR-0043 决策 5 的 CLI 覆盖部分；同步解析器、接口、skill 与测试，并明确调用兼容方式。若保留参数，则须先确定其零值含义。该项尚未实施删除。

### 4.3. S3–S5：日期、证据与覆盖信息

- **S3 显式日期窗口**：`canonical_spec()` 已有显式日期字段，CLI 尚未接通。候选参数为 `--from-date` / `--to-date`；实施前确定单边日期与 `--since-years` 的组合规则，以及日期作用于来源记录还是聚合后的 work。复用现有窗口计算、远端日期过滤与本地过滤；hash 规则遵守 [ADR-0062](决策/ADR-0062.md)，显式日期与相对窗口计算出的日期分别处理。验收合法区间、非法日期、起止倒置、组合冲突、边界日期，以及不同窗口不会错误复用新鲜度。
- **S4 摘要证据**：当前摘要选择规则与载荷限制见 [IFACE-PAYLOAD §2](接口/输出载荷.md)。候选增加 `abstract_meta`，标明选中记录的来源、来源内 ID 与是否截断；来源记录的日期、版本信息另行评估。摘要文本与出处由同一次记录选择产生，复用既有优先级。验收多来源摘要不一致、缺失摘要、长摘要与完整 `lookup` 摘要；摘要关闭时不额外加载证据载荷。
- **S5 覆盖信息**：当前取数策略见 [ADR-0062](决策/ADR-0062.md)，采集完整性定义见 [IFACE-PAYLOAD §3](接口/输出载荷.md)。来源接口当前只返回论文列表；OpenAlex 的 URL 构造预留了游标，实际搜索未使用，arXiv 固定从首批开始。候选内部返回结构为 `SourcePage(items, total?, next_token?, exhausted?)`，字段名待定；外部只暴露 agent 判断覆盖所需的信息。来源未提供总数或耗尽依据时保留「未知」，不能仅凭返回 100 条断言仍有下一批。先实现单批取数的覆盖说明，并区分成功空结果、条件跳过、失败与额度停止；不在此项接入自动翻页，也不把 `counts.complete` 当成远端全量召回证明。

### 4.4. S7：远端继续采集待决

本地展示分页（S6，[ADR-0073](决策/ADR-0073.md)）已实现，离线回归见 `tests/test_cli.py`；真实启动器与本地库的排序、分页验收见 [EX-2026-10-21-local-pagination](实验/EX-2026-10-21-本地排序与分页.md)。本节只保留远端继续采集的候选方案。

| 工作项 | 候选行为 | 边界与验收条件 |
|---|---|---|
| S7 远端采集 | 使用适配器各自的游标或起始位置继续取数；请求次数或批次数上限（例如 `--max-pages`）只是候选策略 | 先确定适用命令、默认取数深度、终止条件与续取方式，并评估对 [ADR-0062](决策/ADR-0062.md) 单批策略的影响。采集层负责请求、额度闸门、落池与留档，适配器负责分页协议。必须同时设计缓存覆盖：取过一批的缓存不能直接满足取三批的请求；查询身份与采集深度的存储方式待定。验收多批成功、空结果、中途失败、额度停止、重复记录，以及一批缓存后请求三批的行为；展示 `limit` 不决定采集终止 |

本地展示分页的采纳不表示接受自动远端分页。远端分页相关的官方 API 行为应在实施时核验并更新事实文档。

### 4.5. 推进方式与完成条件

1. **建议顺序**：S1 的参数去留仍待决定，S3、S4、S5 按调研收益独立安排。S7 单独评估，不作为其余工作项的前置条件。
2. **后续评估范围**：逐来源缓存与失败补查、相关性排序、结构化错误与重试分类。它们不纳入建议首批；分别补充触发场景、契约与验收条件后再排期。跨来源的原始相关性分数不能直接视为同一尺度。
3. **实施步骤**：修复现有契约缺陷时补回归测试；改变公开语义或引入参数、载荷时，先补 ADR 或接口契约并登记 §2，再实现。同步 skill 交付参考与使用说明，交付文档只写已经可用的行为。
4. **完成记录**：每项填入实现提交、实际执行的测试及结果、必要的真实 API 核验依据；完成后从候选队列移除，权威结论留在对应契约、决策或实验记录中，避免在计划里重复定义。
5. **调研验收**：用本节的无人机场景与人工核验的种子论文清单，检查经典召回、年份覆盖、主题贴合与重复项，记录请求数、费用和结果载荷大小。该清单是回归样本，不视为领域完整书目；没有实测时不承诺召回或成本收益。
6. **文档校验**：执行 [AGENTS.md](../AGENTS.md) 第 4 节的三个检查脚本，并人工复核语义一致性、自包含性与结论依据。文档校验通过不代表实现验收通过。
