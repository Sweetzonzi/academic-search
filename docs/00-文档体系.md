# 文档体系

> 本文件定义这套文档怎么分、每篇归谁维护、引用怎么写、改完怎么校验。

## 1. 六层职责

| 层 | 放什么 | 维护方式 | 目录 |
|---|---|---|---|
| 规范 | 需求与验收、设计、接口契约、术语、数据模型（含[正文转换清单](接口/数据模型.md)） | 就地重写（现行权威） | `01`–`03`、术语表、`接口/`、`开发/` |
| 过程 | 里程碑与计划（已接受待实现的决策、候选工作队列）、待决事项、风险、运维手册 | 就地重写 | `04`–`07`、`运维/` |
| 记录 | 设计决策（ADR）、实验（EX） | **追加式，永不改写** | `决策/`、`实验/` |
| 事实 | 本机环境、外部 API、能力边界、可复用资产 | 快照 + 刷新触发条件 | `调研/` |
| 交付 | 面向组员的使用手册；skill 的检索与[论文精读流程](../skills/academic-search/SKILL.md#4-论文精读)（人和 agent 默认从 `works/` 阅读）、运行时 `references/`（初始化步骤统一在 [setup.md](../skills/academic-search/references/setup.md)） | 就地重写；由规范层蒸馏 | `使用/`、`skills/` |
| 元/归档 | 本文件、归档 | 就地 / 冻结 | `00`、`archive/` |

**一条事实只有一个家**：ADR 是「决定」的家，实验是「数字」的家，设计只允许「链接 + 一句结论」。

## 2. 文档 ID 与引用

每篇文档的 front-matter 声明 `doc-id`（稳定不变，与文件名解耦）与 `kind`。跨文档引用写成：

```
DESIGN §4.2              同目录或跨目录的规范文档
ADR-0003                 决策
EX-2026-10-14-textify §3.3   实验
```

文件名可以改、可以移动，`doc-id` 不变，引用不变。自引用写 `§x.y` 即可。

## 3. 生命周期规则

- **规范 / 过程**：写当前状态，不留「上一版/已被推翻」这类版本相对框架（详见 [AGENTS.md](../AGENTS.md)）；
- **记录（决策 / 实验）**：允许出现「第一版/此前」——那是数据或实现的历史，不是文档版本历史；
- **归档**：保留当时的样子，不参与校验。

## 4. 校验

`tools/doc_check.py` 按本体系解析 ID 与 `§` 引用，并按 `kind` 决定是否做自包含性检查。命令见 [AGENTS.md](../AGENTS.md) 第 4 节。
