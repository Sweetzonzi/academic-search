## 2. M0 可行性检查清单

**前置**：Zotero 当前未运行（已确认），库从未同步。

### 2.1 备份（必做，先于一切）

```powershell
# 1) 关闭 Zotero（本机当前未运行）
# 2) 复制整个数据目录（库仅 2.22 MB，附件 51 MB）
Copy-Item -Recurse -Force "D:\ZoteroLib" "D:\ZoteroLib-backup-20261014"
# 3) 校验副本完整性（只读打开副本，不碰原库）
python -c "import sqlite3;c=sqlite3.connect(r'D:\ZoteroLib-backup-20261014\zotero.sqlite');print(c.execute('pragma integrity_check').fetchone())"
# 4) 记录升级前基线（条目数 / 附件数 / 全文索引数 / databaseSchema）
```
**记录基线**：顶层条目 5、附件 6、`fulltextItems` 6、`databaseSchema=37`、`collections=1`、`tags=3`。

### 2.2 申请 OpenAlex 免费 API key

- 入口：openalex.org 账号设置中的 API key（具体页面以官方当前指引为准，本文未逐步核实）。
- 校验：带 key 请求一次 `filter` 查询，确认 `x-ratelimit-limit-usd` 从 `0.1` 提升到约 `1`。

### 2.3 升级 Zotero 到 10.0.6

- 覆盖安装后**逐项比对基线**：`databaseSchema`、条目数、附件数、`fulltextItems` 数、PDF 能否打开、标签与 collection 是否完好。
- 若任何一项不符 → **停止后续步骤**，用备份回退（升级是单向的，回退依靠备份而非降级安装）。

### 2.4 授权本地写入

```powershell
# 1) 启动 Zotero，确认设置中已勾选「允许本机其他应用与 Zotero 通信」
# 2) 读取 Server ID（读请求无需认证）
curl.exe -i http://127.0.0.1:23119/api/
#    → 关注响应头 Zotero-Server-ID: <id>
# 3) 请求授权（必须带 Server-ID 头；Zotero 会弹窗，用户点 "Always Allow"）
curl.exe -X POST http://127.0.0.1:23119/api/local/authorize `
  -H "Content-Type: application/json" `
  -H "Zotero-Server-ID: <id>" `
  -d '{\"appName\": \"academic-search\"}'
#    → 返回 {"key":"<32字符>","remember":true}
```
注意：默认是**单次 key**（首个成功写请求即消耗），只有 "Always Allow" 才可复用；每分钟最多 5 次弹窗。

### 2.5 创建专用 collection 并做写入/读取/删除测试

```powershell
# 1) 创建 collection "Agent Inbox"（POST /api/users/0/collections）
# 2) 写一条最小条目（仅元信息，不带附件）
#    POST /api/users/0/items  → 201 + {"successful":{"0":{"key":"<itemKey>"}}}
#    body 示例：[{"itemType":"journalArticle","title":"[test] academic-search spike",
#                 "DOI":"10.0000/test","tags":[{"tag":"agent-test"}],"collections":["<collectionKey>"]}]
# 3) 读回校验（GET /api/users/0/items/<itemKey>）→ 确认字段落库
# 4) 删除（DELETE /api/users/0/items/<itemKey>）→ 确认进入回收站、UI 中消失
```
**同时验证**：写请求带 `If-Unmodified-Since-Version` 的语义；删掉 key 后写请求应返回 `401`（用于确认授权确实生效）。

### 2.6 回滚验证

- 按 `itemKey` 删除测试条目后，确认 `GET /api/users/0/items?q=academic-search spike` 无结果。
- 在 sidecar 侧记录 `run_id` 与该条目的对应关系，验证"按 run 回滚"的查询路径可跑通。

### 2.7 增量与回退通道（M0b）

```powershell
# 增量：额度充足时分别用无 key / 有 key 请求
curl.exe "https://api.openalex.org/works?filter=from_updated_date:2026-10-13&per-page=1"
# 回退：Zotero 未升级时，用连接器通道导入一条 RIS/BibTeX（需 Zotero 运行且选中目标集合）
curl.exe -X POST "http://127.0.0.1:23119/connector/import" `
  -H "Content-Type: text/plain" --data-binary "@sample.ris"
```

### 3.1 M1.5 文本化 spike 新增的决定（2026-10-14，实测依据见 [05](05-实验记录-文本化.md)）

| # | 决策 | 结论 | 为什么 |
|---|---|---|---|
| F | pandoc 输出方言 | **固定 `commonmark_x+tex_math_dollars+pipe_tables+footnotes+implicit_figures`**；方言串进缓存键 | `-t gfm` 会把行间公式变成 ```` ```math ```` 代码块、行内公式变成 `` $`x`$ ``；`-t markdown` 会丢表格（8 篇中 3 篇） |
| G | 归一化层 | **必需，且是产品的一部分**：公式环境拆壳 → 图件 HTML→Markdown 图片 → PDF 图转 PNG → 锚点注入 → 交叉引用解析 | pandoc 原始输出实测不可直接使用：8/8 篇出现非法 `$$\begin{equation}…$$`、图件全部是带绝对路径的 raw HTML |
| H | 转换器分发与依赖 | 用 **`pypandoc_binary`**（40.9 MB 下载 / 221 MB 磁盘）；`pdftocairo`（本机 TeX Live 2024 已有）作可选依赖，缺失时降级并把 PDF 图链接标注出来 | 一条 `pip install` 即可，无需管理员权限；46/53 张图是 PDF，不转就打不开 |
| I | TikZ 分支 | **降级为罕见回退**，不进关键路径 | 8 篇样本正文里 TikZ 图 0 例（唯一命中在 IEEE 版权声明宏内） |
| J | 两条路线的关系 | **LaTeX 源码为主，HTML 为辅**（回退 + 补表号表题 + 取 SVG 图）。HTML 不作为主力 | 实测：HTML 的数学里会出现未展开的自定义宏（`\real^{n}` 这类无法渲染的命令，单篇 83 次），而 LaTeX 路线 8/8 篇宏展开全对、体积只有 60%。清洗后 HTML 仍为 1.65 倍体积 |
| K | arXiv HTML 可用性判定 | **必须 GET `/html/<id>` 看状态码**，不能读 Atom feed 的 `type="text/html"` 字段 | 该字段对每篇都声明可用，但实测 2004 年论文返回 404；2009 年及以后抽样均可（arXiv 已回溯转换） |
| **L** | **作品身份：确定性 id，不铸随机 id** | **全库没有任何随机生成的标识符**：`record_uid = base32(sha256(source ‖ source_id))[:20]`（确定性、可复现、路径安全）；**`work_key` 直接取组内最早那条记录的 `record_uid`**，不另铸 id；第三方 ID（OpenAlex `W…` / DOI / arXiv）一律降为 `record_ident` 别名。配三条首领规则：首领=最早记录、**禁止硬删记录**（标 tombstone）、**合并=重定向不改名** | 实测**被合并/删除的 OpenAlex Work ID 返回 404 且无跳转**（官方删除日志 5,231 万条中取 5 个真实 ID 复测），2025 年后不再提供"旧 ID→新 ID"映射；标题哈希跨来源碰撞 **16%（最大 7 篇同名）**、反向 1/3 标题会变。**身份的可复现性是收益**：两台机器与删库重建后，`record_uid`、`work_key`、`blobs/` 路径全都一致（随机 id 做不到） |
| **M** | **多来源并存策略** | **统统存为记录、各自保留；不做破坏性合并**；由分组层（可重分组的视图）归为 work；**派生数据按源文本 `content_hash` 共享**，不指向"最早的那条记录"；字节按 `sha256` 内容寻址 | 写入无需跨源仲裁 → 幂等、可乱序、可并行；无不可逆操作 → 分组错了改分组；"指向最早"在原文变更时必然给出错误译文，按内容哈希则自动对且顺序无关 |
| **N** | 去重判据 | 强标识（L0）> 显式桥 `locations[]`/`externalIds`（L1）> `title_key + 一作姓氏 + 年份[-1,+10]` 且强标识不冲突（L2）> 人工（L3）。**`title_key` 绝不进唯一约束** | 实测假阳性：`title_key` 单独 16%、+年份 4%、+作者+年份 4%；年份窗口必须不对称（实测有 -1 与 +3 的真实例子） |
| **O** | 分组维护 | 分组任务常走 **OpenAlex 单实体 GET**（`/works/doi:<doi>`，**免费**）拿 `locations[]` 做 arXiv↔正式版桥；合并时**自己保留 `merged_into` 映射** | 单实体 GET 与 4xx/5xx 免费，所以分组/对账任务可以高频跑而不烧额度；保留合并映射正是我们批评 OpenAlex 缺失的那一点 |
