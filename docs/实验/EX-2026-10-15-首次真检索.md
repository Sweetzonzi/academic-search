# 实验记录：首次真实检索（arXiv）

> 实验日期：2026-10-15。目的：在把 `search` 交给 agent 之前，先对着**真源**跑一次「检索 → 去重 → 落候选池 → 信封」这条链路，而不是只信脱敏 fixture。
> 一句话结论：**链路通**——一次 arXiv 查询取回 5 条、落 5 个候选，随后 `--refresh auto` 零成本命中本地同一批；同时暴露四个只在真网络下才出现的问题（§3.1–§3.3、§6.3），已修。
> 范围：主用 arXiv（免 key）；`lookup` 与 OpenAlex 的顺带实测见 §6（匿名档仍 429，且暴露了一个 DOI 归一化缺陷）。`sync` 与文本化不在本轮。

## 3. 发现

### 3.1 arXiv 对退化的日期边界回 HTTP 500

直接探测 `export.arxiv.org/api/query`（同一检索式、只换日期子句）：

| 日期子句 | 状态码 |
|---|---|
| `submittedDate:[000000000000 TO 202610152359]` | **500** |
| `submittedDate:[* TO 202610152359]` | **500** |
| `submittedDate:[199101010000 TO 999999999999]` | **500** |
| `submittedDate:[199101010000 TO 999912312359]` | 200 |
| 不下发日期子句 | 200 |

原实现把「没有下界」写成 `000000000000`、把「没有上界」写成 `999999999999`，于是**不带 `--since-years` 的第一次检索必然失败**（信封 `source_error`、退出码 1，而 `source_error` 在可重试集合里，agent 会一直重试同一个坏查询）。

修法（`src/academic_search/sources/arxiv.py`）：日期子句只在**有下界**时下发；上界缺失时用合法日期 `999912312359`；只有上界等于没有过滤（论文都在过去），直接不下发。

### 3.2 全失败的 run 被记成 `ok`，把 `auto` 档锁死一天

第一次失败留下 `refreshed=1, status=ok` 的 run 行；`last_refresh_at()` 只认 `status=ok`，于是同一个检索式在 24 小时窗口内被判「新鲜」，`--refresh auto` 直接跳过联网并返回空列表——**用户看到的是「查过了、没有新论文」**。

修法（`src/academic_search/service.py`）：全部源失败且零写入时 `finish_run(status="failed")`，然后再抛错。账本从此对得起信封。

### 3.3 本地 FTS 的精确词比远端严：`drone` 只命中 3/5

联网取回 5 条、本地只返回 3 条。逐条比对摘要后确认：被丢的两篇写的是 **drones**，而 arXiv 的 `abs:"drone"` 把复数一起匹配了；本地 FTS5 的 `unicode61` 不做词形归并。

| FTS 查询 | 命中 |
|---|---|
| `("world model") AND ("drone")` | 3 |
| `("world model") AND ("drone" *)` | 5 |

修法（`src/academic_search/service.py` 的 `_fts_query`）：检索式的每个词按**前缀**匹配（FTS5 的 `*` 只作用于短语末词，`"world model" *` 因此也能命中 world models）。本地是候选池的过滤器，不该比源更严——否则「取回来又静默丢掉」这类 bug 只能靠比对条数发现。

## 6. 顺带实测：`lookup` 与 OpenAlex

### 6.1 `lookup --arxiv` 可用，退出码 0

`lookup --arxiv 2610.18808 --refresh true` → `ok=true`、退出码 0、`requests=2`、`failures=[]`、返回 1 条。`cost.basis="按 OpenAlex 计费档估算"` 说明这一次 OpenAlex 有过 200（429 会在记账之前抛出），即当时的匿名额度还没耗尽。

### 6.2 `search --source openalex` 仍是 429

`search --source openalex --all-of "world model" --since-years 1 --refresh true` → `ok=false`、`code=source_error`、消息「全部源失败且无写入：openalex=429 限流或额度耗尽」，退出码 1；账本按 §3.2 的修法记 `status=failed`。**OpenAlex 匿名档不可靠**：[RUN-M0](../运维/M0-额度与增量实测.md) 的免费 key 是 OpenAlex 采集的前置。

### 6.3 DOI 以 URL 形式入库，L0 与 arXiv 桥同时失效

上面那次 `lookup` 落了 2 条记录、2 个 `work`：arXiv 那条 idents 是 `[("arxiv", "2610.18808")]`，OpenAlex 那条是 `[("doi", "https://doi.org/10.48550/arxiv.2610.18808"), ("openalex", "w7221814676")]`——**DOI 带着 `https://doi.org/` 前缀进了库**，于是：

- 它永远撞不上 Crossref / arXiv 的裸 DOI（L0 强判据失效）；
- `bridges_from_locations` 的 `^10\.48550/arxiv\.` 也匹配不上，同一篇论文的 arXiv 记录与 OpenAlex 记录裂成两个 work（实测 7 条记录 / 7 个 work）。

fixture 复核（`tests/fixtures/openalex_work.json`）：三篇的 `ids.doi` 全是 `https://doi.org/…`；`ids` 里**没有 arxiv 键**（与 [IFACE-SOURCE §3.1](../接口/数据源适配.md) 一致），arXiv 线索只在 `locations[].doi` 或 `landing_page_url` 上。修法：`sources.normalize_doi()` 剥掉 `https://doi.org/`、`doi:` 等前缀，`parse_work` 与 `bridges_from_locations` 都过一遍；`lookup --doi` 的入参同样归一化（用户粘 URL 形式照样命中）。
