# 实验记录：检索口径与来源校验实测

> 实验日期：2026-10-16（本机，Asia/Shanghai）。目的：把「检索式怎么发到 OpenAlex / arXiv、按什么排序取回、来源返回的标识怎么被校验」三件事逐条实测，为 [OPEN](../06-待决事项.md) 里的待决项提供数字依据。
> 一句话结论：**OpenAlex 的全文检索是 `$0.001/次` 档，与 `search=` 同价**——`title_and_abstract.search:` 并不在 `$0.0001` 档；多词值不加引号会退化成词袋 AND；排序与被引过滤只在**取数**和**展示**之一生效，两处与文档表述不一致。
> 范围：只测口径与计数。付费层边界、`works` 上按来源过滤的可用写法未测，见 §8。

## 1. 计费口径：按「有没有做全文检索」分档

实测（带免费 key，每次一个请求，读响应头 `x-ratelimit-cost-usd` 与 `x-ratelimit-credits-used`）：

| 请求 | credits | cost |
|---|---|---|
| `filter=publication_year:2026` | 1 | `$0.0001` |
| `filter=cited_by_count:>100` | 1 | `$0.0001` |
| `filter=title_and_abstract.search:world model` | **10** | **`$0.001`** |
| `search.title_and_abstract=world model` | 10 | `$0.001` |
| `search=world model` | 10 | `$0.001` |
| `filter=title_and_abstract.search:"world model",cited_by_count:>100` | 10 | `$0.001` |

官方文档同一口径：`official-docs/all/api__searching.md` 明写「These filter-based searches cost the same $1 per 1,000 requests」，`official-docs/all/access__example-costs.md` 的价目表把 **List + filter** 记 `$0.10/千次`、**Search** 记 `$1/千次`。

交叉验证：本次会话跑 23 次联网 `search`，账本合计 `$0.023` = 23 × `$0.001`，与按 search 档计费完全吻合。

**结论**：`filter=` 这个参数名不代表便宜档。带 `.search` 后缀的过滤器是一次全文检索，与 `search=` 同价；`$0.0001` 档只属于不含全文检索的普通 filter。

## 2. 多词值不加引号会退化成词袋 AND

`meta.count` 实测：

| 写法 | 命中数 |
|---|---|
| `title_and_abstract.search:world model` | 1 267 321 |
| `title_and_abstract.search:"world model"` | **14 582** |
| `title_and_abstract.search:"world models"` | 14 582 |
| `title_and_abstract.search:attitude` / `…:"attitude"` | 1 877 040 |
| `title_and_abstract.search:attitude control` | 231 312 |
| `title_and_abstract.search:"attitude control"` | 23 018 |
| `title_and_abstract.search:learned` | 843 535 |
| `title_and_abstract.search:learned dynamics model` | 14 304 |
| `title_and_abstract.search:"learned dynamics" model` | **551** |
| `title_and_abstract.search:quadrotor` / `…:"quadrotor"` / `…:"quadrotors"` | 16 625 |
| `title_and_abstract.search:"multi-agent"` / `…:"multi agent"` | 154 663 |

三条读数：

1. **不加引号 = 词袋 AND**：`attitude control`（231 312）远小于 `attitude` 单独命中（1 877 040）；`"learned dynamics" model`（551）远小于 `learned dynamics model`（14 304）。
2. **加引号不牺牲词形归并**：`"world model"` 与 `"world models"` 同值，`"quadrotor"` 与 `"quadrotors"` 同值，`"multi agent"` 与 `"multi-agent"` 同值。官方文档侧的解释是检索本身做 stemming 与连字符切分。
3. **引号救不了单词泛词**：`attitude` 加不加引号都是 1 877 040。高频普通词做 `any_of` 的 OR 组会直接决定噪声量级。

## 3. 两个检索门在短语、布尔、价格上等价

| 对照项 | `filter=field.search:`（旧门，官方标注废弃） | `search.field=`（新门） |
|---|---|---|
| 短语命中（`"world model"`） | 14 582 | **14 582** |
| credits | 10 | 10 |
| `all_of` ∧ `any_of` 的组合 | 两个 filter 子句隐式 AND + `\|` 隐式 OR → 154 | `"world model" AND (drone OR UAV OR quadrotor)` → **154** |
| 与 `sort=publication_date:desc` 共存 | — | 200，首条 2026-10-14 |
| 与 `sort=cited_by_count:desc` 共存 | — | 200，首条 1971-12-01 |
| 与 `sort=relevance_score:desc` 共存 | — | 200，首条 1956-12-01 |

官方文档侧：`api__searching.md` 标注 `filter=field.search:` 已废弃并建议改用 `search` 参数；`api__filtering.md` 建议多词值加引号（`geo.region:"New York"`）。

**结论**：换门不改变命中集合，也不改变价格。新门要求把 `all_of` / `any_of` 合成**一个**布尔串（该参数一次请求只能出现一次），并且必须继续显式下发排序参数——`search.` 的默认排序是 relevance，不是日期。

## 4. 排序在「取数」与「展示」两处，只有后者接 `--sort`

- 实测远端请求：OpenAlex 侧是 `sort=publication_date%3Adesc`，arXiv 侧是 `sortBy=submittedDate&sortOrder=descending`。
- `service._fetch()`（`src/academic_search/service.py`）转发的参数里没有 `sort`，因此 `search_url()` 用了默认值 `"date"`。
- 本地展示排序由 `_sorted_items()` 对 FTS 命中的 work 重排，`citations` 档按 `cited_by_count` 降序、无值排后。
- 判据是 `spec_hash`：`--refresh true` 无条件联网；`auto` 看该 `spec_hash` 最近一次成功刷新是否在 `max_age_hours` 内。而 `config.canonical_spec()`（`src/academic_search/config.py`）的字段集只有 `all_of` / `any_of` / `venues` / `authors` / `since_years`。
- 本地排序实测：`search --any-of "world model" --sort citations --refresh false` 依次排出被引 429 / 184 / 125 / 97 / 46 / 22 / 12 / 12 的条目。

**结论**：`--sort citations` 能正确排序**库里已有的**条目，但联网取回的那一批恒为最近发布的一批；且 `sort` 不在 `spec_hash` 里，所以默认档下换排序不会触发重新取数。

## 5. `--venue` 在远端与本地各有一处与文档不符

**(a) 远端返回 400。** 实测端到端：

```powershell
skills/academic-search/scripts/run.cmd search --all-of "world model" --venue ICRA --refresh true --limit 5
# counts = {"new_candidates":0,"dedup_blocked":0,"by_source":{"openalex":0,"arxiv":5},
#           "failures":[{"source":"openalex","reason":"HTTP 400"}]}   ok = true
```

`build_filter()`（`src/academic_search/sources/openalex.py`）用的过滤器名是 `primary_location.source.display_name.search:`。官方文档里 `display_name.search` 这一族只在 authors 上有示例，且多处标注已废弃。

**(b) 本地把空 venue 的记录排除，而文档写的是「不生效」。** `_venue_ok()`（`src/academic_search/service.py`）在给定白名单时要求 venue 归一化后包含白名单项，venue 为空的记录不通过。实测（`--refresh false`，纯本地）：

| 命令 | 结果 |
|---|---|
| `search --any-of Skytopia --refresh false` | 1 条（该条目 `sources=[arxiv]`，venue 为空） |
| 同上加 `--venue ICRA` | **0 条** |
| 同上加 `--venue arXiv` | **0 条** |

**(c) 两者叠加会让带 venue 白名单的查询恒返 0 条。** 按 `config/profile.toml` 里 `world-model-uav` 的字段原样执行：

| 命令 | items | counts |
|---|---|---|
| 原样（3 个 `--venue`） | **0** | `openalex: 0`（400）、`arxiv: 10` |
| 去掉 `--venue` | 10 | 两源各 10 |

链路是：OpenAlex 腿 400 掉 → arXiv 腿取回 10 条并落库 → 本地 venue 白名单把这 10 条全部排除。

## 7. 补桥反例：两个 arXiv ID 落到无关的 OpenAlex Work

本次按 31 个已知 arXiv ID 逐条 `lookup --arxiv` 补录，其中 **2 条**的 OpenAlex 那一腿返回了另一篇论文：

| 请求的 arXiv ID | arXiv 侧标题 | OpenAlex 返回的 Work | 该 Work 的 `ids.doi` |
|---|---|---|---|
| `1803.10122` | World Models | `W2795843265` VOLE-Field… | `10.5281/zenodo.1207631` |
| `1706.05296` | Value-Decomposition Networks… | `W2626637010` Learning a Generic Value-Selection Heuristic… | `10.4230/lipics.cp.2023.25` |

机制实测：**请求的 arXiv 标识确实出现在返回 Work 的 `locations[]` 里**（`arxiv.org/abs/1803.10122` 与 `10.48550/arxiv.1803.10122` 都在 `W2795843265` 的 locations 中）。因此基于标识一致性的检查会放行，能识别它的是跨来源的内容比对。

连带两个可观测后果：

- `record_ident` 里 `arxiv = 1803.10122` 落在 OpenAlex 那条记录上，arXiv 侧的真记录没有别名。`upsert_ident()`（`src/academic_search/store.py`）是 `INSERT OR IGNORE`，`(ns, value)` 是主键，先写者占位。
- 该 work 的被引数显示为 184（VOLE-Field 的数），在 `--sort citations` 里排到 World Models 真实记录之前。

L1 补桥的验收规则在规范层已经写定（**标题 + 年份 + 首作者交叉校验，冲突标 `metadata_conflict` 且不归组**）；实测 `metadata_conflict` 全库 1608 条记录均为空值，`src/` 下没有写它的代码路径。

## 8. 未覆盖

- **付费层边界**：`cited_by_count:>N` 在无 key / 付费档下的计费与可用性未测（本次只测了带免费 key 的档位）。
- **`works` 上按来源过滤的可用写法**：`primary_location.source.display_name.search:` 实测 400，替代写法（如按 source id 过滤）未查证。
- **URL 长度上限**：官方文档说整条 URL 约 4 KB、超出返回 400 并建议分片；本次未构造超限请求。
- **补桥反例的代表性**：样本是 31 个手动挑选的知名老论文，偏向被重复抓取的记录，**不能外推**为一般错并率。

## 11. venue 白名单的可满足性

§5 覆盖的是 `--venue` 的两处局部缺陷（远端 400、本地排除空值）。本节回答更大的问题：**按载体筛选这件事，在当前的取数口径与语料下能不能成立**。结论是不能——`config/profile.toml` 里三个查询的白名单当前**恒返 0 条**。

**(a) 三个画像查询：白名单归零。** 本地执行（`--refresh false`、`--limit 50`）。「缩写」是配置里的原值，「全称」是把缩写展开成 OpenAlex 实际使用的载体名（见 (e)）。

| 查询 | 不带 venue | 缩写白名单 | 全称白名单 |
|---|---|---|---|
| `world-models`（NeurIPS / ICML / ICLR） | 50 | 0 | 0 |
| `world-model-uav`（ICRA / IROS / RA-L） | 47 | 0 | 0 |
| `multi-agent-decision`（AAMAS / NeurIPS / ICML） | 50 | 0 | 0 |

**(b) 语料的 venue 覆盖。** 全库 1610 条 live 记录：

| 来源 | 记录数 | venue 非空 |
|---|---|---|
| arxiv | 778 | **0** |
| openalex | 832 | 792 |

按关键字做子串命中：`ICRA` 0、`IROS` 0、`RA-L` 0、`NeurIPS` 0、`ICML` 0、`ICLR` 0、`CVPR` 0；`arXiv` 156、`Zenodo` 117。venue 含 `Conference` / `Proceedings` / `Symposium` 的记录合计 29 条，其中一部分是期刊（`Proceedings of the Royal Society A`、`Proceedings of the Institution of Mechanical Engineers Part G`）。

**(c) 会议论文在 OpenAlex 里的 venue 取值。** 同一批记录里几篇经典论文的 `venue` 与 `type`：

| arXiv ID | 论文 | `venue` | `type` |
|---|---|---|---|
| `1706.02275` | MADDPG（ICLR 2017） | `arXiv (Cornell University)` | preprint |
| `1803.11485` | QMIX（ICML 2018） | `arXiv (Cornell University)` | preprint |
| `1802.05438` | TD3（ICML 2018） | `arXiv (Cornell University)` | preprint |
| `1912.01603` | Dreamer（ICLR 2020） | `arXiv (Cornell University)` | preprint |
| `2010.02193` | DreamerV2（ICLR 2021） | `arXiv (Cornell University)` | preprint |
| `1708.02596` | Millirobot 动力学模型（ICRA 2018） | `Proceedings - IEEE International Conference on Robotics and Automation/Proceedings` | other |
| `2103.01955` | —（NeurIPS） | `neural information processing systems` | conference-paper |

两条读法：

1. **会议缩写不出现在 venue 里。** 载体名的实际形态是全称（`neural information processing systems`，全小写）或 proceedings 名（`Proceedings - IEEE International Conference on Robotics and Automation`）。缩写在字面上匹配不到。
2. **`lookup --arxiv` 取回的是预印本 Work。** 查 `1706.02275` 与 `1912.01603` 的完整 `locations[]`：前者是 `arXiv (Cornell University)` ×4 加一个 `TIB Data Manager`，后者是 `arXiv (Cornell University)` ×3，**没有任何会议载体**，两个 Work 的 `type` 都是 `preprint`。会议版本若在 OpenAlex 里另有 Work，本次未查证。这意味着补桥路径取回的记录天然带不上会议载体。

**(d) 把 venue 当远端取数条件是可用的。** `filter=locations.source.id:<S-id>` 与短语过滤器叠加，仍是一次全文检索（10 credits）：

| 远端过滤 | `"world model"` 命中 |
|---|---|
| 无 | 14 582 |
| `locations.source.id:S4210217939`（ICRA proceedings） | **143** |
| `locations.source.id:S4363606243`（neurips） | **110** |
| `locations.source.id:S4306400194`（arXiv） | 4 233 |

三个 source 实体的粒度（单实体 GET，免费）：

| Source | `type` | `works_count` | 近年 |
|---|---|---|---|
| `S4210217939` | conference | 32 827 | 2026: 1882 / 2025: 1610 / 2024: 1766 / 2023: 1347 |
| `S4363606243` | conference | 19 928 | 2025: 5819 / 2024: 4494 / 2023: 3540 / 2022: 2834 |
| `S4306400194` | repository | 1 469 849 | 2026: 282 841 / 2025: 186 162 |

会议在 OpenAlex 里是**系列级**实体：一个 S-id 覆盖 ICRA 的全部年份，不需要按年维护。`locations.` 前缀比 `primary_location.` 宽——只要作品挂在某个载体上就命中，而 `primary_location` 只取主载体。

**载体名 → S-id 的解析路径**：`/sources` 上的 `filter=display_name.search:<全称片段>` 可用，计费与 works 上的全文检索同档（10 credits / `$0.001`）。实测 `display_name.search:robotics and automation` 返回 55 个候选，前两位正是 ICRA proceedings（`S4210217939`）与 IEEE RA-L（`S4210169774`，journal，11 633 篇）。**按缩写搜等于没搜**：`display_name.search:ICRA` 只返回 1 条——一个 6 篇作品的土耳其法学期刊（`Medeni Usul ve İcra İflas Hukuku Dergisi`）。会议缩写不出现在 source 名里（见 (c) 第 1 条），所以「会名 → S-id」这一步只能人工确认后登记，不能靠字符串自动解析。

**(e) 缩写 → 全称的映射表能修到哪一步。** 把白名单从缩写换成全称后，全库命中：

| 缩写 | 全称 | 命中记录 |
|---|---|---|
| `ICRA` | `international conference on robotics and automation` | 3 |
| `IROS` | `intelligent robots and systems` | 0 |
| `RA-L` | `robotics and automation letters` | 2 |
| `NeurIPS` | `neural information processing systems` | 1 |
| `ICML` | `international conference on machine learning` | 0 |
| `ICLR` | `learning representations` | 0 |
| `AAMAS` | `autonomous agents and multiagent systems` | 0 |

合计 6 条，且**没有一条进入 (a) 的三个查询**：

| 记录 | 日期 | 未进入的原因 |
|---|---|---|
| RA-L「Learning Context-Aware Neural ODE Dynamics…」 | 2026-06-08 | 主题不含 |
| RA-L「WAND: Robust Navigation Under Complex Wind Disturbances…」 | 2026-09-02 | 主题不含 |
| ICRA「Gaussian Process Implicit Surfaces as Control Barrier Functions…」 | 2026-06-01 | 主题不含 |
| ICRA「Neural Network Dynamics for Model-Based Deep RL…」 | 2018-05-01 | 在 `since_years 3` 之外 |
| ICRA「Neural-Swarm: Decentralized Close-Proximity Multirotor Control…」 | 2020-05-01 | 同上 |
| NeurIPS「The Surprising Effectiveness of PPO in Cooperative, Multi-Agent Games」 | 记录 2022-01-01 | 主题与载体都命中，只差窗口 |

映射表修的是「字符串匹配」这一层，修不了「语料里没有这类记录」这一层。把 `multi-agent-decision` 的窗口从 3 年放宽到 5 年，那条 NeurIPS 记录就出现（实测 0 条 → 1 条）。白名单筛的是**已经按「主题词 + 日期降序」抓回来的语料**，而这个口径天然偏向预印本与期刊——会议论文要么没被抓过，要么抓回来的是预印本 Work。

**(f) 小结：0 条是四层原因叠加。**

| 层 | 原因 | 可修的位置 |
|---|---|---|
| 1 | 白名单填缩写，数据里是全称 | 映射表或改匹配依据 |
| 2 | arXiv 源 778 条 venue 全空，`_venue_ok()` 对空值不通过 | 空值口径 |

## 12. 质量阈值与被引排序

「找某个方向的经典」有三条候选路。本节记三条路的体量与一条反例。

**(a) 阈值过滤的体量。** 与 §6 同口径（`search.title_and_abstract=<短语>` 叠加 `filter=`，叠加不额外计费）：

| 短语 | 全部 | `cited_by_count:>100` | `fwci:>2` | `fwci:>3` | `>100` 且 `fwci:>2` |
|---|---|---|---|---|---|
| `"world model"` | 14 582 | 294 | 2 103 | 1 579 | 250 |

`fwci` 可直接作远端过滤器，实测无 400。

**(b) 远端按被引排序取回什么。** `filter=title_and_abstract.search:"world model"&sort=cited_by_count:desc&per-page=5`：

| 年 | 被引 | 标题 |
|---|---|---|
| 1971 | 4 865 | Strips: A new approach to the application of theorem proving to problem solving |
| 1997 | 4 684 | World Society and the Nation‐State |
| 2006 | 2 591 | Small-World Brain Networks |
| 1991 | 2 301 | The vector field histogram — fast obstacle avoidance for mobile robots |
| 1989 | 2 214 | Using occupancy grids for mobile robot perception and navigation |

同一次响应的 `meta.count = 14 582`，与 §3 的短语命中同值，**说明引号生效**（词袋写法是 1 267 321）。逐条取 `abstract_inverted_index` 还原摘要复核，五条的命中性质并不相同，见 (c)。

**(c) 五条命中的性质。** 还原 `abstract_inverted_index` 后逐条看上下文：

| 年 | 摘要里的原文 | 命中性质 |
|---|---|---|
| 1971 | **索引为空**（API 不返回摘要） | 无法解释，见下 |
| 1997 | `the diffusion of world models` | 真短语命中——世界社会理论里的「世界模式」，与本研究方向无关 |
| 2006 | `the relevance of small-world models` | **分词产物**：`small-world models` 里 `world` 与 `model` 相邻，等价于 `"world model"` |
| 1991 | `as a world model. This world model is updated…` | 真短语命中——机器人学的「世界模型」 |
| 1989 | `robot perception and world modeling` | **词形归并产物**：`modeling` 归并到 `model`，与 §2 记的 `"world model"` = `"world models"` 同一条规则 |

三条读法：

1. **排序排的是全局被引，不是领域内重要性。** 前五位里只有两条属于本研究方向的「世界模型」（1991 避障、1989 占据栅格），其余三条与方向无关。
2. **短语命中不等于语义命中。** 五条里有两条是分词与词形归并的产物（`small-world models`、`world modeling`），与「世界模型」没有语义关系。**核对命中不能只看「摘要里有没有这个子串」**——`"small-world models"` 含有子串 `world model`，但那是另一回事。
3. **有一条命中无法用载荷解释。** 1971 那篇的 `abstract_inverted_index` 返回 `null`，标题里也没有 `world model`。推测是 OpenAlex 的检索索引保留了已从 API 撤下的摘要，**本次未查证**。

**(d) 与「取数条件」无关。** 上面的跨领域噪声是「短语匹配 + 全局被引排序」的性质——本地排序同样会碰到，只要本地有那批数据。它只说明**按被引排序不适合当「找经典」的手段**，推不出排序该不该参与远端取数：后者是展示偏好与计费口径的问题，与相关性无关。反过来，若真把排序推给远端，远端会从全部 14 582 条里挑被引最高的一批，取回的正是 (b) 那五行。

**(e) 复现。**

```powershell

curl.exe -s "https://api.openalex.org/works?filter=title_and_abstract.search:%22world%20model%22,cited_by_count:>100&per-page=1&select=id&api_key=$env:OPENALEX_API_KEY"

# (b) 按被引排序：读 meta.count 与 results；摘要复核走单实体 GET（免费）取 abstract_inverted_index
curl.exe -s "https://api.openalex.org/works?filter=title_and_abstract.search:%22world%20model%22&sort=cited_by_count:desc&per-page=5&select=id,display_name,cited_by_count,publication_year&api_key=$env:OPENALEX_API_KEY"

# (c) 摘要复核：单实体 GET 取 abstract_inverted_index，按位置还原成文本后**打印上下文**再判断
#     不要只测「摘要里有没有 `world model` 这个子串」——`small-world models` 也会为真
curl.exe -s "https://api.openalex.org/works/<上一步的 id>?select=id,display_name,abstract_inverted_index&api_key=$env:OPENALEX_API_KEY"
```

## 13. 取数页大小与计费

同一条全文检索请求，只改 `per-page`：

| `per-page` | 返回条数 | credits | cost |
|---|---|---|---|
| 1 | 1 | 10 | `$0.001` |
| 100 | 100 | 10 | `$0.001` |

**结论**：OpenAlex 按**次**计费，取数条数不影响价格（与 §1 的档位口径一致）。所以让 `--limit` 决定请求的 `per_page` 是纯损失——默认 `--limit` 是 20，一次请求本可以带回 100 条。`per_page` 的文档上限是 100（`experiments/m1.5/_openalex-identity/` 与 [REF-SOURCES §2](../调研/数据源事实.md) 记「实测 200 仍返回 200 条但不应依赖」）。

```powershell
$env:OPENALEX_API_KEY=[System.Environment]::GetEnvironmentVariable('OPENALEX_API_KEY','User')
curl.exe -sD - -o NUL "https://api.openalex.org/works?filter=title_and_abstract.search:%22world%20model%22&per-page=100&select=id&sort=publication_date:desc&api_key=$env:OPENALEX_API_KEY" |
  Select-String -Pattern '^X-RateLimit-Cost-USD|^X-RateLimit-Credits-Used'
```

**读响应头时的坑**：`Access-Control-Expose-Headers` 那一行里也含这两个名字，过滤时要用 `^` 锚定行首，否则匹配到的是那串长长的头名清单。
