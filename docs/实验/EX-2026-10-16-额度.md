# 实验记录：OpenAlex 免费 key 的额度实测

> 实验日期：2026-10-16（本机，Asia/Shanghai）。目的：验证 [RUN-M0 §1](../运维/M0-额度与增量实测.md) 的校验条件——带 key 请求一次 `filter`，确认 `x-ratelimit-limit-usd` 从 `0.1` 提升到约 `1`；并顺带记录匿名档在同一时刻的实际状态。
> 一句话结论：**key 可用，额度 `0.1` → `1`（10×）**；同一时刻匿名档已被共享池耗尽（`Remaining-USD: 0`，429）。
> 范围：只测额度。**增量口径（`Q1`：`from_created_date` / `from_updated_date` 是否属付费层）本次未测**，见 §3。

## 1. 实验设置

| 项 | 值 |
|---|---|
| 请求 | `GET https://api.openalex.org/works?filter=publication_year:2026&per-page=1`（一次 `filter` 查询） |
| 对照 | 同一 URL：不带 `api_key` / 带 `api_key` |
| key 来源 | 环境变量 `OPENALEX_API_KEY`（用户级已配置；**值不落文档、不进配置、不进版本库**） |
| 客户端 | 标准库 `urllib.request`，`User-Agent` 标注为本仓库的额度探针 |
| 记录 | 本文；`Q4` 据此关闭（[OPEN](../06-待决事项.md)） |

## 2. 结果

| 观测 | 不带 key | 带 key |
|---|---|---|
| HTTP | **429** | **200** |
| `X-RateLimit-Limit-USD` | `0.1` | **`1`** |
| `X-RateLimit-Remaining-USD` | `0` | `0.9999` |
| `X-RateLimit-Limit`（credits） | `1000` | `10000` |
| `X-RateLimit-Cost-USD` | 未计费 | `0.0001` |
| `X-RateLimit-Reset` | 22417 s | 22416 s |

- 429 的响应体：`{"error":"Rate limit exceeded","message":"Insufficient budget. This request has no API key, so it counts against the fre…"}` —— 即 [REF-SOURCES §2](../调研/数据源事实.md) 记的「无 key `$0.10`/天且按出口 IP 共享」，此刻正被别人用光。
- `X-RateLimit-Reset` ≈ 6.2 h 后，即 **00:00 UTC** 重置，与文档值一致。
- 一次 `filter` = `$0.0001`，与 [REF-API](../调研/参考资料-公开API事实.md) 记录的口径一致（`$1`/天 ≈ 1 万次 `filter`）。

## 3. 未覆盖

- **`Q1`**：`from_created_date` / `from_updated_date` 是否属付费层——本次没跑，仍需按 [RUN-M0 §2](../运维/M0-额度与增量实测.md) 的命令各测一次。
- **速率上限**：无 key 10 req/s、免费 key 30 req/s 只按文档记录；本次只发了两发请求，没有测吞吐。
- **采集路径**：`filter` 轮询 / `search=` / 两者混用，取决于 `Q1` 的结论，未定。

## 4. 复现

```powershell
# key 走环境变量；匿名对照去掉 &api_key 即可
$env:OPENALEX_API_KEY = "<key>"
curl.exe -si "https://api.openalex.org/works?filter=publication_year:2026&per-page=1" | Select-String -Pattern x-ratelimit
curl.exe -si "https://api.openalex.org/works?filter=publication_year:2026&per-page=1&api_key=$env:OPENALEX_API_KEY" | Select-String -Pattern x-ratelimit
```

## 5. 顺带修掉的缺陷：`lookup` 不带 key

配 key 之前只有 `search` 把 key 传给 OpenAlex（`service.run_search`），`lookup` 的 OpenAlex 那一腿调 `work_by_doi` / `work_by_arxiv` 时没传 `api_key`，因此即使配了 key 它仍走匿名档、仍会 429。本次一并修掉，并加了回归测试（`tests/test_cli.py` 断言请求 URL 里带 `api_key`）。
