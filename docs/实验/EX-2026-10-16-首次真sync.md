# 实验记录：首次真实 `sync`

> 实验日期：2026-10-16（本机，Asia/Shanghai）。目的：对着真源跑一次 `sync`，逐条核对 [PLAN §2](../04-里程碑与计划.md) 为 [ADR-0066](../决策/ADR-0066.md) 登记的六条验收判据，并查看产出的报告。
> 一句话结论：**三条查询 → 三行 `run`、三个目录、三份报告，报告可读；六条判据全部满足**；过程中发现并修掉一处缺陷——**请求 URL 上的 API key 被照抄进了留档**（§4）。
> 范围：只测 `sync` 的产物与判据。**没有**测多日调度、`data/runs/` 的 GC、真实余额曲线下的额度阈值（后者按 §3.5 的方式用假客户端测过）。

## 1. 实验设置

| 项 | 值 |
|---|---|
| 命令 | `python -m academic_search --root . sync`（`PYTHONPATH=src`） |
| 解释器 | `D:\anaconda3\python.exe`（3.12.7，SQLite 3.45.3） |
| 凭据 | 环境变量 `OPENALEX_API_KEY`（用户级已配置；**值不落文档、不进配置、不进版本库**） |
| 画像 | 仓库本机的 `config/profile.toml`，三条启用查询：`world-models` / `world-model-uav` / `multi-agent-decision`，都带 `venues` 白名单、`since_years = 3` |
| 库的前置状态 | `schema_version = 2`、`run` 213 行、`last_success_watermark` 213 行**全为 NULL**、`candidate` 3528 行 |
| 测试 | `pytest tests` 242 通过（含新增 `tests/test_sync.py` 24 例） |

**为什么三条查询都会走「首次执行」**：`run` 表里 `query_name` 在此之前全为 NULL，没有任何一条具名查询有过成功行。因此三条都用各自的 `since_years = 3`，窗口同为 `2023-10-17 → 2026-10-16`（[ADR-0066](../决策/ADR-0066.md) 决策 9）。

**三条查询都没跑 arXiv 腿**（`by_source.arxiv = 0`）：画像里每条查询都给了 `venues` 白名单，arXiv 没有载体概念，该腿按 [ADR-0060](../决策/ADR-0060.md) 决策 5 主动跳过、如实记 0，不是失败。

**run 217 被跳过**：它的 `spec_hash` 与 2026-10-15T21:22:37Z 的一次 `search`（run 177）相同，那次 `refreshed = 1`、`status = ok`，因此 `auto` 档判为「新鲜」。`sync` 与 `search` 共用一本账、判据是检索式字段而不是命令名——这是 [ADR-0049](../决策/ADR-0049.md) 决策 3 与 [ADR-0066](../决策/ADR-0066.md) 决策 7 的直接结果。

### 2.2 报告长什么样

`report.md` 的头部与同目录 `run.json` 同源（窗口、时区、刷新与状态、花费、计数、失败源），正文两栏。215 的报告是 83 条「新发表」——每条一行 `日期　标题`，下一行给 `doi` / `arXiv id` / `work_key` / 来源。样例：

```text
# run 215　world-models

- 窗口：2023-10-17 → 2026-10-16（UTC+08:00）
- 刷新：是；状态：ok
- 花费：$0.0010 / 1 次请求（按 OpenAlex 计费档估算）
- 计数：新候选 83、去重拦下 3；各源 openalex 91、arxiv 0
- 失败源：无

## 新发表（83）

- 2025-01-01　Improving planning and MBRL with temporally-extended actions
  - `10.52202/085713-4721`；`arXiv:2505.15754`；`24r2otumt4tniorr4uvl`；来源 openalex
```

时区落在 `UTC+08:00`（本机 Windows 拿不到 IANA 名，按偏移渲染，见 `report.local_timezone()`）。

## 4. 缺陷：请求 URL 上的凭据被照抄进留档

**发现**：留档里的 `responses[].url` 是**原样**的请求 URL，而 OpenAlex 的 key 就在查询串上（`?api_key=…`）。这次真跑把它写进了 `data/runs/215/run.json`、`data/runs/216/run.json`，以及 `run.responses` 两行。

**为什么是缺陷**：`data/` 是会被备份、会被人读的目录，而 [配置目录 §0](../使用/配置.md) 的既有口径是「**密钥不进配置文件**、只走环境变量」。留档把这条口径绕过去了——版本库里没有，但数据目录里有。

**修法**：`HttpClient` 记请求时把查询串里 `api_key` / `token` 一类参数的值换成 `REDACTED`（`http.redact_url()`），其余参数（`filter` / `per_page` / `mailto`）逐字保留——留档仍要回答「这次请求长什么样」。已落盘的两份 `run.json` 与两行 `run.responses` 同日抹除；扫描确认 `data/` 下不再出现该 key，版本库里从来没有。

**边界**：这是本次实现里补的一处**数据处置规则**，写进了 [IFACE-PAYLOAD §3](../接口/输出载荷.md) 与[配置目录 §0](../使用/配置.md)；[ADR-0066](../决策/ADR-0066.md) 决策 10 只说了 `responses[]` 记 `url`，没有说凭据怎么办。

## 5. 观察

1. **首次执行时「新发表」这一栏几乎吞掉全部结果。** 215 的 83 条新候选全部落进「新发表」、「新发现」为 0——因为首次窗口是 3 年，而候选的 `published_at` 都在这 3 年内。两栏真正开始有区分度是在**跑过之后**：那时窗口收敛到 `lookback_days`（默认 30 天），「新发表」才回到「最近一个月发表的」这个直觉含义。这是 [ADR-0066](../决策/ADR-0066.md) 决策 3 与决策 9 叠加的必然结果，不是缺陷；但如果首次跑完就按「新发表」去汇报，会把半池子旧论文说成新的。
2. **`world-model-uav` 三年只命中 1 条。** 8 个载体白名单（ICRA / IROS / RA-L / IEEE T-RO / IJRR / Science Robotics / JFR / Autonomous Robots）∩ 「world model」 ∩ （UAV / drone / aerial / unmanned aerial），OpenAlex 的 `meta.count` 就是 1（响应留档可复核）。结合上一条，这条查询的**条件可能过窄**——是画像内容的问题，不是代码的问题。
3. **一次 `sync` 共用一个 `HttpClient`，因此 `cost` 必须按 run 增量记。** 累计值直接写进每个 run 会让第二条查询凭空背上第一条的花费。本次实现按前后差值记账，215/216 各记 \$0.0010、217 记 \$0.0000。
4. **`sync` 的 stdout 不含结果清单**，所以「跑完看一眼」必须读 `latest-report.md` 或 `run.json`——这正是 [ADR-0066](../决策/ADR-0066.md) 决策 4/5 的分工。
