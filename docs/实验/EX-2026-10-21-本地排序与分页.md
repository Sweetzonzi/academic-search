# 真实本地库的排序与 offset 验收

**实测**：2026-10-21，通过 `skills/academic-search/scripts/run.cmd` 启动独立 CLI 进程，读取仓库实际的 `data/sidecar.db` 与配置。共执行 12 次 `search --refresh false`，每次均成功、`failures[]` 为空、`network=false`、请求数与费用为 0。命令会正常写入运行账本；没有使用测试 fixture，也没有替换服务函数。

## 1. 数据与结果

库中有 5,317 篇 work；两种排序均考察 5,317 篇，过滤后匹配 5,297 篇，`truncated=false`。排序规则见 [ADR-0073](../决策/ADR-0073.md)。

| 排序 | 主序范围 | 非空并列组数 | 空值条目数 | 独立核验结果 |
|---|---|---|---|---|
| `date` | `2026-10-19` 至 `1941-11-01`，降序 | 616 | 0 | 全部匹配项顺序正确，并列按 `work_key` 升序 |
| `citations` | 83,751 至 0，降序；空值在末尾 | 219 | 1,442 | 全部匹配项顺序正确，并列与空值组按 `work_key` 升序 |

每种排序先以足够大的 `limit` 取得全部匹配项，再核对 `offset=0/20/40, limit=20` 的三页；每页均与独立计算顺序的对应切片一致，合并后为前 60 篇，无重复、无遗漏。`offset=5297, limit=20` 与 `offset=0, limit=0` 均返回空列表。分页前后的 `considered`、`matched`、`truncated`、`venue_filtered_out` 不变，`returned` 与实际条目数一致。

## 2. 核验方法与边界

复现脚本 `experiments/implementation-review/01_local_sort_pagination.py` 只用标准库。它通过只读 SQLite 连接，按 work 成员独立计算 `MIN(published_at)` 与 `MAX(cited_by_count)`，逐项核对 CLI 载荷，再用包含主序、空值和 `work_key` 的复合键计算期望顺序；不导入生产排序函数。脚本为子进程显式指定当前 Python 解释器，并以占位 key 替代真实凭据。

```powershell
$env:PYTHONIOENCODING='utf-8'
& 'D:\anaconda3\python.exe' experiments/implementation-review/01_local_sort_pagination.py
```

完整信封与汇总保存在该目录的 `out/local-sort-pagination/`，不进版本库。结果对应实测时的本地数据状态；语料或配置变化可能改变计数与页边界。真实库没有日期为空的匹配项，该边界由 `tests/test_cli.py` 的离线用例覆盖。本实验验证本地展示排序与分页，不核验远端取数顺序或召回完整性。
