# sidecar 存储与迁移

> 存储的不变量、字节布局与重建流程。表设计见 [数据模型](数据模型.md)；**DDL 实体随实现落在 `src/**/schema.sql`**，本文只保留「为什么这些约束必须存在」并链接过去。

## 1. 身份公式（全项目唯一定义处）

```
record_uid = lower(base32(sha256(source ‖ 0x1f ‖ normalize(source_id))))[:20]
work_key   = 组内最早见到的那条记录的 record_uid          # 不另铸 id
```

- `‖` 是字节拼接，`0x1f` 是 US 分隔符——成本为零，避免拼接歧义。
- `normalize(source_id)`：**必须做**。arXiv id 大小写不敏感（`math/0601001`）且**去掉版本后缀**（`1501.00001v2` → `1501.00001`，使 v1/v2 是同一条记录）、DOI 按规范大小写不敏感、OpenAlex `W` id 大小写不敏感；不做归一化，同一篇论文会因大小写或版本后缀产生**两条记录、两个 `work_key`**（[ADR-0052](../决策/ADR-0052.md)）。
- `[:20]`：截断到 20 字符 × 5 bit = **100 bit**，长度固定。
- 输出**统一小写**：Windows 与 macOS 的路径不区分大小写，而 `work_key` 就是某个 `record_uid`、又要出现在 `works/<proj>/` 的尾段里；统一小写可避免「看似两个 id、实为一个路径」。
- 哈希在这里只做**格式归一化**（把两个字段压成单列定长），**不做去重**——`(source, source_id)` 本身已经是唯一键。本公式的任何改动都会改变全部 id 与全部 `works/` 路径，属于破坏性变更。

理由与首领规则见 [ADR-0003](../决策/ADR-0003.md)、[ADR-0023](../决策/ADR-0023.md)。

## 2. 两层字节布局的不变量

| 不变量 | 说明 |
|---|---|
| 查询只有一个入口 | sidecar SQLite；`bytes/` 与 `works/` 都不接受查询 |
| sidecar 是 `bytes/` 的索引 | 「记录 → 字节」的唯一映射在 `artifact` / `derived_content`；`bytes/` 的文件名只有 `sha256`，不含作品、来源与 kind，脱库即无主 |
| 大块字节只有一份实体 | `bytes/<sha 前2位>/<sha256>`，内容寻址，相同字节只存一份 |
| `works/` 是可重建投影 | 其中每个文件是 `bytes/` 里的硬链接；删掉可完整重建 |
| 路径不落库 | 库里只存 `sha256`；`bytes/`、`works/` 下的路径一律现场拼（含 `read` 定位器返回的路径） |
| `works/` 的名字可以被人抄走 | 但**只有尾段是身份**：`<年>-<首作者>-<标题>-<work_key>` 里前几段是元数据的渲染，会随刷新变；尾段恒为 `work_key`，可反解（[ADR-0068](../决策/ADR-0068.md)） |

**`works/` 的下一层是投影目录**，名为 `<年>-<首作者>-<标题>-<work_key>`（各段的取值与清洗规则见 [ADR-0068](../决策/ADR-0068.md)）：**最后 20 位恒为 `work_key`**，是可反解的身份段；前面的段是展示记录的渲染，元数据一刷新就可能改名。本文其余处与其它文档一律写作 `works/<proj>/`。

命名与坐标见 [ADR-0033](../决策/ADR-0033.md)；硬链接与只读见 [ADR-0034](../决策/ADR-0034.md)。

## 3. 完整 schema

**表、键、字段与全库不变量见 [数据模型](数据模型.md)**（[IFACE-DATA](数据模型.md)）。本节只保留**为什么这些约束必须存在**：

- **禁止硬删 `record`**：删除一律标 `tombstone`——首领记录消失会让 `work_key` 失效（[ADR-0003](../决策/ADR-0003.md)）；
- **`run` 带 `spec_hash` 与 `refreshed` 两列**，供 `--refresh auto` 按检索式各记各的时间（[ADR-0043](../决策/ADR-0043.md)）；
- **`candidate` 没有状态列**：「要不要」只有 `dismissed_at` / `dismissed_until` 两个可空时间戳（[ADR-0044](../决策/ADR-0044.md)）；
- **`derived_content` 不装文本**：只留缓存键与 `sha256` 指针（[ADR-0045](../决策/ADR-0045.md)）。

## 4. 重建流程

本节是**灾难恢复顺序**，不是清理建议：`works/` 可完整重建；`sidecar.db` 可由重抓重建，代价是一次全量采集与重算；`bytes/` 无法本地重建，只能重新下载或重算。顺序与幂等键固定：

1. **`bytes/` 不重建**：它是唯一的字节实体，只在清理时按引用计数 GC；`verify` 抽样重算 `sha256`，校验它有没有被外部改写（[ADR-0034](../决策/ADR-0034.md)）。
2. **删 `works/` → 重投影**：按 `work_member` 与 `artifact` 拼出 `works/<proj>/`，把 `bytes/` 里的实体硬链接过去；目录名由 `work` 的成员记录现场算出（规则见 [ADR-0068](../决策/ADR-0068.md)），**不需要任何外部输入**。触发方式是**重跑 `read --work <work_key>`**（幂等；本地能重投影时不联网、命中缓存零成本），不设独立的重建命令（[ADR-0053](../决策/ADR-0053.md)、[ADR-0067](../决策/ADR-0067.md)）。
3. **删整个 sidecar → 重新抓取**：`record_uid` / `work_key` / `works/` 路径都由来源坐标派生，两台机器与两次重抓得到同一批 id。但 sidecar 是 `bytes/` **唯一的索引**——「从记录走到字节」的映射只在 `artifact` 与 `derived_content` 里，而 `bytes/` 的文件名只有 `sha256`。删库后字节文件仍在、`verify` 仍能过，却无法归属，必须重抓来源、重算内容才能靠内容寻址命中旧文件；译文与摘要的重算要再跑一次模型，来源已消失的那部分永久无主。重建不回来的还有本地决定——候选的 `dismissed_at` 与人工拆组（[IFACE-DATA §4](数据模型.md)）。
4. **清理顺序**：Windows 上删只读文件要先去只读；删 `works/` 不释放空间，GC 必须按 `bytes/` 的引用计数走（[ADR-0034](../决策/ADR-0034.md)）。

**可清理与不可清理**（判据是「删掉后能不能不花代价拿回来」）：`works/` 重投影即恢复；`data/runs/` 是留档，将来显式 GC；`bytes/` 只能在引用计数归零时逐实体回收；`sidecar.db` 与 `bytes/` 是主要资产，**默认不整体清理**——删库属第 3 条的灾难恢复，且会让 `bytes/` 变成无主字节。

启动时校验两件事：`bytes/` 与 `works/` 在同一个卷（硬链接不能跨卷），以及文件系统支持硬链接（不支持则降级为副本并告警）。

## 5. 落盘总表

**"落盘"分三层四类写，各有条件与幂等键**（[DESIGN §4.3.1](../02-设计说明书.md)）：sidecar 装事实与指针，`bytes/` 装字节，`works/` 装人读投影，Zotero 装用户资产。

| 触发 | 写什么 | 落到哪 | 幂等键 |
|---|---|---|---|
| 联网检索（`search` / `lookup` / `sync`） | 来源记录与标识别名 | sidecar `record` / `record_ident` | `(source, source_id)`、`(ns, value)` |
| 同上 | 候选行：首次入池 `run_id`（`search` / `lookup` / `sync` 三个入口都写，[ADR-0056](../决策/ADR-0056.md)）、评分、理由（**分级列初版不写**，[ADR-0051](../决策/ADR-0051.md)）；`dismissed_at` / `dismissed_until` 两个可空时间戳（**初版无写入入口**） | sidecar `candidate` | `work_key` |
| 每次运行 | 账本：请求参数、`spec_hash`、`refreshed`、花费、计数 | sidecar `run` | `run_id` |
| 命中已有候选时的刷新 | 引用数、`is_retracted`、OA 状态、`refreshed_at`、`seen_count`、`last_seen_at` | sidecar `record` / `candidate`（**更新，不新建**） | `work_key` |
| 原始响应留档 | 响应快照字节（只留产生被采纳记录的页与失败页），清单随 `run.json` 记 | `data/runs/<run_id>/responses/` | `sha256` |
| 每次运行（留档） | `run.json` + `report.md`（人读面），另刷新 `data/latest-report.md` | `data/runs/<run_id>/` | `run_id`（[ADR-0055](../决策/ADR-0055.md)） |
| `download`（「要原件」） | 抓来的原始字节（LaTeX 源码包 / arXiv HTML / PDF） | `bytes/`，投影到 `works/<proj>/source.*` | `sha256`；`artifact(record_uid, kind, sha256)`；`kind` 取 `source_*` |
| `read`（缺正文时） | 派生字节（`paper.md`、图件、图注） | `bytes/`，投影到 `works/<proj>/` | 同上；`kind` 取 `paper_md` / `figure` / `captions` |
| `read`（转换完成） | 绑定正文、图件与输入媒体的转换清单 | `bytes/` + `artifact` 索引；结构见 [IFACE-DATA §3.7](数据模型.md) | `artifact(record_uid, paper_manifest, sha256)`；成员先登记，清单最后登记 |
| `digest put` | 译文与中文摘要的文本 | `bytes/` + sidecar `derived_content` 指针 | `(content_hash, kind, lang, model_id, prompt_version, terms_version)`（[ADR-0054](../决策/ADR-0054.md)） |
| `export` / `bundle`（**初版不实现**，[ADR-0051](../决策/ADR-0051.md)） | 复制到用户指定路径 | 用户目录（快照，不是存储层） | — |
| `promote`（M5） | Zotero 条目与 provenance | Zotero；sidecar 记 `zotero_link` | `work_key` |

**不落的**：`bytes/` 与 `works/` 下的路径（一律现场拼）；`candidate` 的状态列（没有）；`derived_content` 的文本（在 `bytes/`）。

**「是否落盘」的判定不需要状态字段**：`record` 有行 = 见过；`candidate` 有行 = 入过池；`artifact` 有行 = 取过全文；`derived_content` 有行（`text` 为空）= 算过该派生文本。
