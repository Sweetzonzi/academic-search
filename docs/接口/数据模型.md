# sidecar 数据模型

> sidecar 是**一个 SQLite 文件**，也是全库唯一的查询入口（[IFACE-STORE §2](存储与迁移.md)）。本文件定义它的**语义与键**：有哪些表、一行代表什么、唯一键是什么、字段分几组、哪些字段必须能本地筛。
> 存储的不变量、身份公式、字节布局与重建流程见 [IFACE-STORE](存储与迁移.md)；命令与输出见 [IFACE](../03-接口契约.md)。

## 1. 范围与权威

- **本文件定语义，`src/**/schema.sql` 定物理形态。** 建表语句、类型、索引与 FTS5 虚表随实现落在代码旁（[DEV-CONV §2](../开发/约定.md)）；DDL 不得引入本文件没有的实体或唯一键，两者不一致时以本文件为准并修正 DDL。
- **每张表都有一个别处回答不了的问题。** 能被另一张表 join 出来的东西不建表。
- **不存在的表**：`text_cache`（全文缓存由 `artifact` 承担，[ADR-0029](../决策/ADR-0029.md)）；候选池的状态表与多值标签表（[ADR-0044](../决策/ADR-0044.md)、[ADR-0050](../决策/ADR-0050.md)）；专题实体（[ADR-0027](../决策/ADR-0027.md)）。
- **按里程碑分层**：初版（M0–M3）有 §3.1–§3.9；§3.10 的 `citation_edge` 属 M4（初版之外，[ADR-0046](../决策/ADR-0046.md)）；§3.11 的 `zotero_link` 属 M5。

## 2. 实体总览

四个坐标——**记录**（一份来源元数据）、**作品**（一组记录）、**内容**（一段字节）、**执行**（一次采集）：

| 表 | 一行是什么 | 唯一键 | 回答的问题 | 可变性 |
|---|---|---|---|---|
| `record` §3.1 | 某个来源给出的某篇论文的一份元数据 | `(source, source_id)`；对外 id `record_uid` | 这条来源记录抓过没有 | 只增；重新抓取只更新，不新建、不硬删 |
| `record_ident` §3.2 | 一条记录的一个标识别名 | `(ns, value)` | 这个 DOI / arXiv ID / W ID 命中过哪条记录 | 可增可删 |
| `work` §3.3 | 一组记录构成的「一篇作品」 | `work_key` | 这几条记录是不是同一篇 | 只增；合并只写 `merged_into`，不改键、不删行 |
| `work_member` §3.4 | 一条记录属于哪个组 | `record_uid` | — | 可改（重新分组只改 `work_key`） |
| `candidate` §3.5 | 一个 work 进过候选池 | `work_key` | 这篇推过没有 | 只增；`dismissed_*` 可更新 |
| `derived_content` §3.6 | 一段源文本配一组参数算过一次派生文本 | `(content_hash, kind, lang, model_id, prompt_version, terms_version)` | 这段原文算过了没有 | 只增可删（可重算） |
| `artifact` §3.7 | 一条记录贡献的一份字节产物 | `(record_uid, kind, sha256)` | 这份产物来自哪条记录 | 只增可删（可重抓） |
| `run` §3.8 | 一次采集执行 | `run_id` | 上次这个检索式什么时候刷过 | 只增；结束时写终值 |
| `dup_suspect` §3.9 | 一条记录与一个 work 疑似同篇（L2 登记） | `(record_uid, work_key)` | 哪两篇「可能同一篇」 | 可删（可重算） |
| `citation_edge` §3.10（M4） | 一条引用边 | `(src_work_key, dst_work_key, source)` | 谁引用了谁 | 可刷新（`retrieved_at`） |
| `zotero_link` §3.11（M5） | 一个 work 与一个 Zotero 条目的对应 | `work_key` | 入库了没有 | 可更新（`removed_at`） |

**外键方向**：`record_ident` / `work_member` / `artifact` → `record`；`work_member` → `work`；`candidate` / `dup_suspect` / `citation_edge` / `zotero_link` → `work`。没有指向外部系统的外键——Zotero 的 `itemKey` 在本库里只是一个值。

## 3. 逐表定义

### 3.1 `record` —— 一条来源记录

**一行 = 某个来源（arXiv / OpenAlex / Crossref / S2 / 出版社）给出的某一篇论文的一份元数据。** 键是它的来源坐标 `(source, source_id)`；对外 id `record_uid` 由该坐标确定性派生（公式与理由见 [IFACE-STORE §1](存储与迁移.md)）。同一篇论文来自多个来源就是多行，**各自保留、互不覆盖**（[ADR-0011](../决策/ADR-0011.md)）。

| 组 | 列 | 说明 |
|---|---|---|
| 身份 | `record_uid`、`source`、`source_id` | `record_uid` 唯一；写入后不再改变 |
| 首次见到 | `first_run_id` | 写入这条记录的那次 run；「最早见到」的排序依据，见下 |
| 书目 | `title`、`abstract`、`authors`、`published_at`、`updated_at`、`type`、`venue`、`language` | 原样保留；`authors` 是保序的 JSON 数组；`published_at` 是该源给出的**主日期**、`updated_at` 是该记录的最近更新；`type` 存**规范值**而非源原值（映射与逐源语义见 [IFACE-SOURCE](数据源适配.md)、[ADR-0052](../决策/ADR-0052.md)） |
| 分组缓存 | `title_key`、`first_author_surname` | 由书目列算出，可随时重算；**永不进任何唯一约束**（[DESIGN §4.2.3](../02-设计说明书.md)） |
| 质量与状态信号 | `cited_by_count`、`counts_by_year`、`fwci`、`citation_normalized_percentile`、`is_retracted`、`oa_status`、`pdf_url`、`metadata_conflict` | 刷新时覆盖；`is_retracted` 是安全信号，必查（[DESIGN §4.3.9](../02-设计说明书.md)） |
| 刷新簿记 | `refreshed_at`、`seen_count`、`last_seen_at`、`status` | `status` 取 `live` / `tombstone` |

- **不含 DOI / arXiv ID / W ID**：它们是别名，在 `record_ident`（§3.2）。
- **不含任何文本产物**：标题与摘要的原文留在库里（它是 FTS5 的索引源，也是 `content_hash` 的原像，[ADR-0045](../决策/ADR-0045.md)）；译文与中文摘要的字节在 `bytes/`。
- **「最早见到」由 `first_run_id` 排序**，同一 run 内再按 `record_uid` 字典序定序——首领因此唯一且可复现（§3.3）。`work_key` 在常态路径下不变，正是因为新记录总是加入已有组，不会成为首领。
- **禁止硬删**：删除一律把 `status` 置为 `tombstone`，行保留——首领记录消失会让 `work_key` 失效（[ADR-0003](../决策/ADR-0003.md)）。
- **重新抓取只更新不新建**：同一 `(source, source_id)` 的 v1 / v2 是同一条记录（[ADR-0011](../决策/ADR-0011.md)）。

### 3.2 `record_ident` —— 标识别名

**一行 = 一条记录的一个强标识。** 键 `(ns, value)`；`ns` 取值如 `openalex` / `doi` / `arxiv` / `pmid` / `s2`，`value` 用与 `source_id` 同一套归一化规则（[IFACE-STORE §1](存储与迁移.md)）。

- 角色是**索引**：给定一个强标识，唯一地找到一条记录，回答「这条网络结果记过没有」，并让去重的 L0 判据只做一次索引查询。
- `(ns, value)` 唯一意味着**一个别名至多指向一条记录**。两条记录共享同一别名时，先写入的那条持有它，后来者由 L0 判据直接归入同一 work——因此同一 work 内的其余记录不必重复登记同一个别名。
- L1（显式桥）命中后**把桥对面的标识补进来**，让下次反向查询直接命中（[DESIGN §4.2.2](../02-设计说明书.md)）。
- 可增可删：重新分组、来源换了 ID 都属于这一层的变化。

### 3.3 `work` —— 分组

**一行 = 一组记录，即「一篇作品」。** `work_key` 就是组内**最早见到**的那条记录的 `record_uid`，不另铸 id。

| 列 | 说明 |
|---|---|
| `work_key` | 主键；写入后**永不改写** |
| `merged_into` | 可空；合并时指向保留的那个 `work_key`。被合并的行**不删**，仍引用旧键的导出文件都能一跳解析回来（[ADR-0003](../决策/ADR-0003.md)） |

- **没有状态列**：「这几条记录是不是同一篇」由 §3.4 的成员关系回答，不由枚举回答。
- **面向用户的三个入口——检索结果、候选池推荐、阅读列表——返回 `work` 而不是 `record`**，所以同一篇论文不会因为来自两个源就出现两次。

### 3.4 `work_member` —— 成员关系

**一行 = 一条记录属于一个组。** 主键 `record_uid`（一条记录只属于一个 work），另有 `work_key` 与 `role`。

| 列 | 说明 |
|---|---|
| `record_uid` | 主键；外键 → `record` |
| `work_key` | 外键 → `work`；**重新分组只改这一列** |
| `role` | `primary`（首领，`work_key` 的来源）/ `preprint` / `published` / `duplicate` |

- 首领按「最早见到」定，**与「哪条是正式版」无关**：展示时用正式版记录的元数据，`work_key` 仍来自最早那条。
- 合并两个组 = 把被合并组的成员改指保留组，并在 `work` 上写 `merged_into`；**不改 `work_key`、不删记录**（[ADR-0003](../决策/ADR-0003.md)）。

### 3.5 `candidate` —— 候选池

**一行 = 一个 work 进过候选池。** 键 `work_key`。**行存在本身就是事实**，这里没有状态列（[ADR-0044](../决策/ADR-0044.md)）。

| 列 | 说明 |
|---|---|
| `work_key` | 主键；外键 → `work` |
| `first_run_id` | 入池的那次 run（[ADR-0028](../决策/ADR-0028.md)）；「新发现」= 本次 run 才入池 |
| `score`、`grade`、`reasons` | 评分、分级与理由（理由为 JSON）。**初版 `score` 与 `grade` 都不写**：质量判断整体顺延（[ADR-0051](../决策/ADR-0051.md)、[ADR-0053](../决策/ADR-0053.md)），排序按 `published_at` |
| `dismissed_at` | 空 = 没表过态；非空 = 不要（不再主动推荐，仍可被显式搜索到） |
| `dismissed_until` | 空 = 永久；非空 = 到期后允许重新浮现 |

- **`grade` 取 `A` / `B` / `C`**，随候选落库、**过滤在读取端**（`search --min-grade`，默认下限 `B`）；写入期不淘汰，掠夺性期刊黑名单无条件排除（[ADR-0044](../决策/ADR-0044.md)）。**初版只做硬排除**（撤稿、`paratext`/`erratum`、黑名单），分级与 `--min-grade` 顺延（[ADR-0051](../决策/ADR-0051.md)）。
- **没有方向标签**：一篇候选来自哪次运行、哪条检索式，由 `first_run_id` → `run.spec_hash` 回答（[ADR-0050](../决策/ADR-0050.md)）。
- **边界**：只装「入过池」与「表过态」两个事实，不长出 collection、标签树或引用格式化（[ADR-0032](../决策/ADR-0032.md)）。

### 3.6 `derived_content` —— 派生文本的缓存键

**一行 = 一段源文本配一组生成参数，算过一次派生文本。** 组合键 `(content_hash, kind, lang, model_id, prompt_version, terms_version)`，另有 `sha256` 指针。`kind` 含粒度、`terms_version` 来自译名表 `config/terms.toml`（[ADR-0054](../决策/ADR-0054.md)）。

```
content_hash = sha256(规范化后的源文本)      # 摘要原文 / 正文原文，按 kind 各算一次
```

- **文本本身不在库里**：译文与中文摘要的字节进 `bytes/`，本表只留缓存键与 `sha256`（[ADR-0045](../决策/ADR-0045.md)）。**不设 `text` 列**。
- **`content_hash` 而不是 `record_uid` 放在首位**：同一段原文出现在多条记录、甚至多个 work 下只算一次；原文一变自动失效；**顺序无关**（[ADR-0011](../决策/ADR-0011.md)）。
- **引用数与任何会随时间变的信号都不进键**：否则每次引用数变动都会触发全量重翻译（[DESIGN §4.3.9](../02-设计说明书.md)）。
- **与 `artifact` 的分工**：本表回答「这段原文配这组参数算过没有」（跨 work 共享，`digest list` 用 `LEFT JOIN` 找缺口），`artifact` 回答「这份产物来自哪条记录」（记录级溯源）。

### 3.7 `artifact` —— 产物溯源

**一行 = 一条记录贡献的一份字节产物。** 键 `(record_uid, kind, sha256)`。

| 列 | 说明 |
|---|---|
| `record_uid` | 外键 → `record`；这份产物**由哪条记录**采集或转换而来 |
| `kind` | 产物类型，**机器值**取 `extracted_text` / `paper_md` / `paper_html` / `source_tar_gz` / `figure` / `captions`（枚举唯一家见 [IFACE-PAYLOAD](输出载荷.md)） |
| `sha256` | 指向 `bytes/<sha 前2位>/<sha256>` 的字节实体 |
| `converter`、`converter_version` | 生成它的转换器与版本；换转换器即触发重转（[DESIGN §4.10](../02-设计说明书.md)） |

- **取产物** = 按 `(record_uid, kind)` 取 `converter_version` 与当前一致的那一行，再读 `bytes/`。
- **旧产物不删**：换了代表来源或转换器之后，旧字节留在 `bytes/` 里（可能仍被别的 work 引用）。
- **「要这篇」的证据就是这张表有行**：`textify` 的产物落盘后登记，不设 `kept` 状态（[ADR-0035](../决策/ADR-0035.md)）。
- 同一 work 的多条记录可以各自贡献产物（arXiv 源码、出版社 HTML、PDF）；**选哪条当代表写进 `record_uid`**，于是「这份 Markdown 是转的还是抽的」永远可追溯。

### 3.8 `run` —— 运行账本

**一行 = 一次采集执行**，`search` 与 `sync` 共用同一本账（[ADR-0049](../决策/ADR-0049.md)）。主键 `run_id`。

| 列 | 说明 |
|---|---|
| `run_id` | 主键；**单调递增整数** |
| `spec_hash` | `sha256(规范化后的检索式)`（字段排序、大小写归一、关键词排序）；`--refresh auto` 的判据按它各记各的时间（[ADR-0043](../决策/ADR-0043.md)） |
| `query_name` | 可空；`sync` 执行具名查询时记下查询名（[ADR-0027](../决策/ADR-0027.md)） |
| `refreshed` | 本次是否真的联网刷新过；`auto` 档跳过时置否，并在输出里标注 |
| `window_from`、`window_to` | 本次的发表时间窗口（回看 `lookback_days` 天，默认 30；首次运行用画像的 `since_years`）；报告分「新发表 / 新发现」两栏要靠它（[ADR-0028](../决策/ADR-0028.md)、[ADR-0055](../决策/ADR-0055.md)） |
| `started_at`、`finished_at`、`status` | `status` 取 `running` / `ok` / `failed` |
| `requests`、`cost_usd`、`cost_basis` | 请求数、花费与口径；输出信封的 `cost` 从这里取（[IFACE §1](../03-接口契约.md)） |
| `counts` | JSON：新增候选、各级计数、去重拦截、失败源与原因（[DESIGN §4.7](../02-设计说明书.md)） |
| `responses` | JSON 数组：本次留档的原始响应的 `{n, sha256, source, url, page, status}`；字节在 `data/runs/<run_id>/responses/`（只留产生被采纳记录的页与失败页，[ADR-0055](../决策/ADR-0055.md)） |
| `last_success_watermark` | 本次成功覆盖到的发表时间上界；失败的 run 不推进。**当前水位 = 最近一次成功 run 的该列**，不另存一份 |

- **`run_id` 是本库唯一的非派生标识符**：一次执行这个事件没有来源坐标，无法派生；它是本地单调序号，不承诺跨库可复现。语料事实（记录、作品、字节）的身份仍然全部可复现（[ADR-0003](../决策/ADR-0003.md)）。
- **原始请求进本表，原始响应快照落 `bytes/`**，两边合起来才回答得了「这次跑了什么、看到了什么」（[DESIGN §4.9](../02-设计说明书.md)）。
- **增量不依赖水位**：回看 N 天 + 本地去重本来就无状态（[ADR-0027](../决策/ADR-0027.md)），水位只用于观测与报告。

### 3.9 `dup_suspect` —— L2 待确认登记

**一行 = 一条记录与一个已有 work 疑似同一篇。** 键 `(record_uid, work_key)`；判据是 L2——`title_key` 命中、一作姓氏相同、年份落在窗口内，且强标识不冲突。

| 列 | 说明 |
|---|---|
| `record_uid`、`work_key` | 被怀疑的两方 |
| `evidence` | 命中的判据与取值（JSON），供人复核 |
| `detected_at` | 登记时间 |

- **不归组**：初版的 `group()` 只自动执行 L0 与 L1；L2 命中只登记，并在检索结果里标注「可能同一篇」（[ADR-0048](../决策/ADR-0048.md)）。
- **没有状态列**：L2 是记录字段的纯函数，登记可随时重算，**消除靠删除行**——不设 `resolved` / `merged` 这类枚举。
- 实测 L2 的假阳性约 4%，所以这条登记是**给人看的线索**，不是自动动作的输入（[DESIGN §4.2.3](../02-设计说明书.md)）。

### 3.10 `citation_edge`（M4，初版之外）

**一行 = 一条引用边。** 键 `(src_work_key, dst_work_key, source)`，另有 `retrieved_at`。

- 节点统一为 `work_key`：抓回来的 OpenAlex ID 先经 `record_ident` 解析；**没解析出来的目标节点暂存为待解析引用**，等它被检索到时再补，不为了建图去拉全库（[DESIGN §4.8](../02-设计说明书.md)）。
- **被引数会随对方合并 / 删除而变**，所以边带 `retrieved_at` 并可刷新。

### 3.11 `zotero_link`（M5）

**一行 = 一个 work 与一个 Zotero 条目的对应**（一个 work 只对应一个条目，[DESIGN §4.3.2](../02-设计说明书.md)）。主键 `work_key`。

| 列 | 说明 |
|---|---|
| `work_key` | 主键；外键 → `work` |
| `item_key`、`library_id` | Zotero 条目的稳定标识；外键用 `libraryID + itemKey`，不用自增 `itemID`（[DESIGN §4.3.3](../02-设计说明书.md)） |
| `zotero_attachment_key` | 可空；仅元信息条目本来就没有附件（[DESIGN §4.3.8](../02-设计说明书.md)） |
| `promoted_run_id` | 哪次 run 写进去的；按它可一键回滚 |
| `removed_at` | 可空；用户在 Zotero 里删了条目即记下——**不自动重新入库**，尊重删除决定 |

- **「已入库」由本表有行表达**，不设 `promoted` 状态（[ADR-0044](../决策/ADR-0044.md)）。
- 这是全库唯一一处「同一事实存在两处」的冗余（`work_key` ↔ `itemKey` 指针），方向单一：**只由 `promote` 写**（[ADR-0008](../决策/ADR-0008.md)）。

## 4. 全库不变量

这几条破坏即伤及身份稳定性或「查询只有一个入口」：

| 不变量 | 含义 |
|---|---|
| 没有随机铸造的标识符 | `record_uid` 由来源坐标派生，`work_key` 取首领记录的 `record_uid`，`sha256` 是字节自己的名字；`run_id` 是唯一的非派生标识——它标识的是一次执行事件，没有来源坐标（§3.8） |
| 禁止硬删 `record` 与 `work` | `record` 的删除标 `status = tombstone`，`work` 的合并只写 `merged_into`——两者的行都保留；首领记录消失会让 `work_key` 与所有历史导出失效 |
| 路径不落库 | 库里只存 `sha256`，`bytes/` 与 `works/` 下的路径一律现场拼（`read` 定位器返回的路径也不例外）；`works/` 路径不得被长期保存（[IFACE-STORE §2](存储与迁移.md)、[ADR-0053](../决策/ADR-0053.md)） |
| 面向用户只返回 `work` | 检索结果、候选池、阅读列表都以 `work_key` 为单位，`record` 不出现在任何用户界面里 |
| 候选池没有状态列 | 「要不要」只用 `dismissed_at` / `dismissed_until` 两个可空时间戳（[ADR-0044](../决策/ADR-0044.md)） |
| 库里不存派生文本 | 译文、中文摘要、全文都在 `bytes/`；`derived_content` 只留键与指针，`record` 只留源文本（[ADR-0045](../决策/ADR-0045.md)） |
| 一个事实一个家 | `record_ident` 是别名的家，`candidate` 是「入过池」的家，`artifact` 是「取过全文」的家；一个事实不允许有第二个字段表达 |

**「是否落盘」的判定不需要状态字段**：`record` 有行 = 见过；`candidate` 有行 = 入过池；`artifact` 有行 = 取过全文；`derived_content` 有行 = 算过该派生文本。

**整体删除 sidecar 之后**，语料部分可以重新抓取重建，而且 `record_uid` / `work_key` / `works/` 路径都会和原来一样（这正是确定性身份的意义）；**重建不回来的是本地决定**——候选的 `dismissed_at` 与人工拆组的结果，它们在任何来源里都没有原像。

## 5. 检索面：FTS5 与本地筛选

**FTS5 虚表只覆盖 `record` 的英文原文**（`title`、`abstract`），用默认 `unicode61` 分词器。中文翻译与中文摘要不进索引（[ADR-0042](../决策/ADR-0042.md)、[ADR-0045](../决策/ADR-0045.md)），检索由 agent 用英文发起。

**必须能本地筛的字段**（本地优先的前提：只在有缺口时才联网）：

| 筛什么 | 落在哪 | 备注 |
|---|---|---|
| 关键词 | `record.title` / `record.abstract` | 走 FTS5；中文查询先由 agent 翻成英文 |
| venue | `record.venue` | 白名单与掠夺性黑名单都在读取端判 |
| 作者 | `record.authors` | 至少要能按姓氏匹配 |
| 年份 | `record.published_at` | **不进任何唯一索引或幂等键**——发表时间会变（预印本 → 正式版实测可前跳三年、也可倒退两个月，[ADR-0028](../决策/ADR-0028.md)） |
| 来源 | `record.source` | 每条结果都标出它来自哪个来源 |
| 质量分级 | `candidate.grade` | 默认下限 `B`，放宽走 `--min-grade`；**初版该列不写、该筛选不生效**（[ADR-0051](../决策/ADR-0051.md)） |
| 排序 | `record.published_at`（组内最早）／聚合后的引用数 | 默认按主日期降序，`--sort citations` 可切（[ADR-0053](../决策/ADR-0053.md)） |
| 撤销与 OA 状态 | `record.is_retracted` / `record.oa_status` | 安全信号，读取端可筛 |

- **正文检索不走 SQLite**：`--in body` 对 `works/` 做线性子串扫描（[ADR-0036](../决策/ADR-0036.md)）。
- **两个索引不能省**：`record_ident(ns, value)` 让去重不扫全表，`candidate(work_key)` 让「推过没有」是一次主键查询。

## 6. 迁移与重建

- **版本号**：整库有一个 `schema_version`（代码侧对外的 `SCHEMA_VERSION` 是另一件事，只增不删，见 [IFACE §1](../03-接口契约.md)）；迁移脚本由该版本驱动。
- **迁移只加表、加列、加索引**，不改唯一键、不改 `record_uid` 的派生规则——后者是破坏性变更，老 id 与老 `works/` 路径要一起批量重命名（[RISK](../07-风险登记册.md)）。
- **索引与投影都可以丢，身份不能丢**：`works/` 的重投影、`bytes/` 的校验与整体重建流程见 [IFACE-STORE §2–§4](存储与迁移.md)。
- **落盘总表**（触发 → 写什么 → 落到哪 → 幂等键）在 [IFACE-STORE §5](存储与迁移.md)：那是「某一刻发生了什么」的视图，本文件是「库里长什么样」的视图，两者描述同一批表。
