# 输出载荷

> 信封（`{ok, command, schema, data|error}`）与命令清单见 [IFACE](../03-接口契约.md)；本文回答信封里**装什么**：结果条目、`run.json`、`digest` 与 `read` 的载荷，以及**全部机器枚举值**。`SCHEMA_VERSION` 的「只增不删」以本文为对象（[ADR-0053](../决策/ADR-0053.md)）。
>
> **状态：草案。** 字段名与取值一旦被实现引用就只能增、不能改语义。

## 1. 通用字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `ok` | bool | 成功与否；失败时 `data` 缺席、`error` 出现。**部分源失败或降级不算失败**：主链路产出正常即 `ok=true`、退出码 0，失败源进 `counts.failures[]`、降级进 `degraded`（[ADR-0056](../决策/ADR-0056.md)） |
| `command` | string | 命令名（含子命令，如 `digest.list`） |
| `schema` | int | 当前 `1` |
| `network` | bool | **检索类命令必带**：本次是否发过网络请求 |
| `cost` | object | `{usd, basis, requests}`；`basis` 说明口径（如"按 OpenAlex 计费档估算"） |
| `degraded` | object? | 仅降级时出现：`{reason}`。**两类降级都走这里**：余额不足只查本地（如"余额不足，只查本地"）、`--refresh auto` 因新鲜度跳过联网（如"同一检索式在新鲜度窗口内，跳过联网"）。降级不改退出码（[ADR-0056](../决策/ADR-0056.md)） |

## 2. 结果条目（`search` / `lookup` 的 `data.items[]`）

| 字段 | 类型 | 说明 |
|---|---|---|
| `work_key` | string | 作品的稳定键（[ADR-0003](../决策/ADR-0003.md)） |
| `title` / `authors[]` / `venue` / `language` | — | 按 [IFACE-SOURCE §5](数据源适配.md) 的聚合规则合成 |
| `published_at` | date | 组内最早的主日期（"新论文"语义） |
| `updated_at` | date? | 组内记录 `updated_at` 的最大值（聚合规则见 [IFACE-SOURCE §5](数据源适配.md)） |
| `type` | enum | 规范值，见 §7 |
| `doi` / `arxiv_id` / `openalex_id` | string? | 来自 `record_ident` 的别名，可空 |
| `oa_status` / `pdf_url` | string? | 可空 |
| `is_retracted` | bool | **或运算**结果；真即不该被推荐 |
| `cited_by_count` | int? | 组内取最大；只有 OpenAlex 记录有值，arXiv-only 的条目为 `null`（[ADR-0052](../决策/ADR-0052.md)） |
| `sources[]` | array | 每条记录一行：`{source, source_id, first_seen, role}`，用于"这篇来自哪几条记录" |
| `first_seen` / `last_seen` | date | 首次与最近一次见到的 **run 日期** |
| `dup_suspect` | bool | L2 弱判据命中：结果为"可能同一篇"，**不合并**（[ADR-0048](../决策/ADR-0048.md)） |
| `abstract` | string? | **按需出现**：`lookup` 固定带**完整**摘要；`search` 只在开了 `--abstract` 时带，且**截断**到 `config/search.toml` 的 `abstract.chars` 个字符；其余情况该**键缺席**（不是 `null`）。多篇成员的摘要不一致时按 [ADR-0058](../决策/ADR-0058.md) 两级取值。**实现未到**：当前 `lookup` / `search` 都不带这个键 |
| `score` / `grade` | — | **初版不出现**（[ADR-0051](../决策/ADR-0051.md)、[ADR-0053](../决策/ADR-0053.md)） |

排序：默认按 `published_at` 降序；`--sort citations` 时按聚合后的 `cited_by_count` 降序（无值的排后）。

**不给检索式 = 列本地库全部**：`all_of` / `any_of` 都为空时跳过 FTS 过滤，返回本地所有 `live` work（条数仍受 `--limit` 限制，默认 20）。这一档只配 `--refresh false`；空关键词（如 `--all-of ""`）不属此列，会落到 FTS 报错。

**摘要怎么出**：取 `record.abstract`（[IFACE-DATA](数据模型.md)），规则见 [ADR-0058](../决策/ADR-0058.md)——`lookup` 带完整摘要，`search` 需 `--abstract` 且为截断版。**摘要可能不是逐字符原文**：多来源取值的两级顺序是「版本层级（`published` > `preprint`）→ 文本保真度（`arxiv` 原生 > `crossref` 原生 > `openalex` 由 `abstract_inverted_index` 还原）」，因此给出来的既可能是预印本稿、也可能是 OpenAlex 的还原产物；**载荷不带标记**，要逐字符引用时请回到原文核对。正文始终不进载荷（[ADR-0057](../决策/ADR-0057.md)）：正文走 `textify` + `read`，中文摘要走 `digest`（未接线）。

`data` 除 `items` 外：`network` / `cost` 见 §1；**本次联网刷新过**时另有 `counts`，与 §3 的 `counts` 同形（`{new_candidates, dedup_blocked, by_source:{}, failures:[{source, reason}]}`），离线查库时不出现。

## 3. `run.json`

落 `data/runs/<run_id>/run.json`（[ADR-0055](../决策/ADR-0055.md)），字段与 [数据模型 §3.8](数据模型.md) 的 `run` 行一一对应：

`{run_id, command, queries[], spec_hash[], refreshed, window:{from,to}, timezone, started_at, finished_at, status, counts:{new_candidates, dedup_blocked, by_source:{}, failures:[{source, reason}]}, cost:{usd, basis, requests}, responses:[{n, sha256, source, url, page, status}]}`

- 时间字段一律 UTC（ISO-8601 带 `Z`）；`timezone` 记渲染报告用的本地时区。
- `report.md` 的头部与 `run.json` 同源：run_id、窗口、时区、各级计数、失败源。
- `responses[]` 只列被留档的页（产生被采纳记录的页与失败页）。

**`sync` 的 stdout 信封**：`data` 是上面这份 `run.json` 的**真子集**——去掉 `responses`、去掉 `timezone` 与时间字段，字段名逐字相同，另可带 `degraded`：

`{run_id, status, queries[], spec_hash[], refreshed, window:{from,to}, counts:{new_candidates, dedup_blocked, by_source:{}, failures:[{source, reason}]}, cost:{usd, basis, requests}}`

- `run.json`（落盘）是唯一权威；stdout 只供调度器与 agent 一眼判断成败（[ADR-0056](../决策/ADR-0056.md)）。
- **不含路径字段**：`data/runs/<run_id>/` 由 `run_id` 现场拼（[IFACE-STORE §2](存储与迁移.md)）。

## 4. `digest` 载荷

- `digest list` → `data.items[] = {work_key, kind, lang, content_hash, source_text, chars, terms_version}`；按缓存键去重，缺哪个就列哪个。
- `digest put` ← stdin（或 `--file`）读 JSON：`{items:[{work_key, kind, lang, model_id, prompt_version, text}]}`。**不接受调用方给的 `content_hash`**：CLI 按 `work_key` 现算（[ADR-0056](../决策/ADR-0056.md)）。
- `digest put` → `data = {written, skipped:[{index, reason}]}`；`reason` 取固定枚举 `not_found` / `no_source_text`（键由 CLI 现算，故不存在「键不匹配」这一档）。文本落 `bytes/`、指针进 `derived_content`（[ADR-0045](../决策/ADR-0045.md)）。
- `source_text` 取哪条记录见 [IFACE-SOURCE §5](数据源适配.md)；**不截断**（截断会让 `content_hash` 失去意义），超预算用 `--limit` 控制。
- **边界**：CLI 能保证缓存键算得对，**不能**判断 `text` 是否真的属于该 `work_key`——那由 `put` 的调用方负责。

## 5. `read` 载荷（定位器）

`data = {work_key, doc:{path, work_path?, sha256, size, artifact_kind, converter_version}, figures:[{ref, path, caption?, sha256}], anchors:[{kind:"sec"|"page", label, line}], front_matter:{}}`

- `doc.path` 指向 `bytes/` 里的实体（权威、保证存在）；`doc.work_path` 仅在 `works/` 投影存在时出现。
- `figures[].ref` 是 Markdown 里的引用名（如 `figures/fig-01.svg`），`path` 是它对应的 `bytes/` 路径——**从内容坐标读时靠它取图**。
- `anchors[].line` 是 1 起的行号，只在本次返回的 `sha256` 上有效。
- 投影缺失：`ok=false`、`error.code=projection_missing`，附修复提示 `textify --work <work_key>`（[ADR-0053](../决策/ADR-0053.md)）。

## 6. 错误码

**信封上的退出码只有 0 与 1**，含义是「这次运行有没有产出可用的东西」；细分靠 `error.code`（[ADR-0056](../决策/ADR-0056.md)）。**参数解析失败是例外**：argparse 在进 `main` 之前就退出，退出码 **2**、usage 写 stderr、**没有信封**（实测 2026-10-16）——「有没有信封」不能只看退出码非零。下表只列 `error.code`——`source_error` / `network_error` / `rate_limited` 在**仍产出结果**时不走本表，只记进 `counts.failures[]` / `degraded`。

| code | 含义 | 退出码 | 重试同一命令 | 若否，先做什么 |
|---|---|---|---|---|
| `busy` | 写锁被占用（另一个 run 在跑） | 1 | ✅ 稍后一次 | — |
| `projection_missing` | `works/` 投影缺失 | 1 | ❌ 重试无用 | 先跑 `textify --work <work_key>` |
| `no_profile` | 没有画像 | 1 | ❌ | 引导生成画像 |
| `profile_invalid` | 画像解析失败（附出错行） | 1 | ❌ | 修文件后重跑 `profile check` |
| `invalid_args` | 参数不合法 | 1 | ❌ | 改参数 |
| `not_found` | 标识或 `work_key` 未命中 | 1 | ❌ | 换标识，或先 `search` 联网取 |
| `source_error` | 全部源都失败、零写入 | 1 | ✅ | — |
| `network_error` | 网络不可达 | 1 | ✅ | — |
| `rate_limited` | 429 或余额耗尽且无法降级 | 1 | ✅ 稍后 | — |
| `io_error` | 本地读写失败（含只读属性、跨卷硬链接） | 1 | ❌ | 排查路径与权限 |
| `internal_error` | 未分类缺陷 | 1 | ❌ | 报缺陷 |

## 7. 机器枚举（唯一家）

| 枚举 | 取值 |
|---|---|
| `type` | `article` / `preprint` / `chapter` / `thesis` / `paratext` / `other` |
| `record_ident.ns` | `openalex` / `doi` / `arxiv` / `pmid` / `pmcid` / `s2` |
| `artifact.kind` | `extracted_text` / `paper_md` / `paper_html` / `source_tar_gz` / `figure` / `captions` |
| `derived kind` | `title` / `abstract` / `summary.oneline` / `summary.points` / `summary.mrl` |
| `lang` | BCP-47（`zh` 默认 / `en`） |
| `run.status` | `running` / `ok` / `failed` |
| `record.status` | `live` / `tombstone` |
| `work_member.role` | `primary` / `preprint` / `published` / `duplicate` |

## 8. profile 载荷

`profile` 是画像的**只读**通道（CLI 不写配置，[ADR-0040](../决策/ADR-0040.md)）；查询字段见[配置目录](../使用/配置.md) §1。

- `profile show` → `data = {queries:[…]}`；无画像时 `ok=false`、`error.code=no_profile`。
- `profile check` → 成功时 `data = {queries:[…]}`；失败时 `ok=false`、`error.code=profile_invalid`，`error.message` 逐条列出**出错行号与原因**。
- `profile scaffold` → `data = {template}`，`template` 是带注释的 `profile.toml` 模板原文。

## 9. 版本规则

- 本文定义的字段与枚举**只增不删**；改语义等于换 `SCHEMA_VERSION`，并附迁移说明。
- **未在本文定义的字段不得出现在信封里**：实现即兴加的字段会变成事实上的契约，而它没有家。
