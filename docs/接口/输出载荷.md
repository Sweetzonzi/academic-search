# 输出载荷

> 信封（`{ok, command, schema, data|error}`）与命令清单见 [IFACE](../03-接口契约.md)；本文回答信封里**装什么**：结果条目、`run.json`、`digest` 与 `download`／`read` 的载荷，以及**全部机器枚举值**。`SCHEMA_VERSION` 的「只增不删」以本文为对象（[ADR-0053](../决策/ADR-0053.md)）。
>
> **状态：草案。** 字段名与取值一旦被实现引用就只能增、不能改语义。

## 1. 通用字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `ok` | bool | 成功与否；失败时 `data` 缺席、`error` 出现。**部分源失败或降级不算失败**：主链路产出正常即 `ok=true`、退出码 0，失败源进 `counts.failures[]`、降级进 `degraded`（[ADR-0056](../决策/ADR-0056.md)） |
| `command` | string | 命令名（含子命令，如 `digest.list`） |
| `schema` | int | 当前 `1` |
| `network` | bool | **单 run 命令（`search` / `lookup` / `download` / `read`）必带**：本次是否发过网络请求。`sync` 一次调用含多条 run，它的 `network` 就是 `runs[].refreshed` 的或，不另给顶层字段（§3，[ADR-0066](../决策/ADR-0066.md)） |
| `cost` | object | `{usd, basis, requests}`；`requests` 计实际发起的请求，包含 HTTP 错误与网络失败；`basis` 说明口径（如"按 OpenAlex 计费档估算"）。**单 run 命令必带**；`sync` 逐 run 放在 `runs[].cost`，不设调用级合计 |
| `degraded` | object? | 仅降级时出现：`{reason}`。包括余额不足整次跳过或只完成部分来源、`--refresh auto` 因新鲜度跳过联网、`--title` 配 `--refresh true` 时只能查本地（标题不是标识，用不了单实体 GET，[ADR-0065](../决策/ADR-0065.md)）。是否实际联网结合 `network` / `refreshed` 与请求数判断；降级不改退出码（[ADR-0056](../决策/ADR-0056.md)） |
| `warnings` | string[]? | `search` / `lookup` 成功返回中的人读提示列表，位于 `data.warnings`；没有提示时省略。具体触发条件见 §2；字符串供展示，不作为机器判据 |

## 2. 结果条目（`search` / `lookup` 的 `data.items[]`）

| 字段 | 类型 | 说明 |
|---|---|---|
| `work_key` | string | 作品的稳定键（[ADR-0003](../决策/ADR-0003.md)） |
| `title` / `authors[]` / `venue` / `language` | — | 按 [IFACE-SOURCE §5](数据源适配.md) 的聚合规则合成 |
| `published_at` | date | 组内最早的主日期（"新论文"语义） |
| `updated_at` | date? | 组内记录 `updated_at` 的最大值（聚合规则见 [IFACE-SOURCE §5](数据源适配.md)） |
| `type` | enum | 规范值，见 §7 |
| `doi` / `arxiv_id` / `openalex_id` | string? | 来自 `record_ident` 的别名，可空 |
| `oa_status` / `pdf_url` | string? | 可空 |
| `is_retracted` | bool | **或运算**结果；真即不该被推荐 |
| `cited_by_count` | int? | 组内取最大；只有 OpenAlex 记录有值，arXiv-only 的条目为 `null`（[ADR-0052](../决策/ADR-0052.md)） |
| `fwci` | float? | 同上取最大；它是 `--min-fwci` 的判定依据，也让人能复核阈值筛掉了什么（[ADR-0061](../决策/ADR-0061.md)）。与之同义的 `citation_normalized_percentile` **不进载荷**（同 ADR 的否决项） |
| `sources[]` | array | 每条记录一行：`{source, source_id, first_seen, role}`，用于"这篇来自哪几条记录" |
| `versions` | object? | **只有 `lookup` 带**：`{remote, local}`——`remote` 是 `record.source_version`，`local` 是本地已有产物对应的版本；没有该侧信息时为 `null`（[ADR-0067](../决策/ADR-0067.md)） |
| `first_seen` / `last_seen` | date | 首次与最近一次见到的 **run 日期** |
| `dup_suspect` | bool | L2 弱判据命中：结果为"可能同一篇"，**不合并**（[ADR-0048](../决策/ADR-0048.md)） |
| `abstract` | string? | **按需出现**：`lookup` 固定带**完整**摘要；`search` 只在开了 `--abstract` 时带，且**截断**到 `config/search.toml` 的 `abstract.chars` 个字符；其余情况该**键缺席**（不是 `null`）。多篇成员的摘要不一致时按 [ADR-0058](../决策/ADR-0058.md) 两级取值 |
| `score` / `grade` | — | **初版不出现**（[ADR-0051](../决策/ADR-0051.md)、[ADR-0053](../决策/ADR-0053.md)） |

排序：默认按 `published_at` 降序；`--sort citations` 时按聚合后的 `cited_by_count` 降序（无值的排后）；主排序值相同时按 `work_key` 升序。排序在**候选集**上做，候选由本地候选预算截断（`[local] max_candidates`，[ADR-0070](../决策/ADR-0070.md)）；`counts.local.truncated=true` 时，排序与分页只覆盖看过的候选。

**本地分页**：采用 [ADR-0073](../决策/ADR-0073.md) 的 offset / limit 展示规则，不新增结果条目字段或计数模式。`counts.local.matched` 保持展示切片前的匹配数，`returned` 表示实际返回数，预算截断的含义不变。数据库变化可能改变页边界，不提供跨命令快照。

**不给检索式 = 列本地库全部**：`all_of` / `any_of` 都为空时跳过 FTS 过滤，返回本地所有 `live` work（条数仍受 `--limit` 限制，默认 20）。这一档只配 `--refresh false`；显式给空字符串或全空白关键词返回 `invalid_args`。

**摘要怎么出**：取 `record.abstract`（[IFACE-DATA](数据模型.md)），规则见 [ADR-0058](../决策/ADR-0058.md)——`lookup` 带完整摘要，`search` 需 `--abstract` 且为截断版。**摘要可能不是逐字符原文**：多来源取值的两级顺序是「版本层级（`published` > `preprint`）→ 文本保真度（`arxiv` 原生 > `crossref` 原生 > `openalex` 由 `abstract_inverted_index` 还原）」，因此给出来的既可能是预印本稿、也可能是 OpenAlex 的还原产物；**载荷不带标记**，要逐字符引用时请回到原文核对。正文始终不进载荷（[ADR-0057](../决策/ADR-0057.md)）：正文走 `download` + `read`，中文摘要走 `digest`（未接线）。

`data` 除 `items` 外：`network` / `cost` 见 §1；`search` 的 `counts` **恒出现**，其中 `local` 段是本地漏斗（[ADR-0070](../决策/ADR-0070.md)）：`{considered, matched, returned, truncated, venue_filtered_out}`——`considered` 是候选预算内的 work 数、`matched` 是过滤后、`offset` / `limit` 切片前的 work 数、`returned` 是实际条数、`truncated` 表示预算用尽（可能还有没看的匹配）、`venue_filtered_out` 是文本命中但载体不含白名单的 work 数。**进入采集流程**时另有 `new_candidates` / `dedup_blocked` / `by_source` / `failures` / `complete`（与 §3 同形）；全部来源被条件排除时也保留这些字段，但 `network=false`。离线与新鲜度跳过时只有 `local`。`lookup` 的 `counts` 只在本次刷新时出现，没有 `local` 与 `complete`。

**`warnings` 的触发条件**：

- `search` 进入采集流程且实际因引用阈值或载体白名单跳过所选 arXiv 来源：说明该接口不提供相应引用指标或用于白名单判定的载体信息，以及触发的参数；多个限制合并为一条。只选 OpenAlex、离线、新鲜度命中或额度在采集前阻止整次刷新时，不声称跳过了 arXiv 采集。仅 `--sort citations` 不跳过 arXiv；其采集仍按日期取数，本地缺少引用指标的结果排在末尾。
- `search` 的 `counts.local.truncated=true`：说明候选预算耗尽，排序和分页只覆盖已检查候选；即使返回空列表也可能还有未检查的匹配项。
- `search` / `lookup` 成功结果的 `counts.failures[]` 非空：按来源合并说明请求失败、结果覆盖可能不完整。全部来源失败时仍按既有错误路径处理。
- `search` 实际以匿名档向 OpenAlex 发出过请求（当次进程里没有 key）：说明本次请求没带凭据、匿名额度按出口 IP 共享，并给出补注入的入口。429 与“用户没配 key”在响应上不可区分，只有这条事实能把两者分开；它不改变 `degraded`，也不改变 `counts`。
- `search` 因额度在采集前停止或中途停止：说明未执行或未完成远端采集、结果覆盖可能不完整；以实际执行状态区分两者。
- `lookup --title ... --refresh true` 成功返回本地匹配：复用 `degraded.reason` 说明标题查询无法执行远端刷新。

同类提示合并，完全相同的字符串去重。正常离线、新鲜度复用、常规筛选与零结果本身不产生提示。`warnings` 不改变 `ok`、退出码、`counts`、`degraded` 或缓存身份，也不写入账本和 `sync` 留档；机器处理继续使用既有结构化字段。更多来源状态与覆盖信息归 [PLAN §4.3](../04-里程碑与计划.md) 的 S5。

## 3. `run.json`

落 `data/runs/<run_id>/run.json`（[ADR-0055](../决策/ADR-0055.md)），字段与 [数据模型 §3.8](数据模型.md) 的 `run` 行一一对应。**一次 run 对应一条检索式**：一次 `sync` 跑几条具名查询就写几行 `run`、几个目录（[ADR-0066](../决策/ADR-0066.md) 决策 1）：

`{run_id, command, query, spec_hash, refreshed, window:{from,to}, timezone, started_at, finished_at, status, counts:{new_candidates, dedup_blocked, by_source:{}, failures:[{source, reason}], complete}, cost:{usd, basis, requests}, responses:[{n, sha256, source, url, page, status}], items:{new_published:[…], new_discovered:[…]}}`

- `query` 只有 `sync` 填（具名查询名）；`search` / `lookup` 的 run 为 `null`。
- **首次回溯的身份**：`sync` 只用同时匹配当前查询名与 `spec_hash` 的完整采集行判断是否已完成首次回溯；没有该行时用画像的 `since_years`，有该行后用 `lookback_days`。同名查询改变条件或来源时重新回溯，见 [ADR-0072](../决策/ADR-0072.md)。
- **采集完整性**：`search` / `sync` 进入采集流程时，`counts.complete` 为 bool；仅实际发起请求、未被条件排除的来源均成功完成本次规定的一页、且没有因额度停止时为 `true`。成功空页也算完成，全部来源被排除不算；这不证明远端全库召回完整。离线与新鲜度跳过的账本 `counts={}`。只有 `status=ok`、`refreshed=true`、`requests>0` 且 `counts.complete=true` 的行可作为新鲜度与首次回溯完成的依据。缺少此标记的历史行不作该依据，已有语料保留，后续按需重新采集；不需要数据库迁移。部分成功仍可 `status=ok`，下次 `auto` 没有完整采集依据时会重新查询整条检索式，逐源补查尚未实现。
- `items` 是 [ADR-0028](../决策/ADR-0028.md) 的两栏：**新发表**（`publication_date` 落在本次窗口内）与**新发现**（本次 run 才入池、发表更早）。条目取 §2 的**可溯源最小集**（`work_key`、`title`、`published_at`、`doi`、`arxiv_id`、`sources[]`），不带摘要与正文，按 `published_at` 降序（[ADR-0066](../决策/ADR-0066.md) 决策 3）。

- 时间字段一律 UTC（ISO-8601 带 `Z`）；`timezone` 记渲染报告用的本地时区。
- `report.md` 的头部与 `run.json` 同源：run_id、窗口、时区、各级计数、失败源；正文两栏用 `items` 的同一份数据渲染。**每条 run 一份**，落在自己的 `data/runs/<run_id>/`。
- `data/latest-report.md` 是**最近一次调用**的汇总：按查询分节，每节就是对应 run 的 `report.md` 内容（[ADR-0066](../决策/ADR-0066.md) 决策 5）。
- `responses[]` 只列被留档的页（产生被采纳记录的页与失败页）；`n` 从 1 起按请求顺序，`page` 初版恒为 `1`。
- `responses[].url` 是**请求 URL**，但查询串里的凭据（`api_key` 等）记作 `REDACTED`：留档落在 `data/runs/`，那是会被备份、会被人读的目录（[ADR-0066](../决策/ADR-0066.md) 决策 10）。

**`sync` 的 stdout 信封**：一次调用跑多条查询、写多行 `run`，因此 `data.runs[]` **逐 run 自包含**，每个元素是上面那份 `run.json` 的**真子集**——去掉 `command`、`responses`、`timezone`、时间字段与 `items`，字段名逐字相同，另可带调用级的 `degraded`：

`{runs:[{run_id, status, query, spec_hash, refreshed, window:{from,to}, counts:{new_candidates, dedup_blocked, by_source:{}, failures:[{source, reason}], complete}, cost:{usd, basis, requests}}, …], degraded?:{reason}}`

- **不设调用级 `counts` / `cost` 合计**：合计是逐 run 值的纯折叠（求和 / 拼接），两处记同一个数就会漂；要总数由调用方自己求和（[ADR-0066](../决策/ADR-0066.md) 决策 4）。
- **结果清单不进 stdout**（[ADR-0056](../决策/ADR-0056.md) 决策 1 不变）；要清单读落盘的 `run.json`。
- `run.json`（落盘）是唯一权威；stdout 只供调度器与 agent 一眼判断成败。
- **不含路径字段**：`data/runs/<run_id>/` 由 `run_id` 现场拼（[IFACE-STORE §2](存储与迁移.md)）。

## 4. `digest` 载荷

- `digest list` → `data.items[] = {work_key, kind, lang, content_hash, source_text, chars, terms_version}`；按缓存键去重，缺哪个就列哪个。
- `digest put` ← stdin（或 `--file`）读 JSON：`{items:[{work_key, kind, lang, model_id, prompt_version, text}]}`。**不接受调用方给的 `content_hash`**：CLI 按 `work_key` 现算（[ADR-0056](../决策/ADR-0056.md)）。
- `digest put` → `data = {written, skipped:[{index, reason}]}`；`reason` 取固定枚举 `not_found` / `no_source_text`（键由 CLI 现算，故不存在「键不匹配」这一档）。文本落 `bytes/`、指针进 `derived_content`（[ADR-0045](../决策/ADR-0045.md)）。
- `source_text` 取哪条记录见 [IFACE-SOURCE §5](数据源适配.md)；**不截断**（截断会让 `content_hash` 失去意义），超预算用 `--limit` 控制。
- **边界**：CLI 能保证缓存键算得对，**不能**判断 `text` 是否真的属于该 `work_key`——那由 `put` 的调用方负责。

## 5. 全文产物载荷（`download` / `read`）

### 5.1 `download`（原件）

`data = {work_key, record_uid, arxiv_id, artifacts:[{kind, status, source_version, sha256?, size?, path?, work_path?, source?, reason?}], network, cost}`

- `artifacts[]` **逐取件路线一行**（[ADR-0067](../决策/ADR-0067.md) 决策 6）：`--source all` 列三条；`auto` 回退时能同时看到 LaTeX 那条为什么没成。`kind` 取 `source_tar_gz` / `source_html` / `source_pdf`（§7）。
- `status` 取 `fetched`（这次取的）／`reused`（命中缓存，含条件 GET 回来的 304）／`failed`（没取到，附 `reason` 与 `source`，后者是取件路线 latex/html/pdf）。
- `source_version` **恒出现**，未知时为 `null`（取值规则见 [IFACE-DATA §3.7](数据模型.md)）。
- `path` 指向 `bytes/` 里的实体；`work_path` 只在投影存在时出现。两者都现场拼，不落库（[IFACE-STORE §2](存储与迁移.md)）。
- **全部路线都失败时 `ok=false`**：`--refresh false` → `projection_missing`；其余 → `source_error`（§6）。

### 5.2 `read`（定位器）

`data = {work_key, doc:{path, work_path?, sha256, size, artifact_kind, converter_version, source_version, remote_version, stale}, figures:[{ref, path, caption?, sha256}], anchors:[{kind:"sec"|"page", label, line}], front_matter:{}, network, cost, warnings?}`

- `doc.work_path` 仅在 `works/` 投影完整可用时出现，是人和 agent 默认阅读的 `paper.md`；图片可从其父目录按正文相对引用打开。`doc.path` 指向 `bytes/` 里的实体（权威、保证存在），投影不可用时作为回退。两份正文逐字节相同，均只读；当前路径按本次定位器获取，长期身份用 `work_key`。
- `figures[].ref` 是 Markdown 里的引用名（如 `figures/fig-01.svg`），`path` 是它对应的 `bytes/` 路径——**回退到内容坐标读时靠它取图**。
- `anchors[].line` 是 1 起的行号，只在本次返回的 `sha256` 上有效。
- LaTeX 路线的 `anchors[].label` 与交叉引用共用完整源码标题大纲，有无 `\label` 均参与编号；附录采用字母体系。未编号的段落按“最近的已编号祖先 · 标题”定位（如 `F.1 · Revisiting benchmark.`），不生成论文中不存在的节号。显式 `secnumdepth` 按源码取值；自定义类内部编号宏尚未全面解析。标题无法对齐时保留标题定位并返回警告，不猜数字；定位器中的 `id:` 后缀保留输出标签原值。
- `doc.source_version` / `doc.remote_version` / `doc.stale`：本地这份产物的版本、`record.source_version`、以及「有没有证据表明落后」。**`stale` 只在两侧版本都非空且不等时为 `true`**；未知的一侧为 `null`，另一侧保留已知值，`stale=false` 不证明最新（[ADR-0074](../决策/ADR-0074.md)）。
- `warnings` 是可选的字符串数组，说明转换缺损、路线回退、版本未知或陈旧、缺少转换器与投影降级。缺图、未解析引用、未渲染的 PDF 图不会让非空正文失败；HTML 公式尚未全面验证，固定提示该限制。提示随清单缓存复用，当前版本与环境提示在读取时计算；正文与图件的绑定见 [IFACE-DATA §3.7](数据模型.md)。
- 投影缺失：`ok=false`、`error.code=projection_missing`，附修复提示「去掉 `--refresh false` 重跑，或先 `download --work <work_key>`」（[ADR-0067](../决策/ADR-0067.md)）。

## 6. 错误码

**信封上的退出码只有 0 与 1**，含义是「这次运行有没有产出可用的东西」；细分靠 `error.code`（[ADR-0056](../决策/ADR-0056.md)）。**参数解析失败是例外**：argparse 在进 `main` 之前就退出，退出码 **2**、usage 写 stderr、**没有信封**（实测 2026-10-16）——「有没有信封」不能只看退出码非零。下表只列 `error.code`——`source_error` / `network_error` / `rate_limited` 在**仍产出结果**时不走本表，只记进 `counts.failures[]` / `degraded`。

| code | 含义 | 退出码 | 重试同一命令 | 若否，先做什么 |
|---|---|---|---|---|
| `busy` | 写锁被占用（另一个 run 在跑） | 1 | ✅ 稍后一次 | — |
| `projection_missing` | 本地没有这份产物且不允许联网（`download` / `read` 的 `--refresh false`） | 1 | ❌ 重试无用 | 去掉 `--refresh false`，或先跑 `download --work <work_key>` |
| `no_profile` | 没有画像 | 1 | ❌ | 引导生成画像 |
| `profile_invalid` | 画像解析失败（附出错行） | 1 | ❌ | 修文件后重跑 `profile check` |
| `invalid_args` | 参数不合法 | 1 | ❌ | 改参数 |
| `not_found` | 标识或 `work_key` 未命中 | 1 | ❌ | 换标识，或先 `search` 联网取 |
| `source_error` | 全部源都失败、零写入 | 1 | 原因允许时一次 | 授权、依赖或策略问题先修原因，见[初始化排障](../../skills/academic-search/references/setup.md#5-按失败阶段恢复) |
| `network_error` | 网络不可达 | 1 | 暂时故障一次 | 网络策略拒绝或配置错误先修原因，见[初始化排障](../../skills/academic-search/references/setup.md#5-按失败阶段恢复) |
| `rate_limited` | 429 或余额耗尽且无法降级 | 1 | 依返回原因 | 速率限制稍后一次；额度耗尽停止，等待或使用已有结果 |
| `io_error` | 本地读写失败（含只读属性、跨卷硬链接） | 1 | ❌ | 排查路径与权限 |
| `data_not_writable` | 数据目录不可写（只读挂载 / 权限不足），sidecar 连打开都不行 | 1 | ❌ | 按[初始化排障](../../skills/academic-search/references/setup.md#5-按失败阶段恢复)处理原库权限与根目录（[ADR-0069](../决策/ADR-0069.md)） |
| `internal_error` | 未分类缺陷 | 1 | ❌ | 报缺陷 |

## 8. profile 载荷

`profile` 是画像的**只读**通道（CLI 不写配置，[ADR-0040](../决策/ADR-0040.md)）；查询字段见[配置目录](../使用/配置.md) §1。

- `profile show` → `data = {queries:[…]}`；无画像时 `ok=false`、`error.code=no_profile`。
- `profile check` → 成功时 `data = {queries:[…]}`；失败时 `ok=false`、`error.code=profile_invalid`，`error.message` 逐条列出**出错行号与原因**。
- `profile scaffold` → `data = {template}`，`template` 是带注释的 `profile.toml` 模板原文。

## 9. 版本规则

- 本文定义的字段与枚举**只增不删**；改语义等于换 `SCHEMA_VERSION`，并附迁移说明。
- **未在本文定义的字段不得出现在信封里**：实现即兴加的字段会变成事实上的契约，而它没有家。
