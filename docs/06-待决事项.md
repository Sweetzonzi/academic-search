| Q22 | `spec_hash` 该覆盖哪些参数：它只由 `all_of` / `any_of` / `venues` / `authors` / `since_years` 决定（`config.py` 的 `canonical_spec`），**不含 `--limit`、不含窗口宽度、不含 `--source`**；若以后让排序或引用数影响联网取数，那两者也不在其中 | 决定「同一检索式在新鲜度窗口内不重复计费」这条是否真的成立。已知的三处后果：① 一次 `--limit 5 --refresh true` 会把该检索式置为新鲜 24 小时，随后同字段的 `--limit 20`（或将来的 `sync --query`）跳过联网，只读到那次 5 条的快照；② `--since-years 3` 与「回看 30 天」算出同一个 `spec_hash`；③ `--source arxiv` 跑过一次后，默认两源在 24 小时内被判新鲜、只查本地（实测见 [EX-2026-10-16-source-contract](实验/EX-2026-10-16-检索口径与来源校验.md) §4）。要点是先定一条规则：**哪些参数改变远端取数结果，哪些只改变展示**；前者进 `spec_hash`，后者不进（`--abstract` 已按后者处理） |
| Q24 | 检索门走哪一条：继续用 `filter=field.search:`（官方标注废弃）并对多词值加引号，还是换到 `search.field=` 参数 | 两者在短语命中、布尔组合、计费上实测等价（[EX-2026-10-16-source-contract](实验/EX-2026-10-16-检索口径与来源校验.md) §3），所以这是路径选择而非取舍：新门要求把 `all_of` / `any_of` 合成**一个**布尔串，并要求继续显式下发排序参数（`search.` 默认按 relevance 排），代价是要重写 URL 组装；旧门只需给多词值加引号。本项同时决定计费表述怎么改：**单价差 10 倍的轴是「有没有做全文检索」，不是「用 filter 还是用 `search=`」**（[EX-2026-10-16-source-contract](实验/EX-2026-10-16-检索口径与来源校验.md) §1） |
| Q25 | 单边字段（`venues`，以及可能的 `cited_by_count`）在本地过滤时，值为空的记录算**通过**还是不通过；该不该推给远端 | 决定 `config/profile.toml` 里带 venue 白名单的查询能否返回 arXiv 侧结果。现状是三方不一致：规范层写「推远端」（[IFACE-SOURCE](接口/数据源适配.md) §9）、交付层写「对 arXiv 不生效」（`skills/academic-search/references/cli-reference.md` §1）、实现是**排除**，且远端那一腿实测 HTTP 400（[EX-2026-10-16-source-contract](实验/EX-2026-10-16-检索口径与来源校验.md) §5）。定完口径要同时决定 `--venue` 的远端过滤器名，或改为只做本地过滤 |
| Q26 | 是否引入 `--min-citations`，以及它的形态 | 决定「找某个方向的经典」这条路——目前只能靠 `lookup` 按已知 ID 逐条补。它不需要新概念，可作为 `--venue` 的同构物（远端 filter + 本地过滤），体量实测见 [EX-2026-10-16-source-contract](实验/EX-2026-10-16-检索口径与来源校验.md) §6（`"world model"` 14 582 → 294）；叠加 `cited_by_count:>N` 不额外计费，且 arXiv 侧无此字段。本项与 `Q25` 共用同一条空值口径 |
| Q27 | L1 补桥的一致性校验落在哪一层，以及校验不通过时 `record_ident` 还写不写 | 判据与后果规范层已定（标题 + 年份 + 首作者；冲突标 `metadata_conflict` 且不归组），缺的是落点与顺序。顺序问题有实测依据：`upsert_ident()` 是 `INSERT OR IGNORE`、(ns, value) 为主键，**先写者永久占位**——若先写别名再判冲突，错误别名会留下（[EX-2026-10-16-source-contract](实验/EX-2026-10-16-检索口径与来源校验.md) §7）。要定的是：校验放在 `group.ingest()` 的 L1 分支，还是放在 `service.run_lookup()` 的入库之前 |
